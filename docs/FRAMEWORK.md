## 1. 一句话与三层结构

**一句话：把「事情做完了」变成「看得见的路」。**

产品分三层，缺一层就不成立：

| 层 | 回答 | 承载 |
|---|---|---|
| 做事层 | 我现在做什么 | 今天、项目、待办 |
| 记录层 | 我做完了什么 | 完成动作、不可改的记录 |
| 看见层 | 我这一年走成了什么样 | 人生树、里程碑、徽章、回顾 |

大多数待办软件只有做事层，做完就消失；日记软件只有记录层，写起来太累。**这个产品的差别在记录层到看见层的这一段**——完成一次只需一次点击，但它会永久留在图上。

## 2. 核心对象

整个产品只有 7 个对象。任何新功能先问：它改变的是哪一个？落不到对象上就不做。

| 对象 | 是什么 | 关键字段 | 生命周期 |
|---|---|---|---|
| **领域** Area | 人生的一块地：健康 / 事业 / 关系 / 成长 / 兴趣 / 财务 | 名称、颜色、图标 | 常驻，建议 ≤7 个 |
| **项目** Project | 有目标、会结束的一件事（"上线 1.0"、"跑完半马"） | 名称、所属领域、状态、起止 | 会结束 |
| **并行线** Line | 项目内同时推进的一条路径 | 名称、颜色、状态 | 可合并、可放弃 |
| **待办** Todo | 最小可执行单元 | 标题、截止、优先级、所属线 | 完成 / 放弃 |
| **记录** Record | 完成时自动产生，不可修改 | 一句话、时间、所属、关联待办 | 永存 |
| **里程碑** Milestone | 人为标记的锚点 | 标题、日期、备注、照片 | 永存 |
| **徽章** Badge | 达成条件后授予 | 名称、类别、条件、授予时间、当时数据 | 永存 |

**命名对照**（文档内一律用左列的对象名，界面按当前模式换显示名）：

| 对象（文档 / 代码） | 项目模式显示 | 人生模式显示 |
|---|---|---|
| 领域 Area | 领域 | 人生领域 |
| 项目 Project | 项目 | 主线 |
| 并行线 Line | 并行线 | 支线 |
| 待办 Todo | 待办 | 小事 |
| 记录 Record | 完成记录 | 足迹 |
| 里程碑 Milestone | 里程碑 | 里程碑 |
| 徽章 Badge | 徽章 | 徽章 |

两列显示名是同一批数据的两套说法，不是两套对象。界面铁律与两种模式的分工见 `docs/PRODUCT-STRATEGY.md` §5.1；**对象名以本表左列为准，其他文档一律引用不复述**。

三条不变量：

1. 一条待办必须归属于某个项目；项目必须归属于某个领域。
2. 完成待办**必然**产生一条记录，不可跳过、不可静默。
3. 记录写下即不可修改；纠错只能追加一条「更正记录」。

> 第 3 条是产品的信任基础。所有"回看"功能的价值都建立在它上面。

## 5. 徽章体系

徽章最容易做成廉价游戏化：签到送星星、集齐换皮肤、排行榜比谁多。那套东西会让人为了拿徽章去刷垃圾任务，最后数据全是假的。

所以先立五条原则。

### 5.1 五条原则

1. **奖励结构，不奖励数量。** 「完成 100 个待办」只会催生 100 个「喝水」；「把一条并行线并回主线」才代表你学会了安排生活。
2. **没有断签。** 不做连续打卡清零。连续类徽章只记录历史最高，断了不掉、不催、不红点。
3. **每枚都要能说清为什么给你。** 徽章详情里写当时的真实数据：「2026 年 3 月，你的 3 条并行线全部合回了主线」。
4. **徽章长在树上。** 独立的徽章墙只是索引，主场是它出现在你人生树的某一天。
5. **不设稀有度、不排名、不比朋友。** 一旦能比，它就从「我走过的证据」变成「社交货币」，然后开始造假。

### 5.2 四类 24 枚

**第一类：结构类（8 枚）——你学会了怎么安排**

| 徽章 | 获得条件 |
|---|---|
| 第一道岔 | 第一次创建并行线 |
| 汇流 | 第一次把并行线合回主线 |
| 收束 | 一个项目里所有线都已合并或结束 |
| 双线并行 | 同时推进两条线持续 ≥14 天 |
| 断舍离 | 第一次主动「放下」一个项目并写了原因 |
| 有始有终 | 一个项目从创建到结项，记录 ≥10 条 |
| 五域 | 五个不同领域都至少有 1 条记录 |
| 主干 | 某个领域连续 3 个月有记录 |

**第二类：时间类（5 枚）——你和时间的关系**

| 徽章 | 获得条件 |
|---|---|
| 起笔 | 第一条记录 |
| 补白 | 第一次回填过去的事件 |
| 常青 | 单条线持续有记录 ≥6 个月 |
| 回望 | 第一次打开年轮 |
| 第一年 | 使用满 365 天 |

**第三类：里程碑类（4 枚）——你主动标记的人生**

| 徽章 | 获得条件 |
|---|---|
| 立碑 | 第一个里程碑 |
| 三碑 | 累计 3 个里程碑 |
| 碑上有字 | 里程碑带照片（V1 后） |
| 年轮有痕 | 同一年内 ≥3 个里程碑 |

**第四类：彩蛋类（7 枚）——不预告，撞见才有**

| 徽章 | 获得条件 |
|---|---|
| 夜航 | 在 0:00–5:00 完成一条记录 |
| 跨年 | 12 月 31 日或 1 月 1 日有记录 |
| 生日 | 生日当天有记录 |
| 空白年 | 某一年只有 1 条记录 |
| 复活 | 停滞 ≥90 天的线重新有记录 |
| 满月 | 某个月每天至少有 1 条记录 |
| 早鸟 | 连续 7 天在 8 点前完成第一条 |

### 5.3 获取与展示规则

- **判定时机**：完成记录 / 创建里程碑 / 建线 / 合并线时即时判定。
- **通知方式**：不弹窗、不打断。当天「今天」页底部出现一条轻提示，点开看详情。
- **墙上展示**：四类分栏。结构类与时间类显示「还差什么」（如「再有 1 次汇合」）；彩蛋类**未获得时完全不显示**，不给人刷的目标。
- **树上展示**：在获得那天的节点旁钉一个 4px 小标记，悬停显示徽章名。
- **不可撤销**：徽章一旦获得不回收，即使后续数据被删除（它记录的是「当时发生过」）。

### 5.4 明确不做

| 不做 | 原因 |
|---|---|
| 排行榜 / 好友对比 | 一旦可比就会造假，且与「不做人生导师」原则冲突 |
| 稀有度标签（"仅 0.3% 获得"） | 制造稀缺焦虑，且我们没有可信的全局数据 |
| 断签惩罚 / 补签卡 | 惩罚机制会把工具变成负担 |
| 积分兑换 / 徽章换皮肤 | 把荣誉变成货币，立刻贬值 |
| 强制分享 | 人生数据不该默认外流 |

## 6. 哪些功能真正值得做

评审时最该讨论的不是"还缺什么"，而是"哪些其实没用"。以下是我的判断。

### 6.1 护城河（5 项，不可砍）

| 功能 | 为什么是护城河 |
|---|---|
| **记录不可改** | 所有日记和待办软件都能编辑。敢说"这条不能改"，回看才有分量。这是整个产品的地基。 |
| **停滞虚线** | 别的软件只显示你做了什么，不显示你**没做**什么。这条虚线是唯一会主动指出"你三个月没碰健身了"的地方。 |
| **双视角一份数据** | 项目模式管交付、人生模式管历程，同一批数据不重复录入。竞品要么是纯待办，要么是纯日记。 |
| **徽章长在树上** | 成就是和时间绑定的路标，不是收集品。这个组合几乎没人做。 |
| **一句话注解** | 让人顺便懂点计算机，但从不挡路。成本极低，感知极强。 |

### 6.2 必须有但不差异化（照做即可，别在这上面花心思）

快速添加、提醒、搜索、导出、明暗主题、拖拽排序、领域配色。这些做不好用户会走，做好了也没人夸。

### 6.3 建议不做

| 不做 | 原因 |
|---|---|
| 社交 / 好友 / 排行 | 与"不做人生导师"冲突，且会诱导造假 |
| 强制打卡 / 连续签到 | 把工具变成 KPI |
| 自定义字段 / 多维表格 | 复杂度爆炸，收益只对 1% 用户成立 |
| 番茄钟 / 时间统计 | 是另一个产品的事 |
| 多人协作 | 人生是自己的 |
| AI 替你写日记 | AI 可以帮你归类、起标题，**不能替你感受**。这条要写进原则 |

## 7. 版本切分

| 阶段 | 一句话目标 | 包含 | 不含 |
|---|---|---|---|
| **MVP** | 验证「待办 → 记录 → 树上有节点」这个闭环有人要 | 29 项：引导、今天、项目（单线）、完成记录、人生树、停滞虚线、周回顾、备份导出、双视角、3 枚徽章、注解、纯本地 | 并行线、年轮、完整徽章、照片、模板、同步 |
| **V1** | 让「人生」这件事成立 | 28 项：并行线与合并、年轮、里程碑照片、24 枚徽章、模板、重复任务、补记、导入、分享图 | 账号、同步、多端 |
| **V2** | 让长期使用与换设备成为可能 | 8 项：账号、端到端加密同步、第二端、AI 录入与语音、彩蛋徽章、原理面板 | 协作、社交 |

**如果只能做 15 项**（其余 14 项都是让它好用的配套）：

A-01 引导 · B-01 快速添加 · C-01 今日 · C-02 逾期 · C-03 一键完成 · D-01 项目列表 · D-02 项目详情 · E-01 完成即记录 · E-02 记录不可改 · E-03 记录详情 · F-01 人生树 · F-02 停滞虚线 · J-02 自动备份 · K-01 双视角 · L-01 无账号可用

这 15 项构成「建了事 → 做完了 → 树上有节点 → 能回看」的最小闭环。**MVP 真正的风险不是功能不够，是闭环没跑通就先做周边。**

**MVP 的验收只有一句话**：5 个真实用户用它记录两周，第 15 天有人主动打开人生树往回看。

## 8. 待你拍板的 9 个决策

这些不定，逐功能设计时会反复卡住。建议这次 review 一次性定掉。

| # | 决策 | 选项 | 我的建议 |
|---|---|---|---|
| 1 | 并行线进 MVP 吗 | MVP 单线 / MVP 就带并行线 | MVP 单线。树先有主干，V1 再长枝 |
| 2 | 「重复任务」要不要 | 要 / 不要 | 要，但做成"模板待办"，不预生成实例，避免和记录冲突 |
| 3 | 项目能跨领域吗 | 单领域 / 可跨 | 单领域。跨领域会让树上颜色打架 |
| 4 | 记录"不可改"的强度 | 完全不可改 / 24 小时内可改 / 当天可删 | 当天可删（留痕），跨天完全不可改 |
| 5 | 徽章一次做全还是先 3 枚 | 一次 24 枚 / 先 3 枚 | 先 3 枚。MVP 只需要"第一笔"的即时反馈 |
| 6 | 回顾是独立入口吗 | 独立 tab / 嵌在历程 / 嵌在今天 | 嵌入今天（卡片）+ 历程（年轮），不开第五个 tab |
| 7 | 账号的必要性 | MVP 纯本地 / 一上来就要账号 | 纯本地。数据信任优先于同步 |
| 8 | AI 放哪一层 | 只做录入 / 也做周报总结 | 录入 + 归类可以做；**总结必须用户自己写** |
| 9 | 要不要子任务 | 要 / 不要 | 不要。子任务一出现，项目就会变成一张网 |

## 9. 下一轮怎么走

框架定稿后，建议按**依赖顺序**逐个功能点设计，而不是按页面：

1. 对象与数据模型（决定后面一切）
2. 今天 + 快速添加
3. 项目与并行线
4. 完成与记录（不可改规则是难点）
5. 人生树渲染
6. 回顾
7. 徽章
8. 数据与备份
9. 设置与模式

每个功能点出稿时给：用户故事 → 交互与状态 → 边界与异常 → 验收标准。你逐条 re，我改，再进下一个。
