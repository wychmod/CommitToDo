## 1. 一句话与三层结构

**一句话：把「事情做完了」变成「看得见的路」。**

| 层 | 回答 | 承载 |
|---|---|---|
| 做事层 | 我现在做什么 | 今天、分支、待办 |
| 提交层 | 我做完了什么 | 完成待办即产生一条提交；当天可改，跨天锁定 |
| 看见层 | 我这一年走成了什么样 | 分支树、里程碑、徽章、年轮 |

大多数待办软件只有做事层，做完就消失；日记软件只有提交层，写起来太累。**差别在提交层到看见层的这一段**——一次点击完成待办，就能在历程里回看这次进展。

## 2. 对象与层级

### 2.1 全树长什么样

```
我                                  ← 根分支，全树唯一，不可删、不可合并
├── 工作                            ← 一级分支（生活面）
│   ├── 主业                        ← 二级分支（方向）
│   │   └── 小程序 1.0              ← 三级分支（有终点的目标）
│   ├── 副业
│   └── 周末兼职
├── 健康
│   ├── 跑步
│   │   └── 半马训练
│   └── 睡眠
└── 生活
    └── 搬家
```

- **待办可以挂在任意一级到三级分支上**，不必先建"项目"；**也可以不建分支直接记一笔，默认落在根分支上**。
- **完成待办 = 在那条线上打一个提交点**。横向长度表示时间跨度，提交节点表示有过活动。
- **分支只能合并到自己的父分支**，合并后子分支保留为「已合并」。

### 2.2 只有 5 个对象

| 对象 | 是什么 | 关键字段 | 生命周期 |
|---|---|---|---|
| **分支** | 唯一的结构容器，可嵌套、可合并 | 名称、父分支、层级、颜色、状态、归档标记、目标、起止 | 进行中 → 已合并 / 已放下；已放下可重新开始 |
| **待办** | 最小可执行单元 | 标题、所属分支、截止日期、计划日期、优先级、状态 | 待完成 → 已完成 / 已取消；撤销完成可回到待完成 |
| **提交** | 待办完成时自动产生，V1 支持补记 | 一句话、写入时间、代表日期、原始所属分支、关联待办（若有） | 写入当天可纠错并留痕，跨天锁定 |
| **里程碑** | 人为标记的锚点 | 标题、日期、所属分支、备注 | 永存 |
| **徽章** | 达成条件后授予 | 类型、授予时间、当时数据 | 永存 |

被取消的四个概念：

| 旧概念 | 现在 |
|---|---|
| 领域 | 一级分支（工作 / 健康 / 生活） |
| 项目 | 二级或三级分支 |
| 并行线 | 就是分支 |
| 仓库 | 不存在。全应用只有一棵树 |

### 2.3 层级与上限

数字是为了让树能一次查完、不让用户迷路，不是拍脑袋的审美。

| 层 | 叫法 | 例子 | 每个父节点可见子分支上限 | 全树默认可见上限 |
|---|---|---|---|---|
| 根 | 根分支 | 我 | 固定 1 个 | 单独计 |
| L1 | 一级分支 | 工作 / 健康 / 生活 / 关系 / 成长 / 兴趣 / 财务 | 根下 ≤7 | ≤7 |
| L2 | 二级分支 | 主业 / 副业 / 跑步 / 睡眠 | 每个 L1 ≤9 | ≤63 |
| L3 | 三级分支 | 小程序 1.0 / 半马训练 / 搬家 | 每个 L2 ≤20 | L1–L3 合计 ≤200 |

规则：

1. **不能建第 4 层**。根分支以下最多 L1–L3。
2. 同一父分支下名称唯一，包含已归档的同级分支。
3. **按默认树可见性计算额度**。显示在默认树的已合并、已放下分支照常计入；自己或祖先已归档的分支不计入。200 个额度只计 L1–L3，根分支固定显示。
4. 新建、移动、取消归档都校验层级上限和全树额度。达到上限时，先删除无历史的空分支，或通过当前版本支持的归档操作释放额度。
5. 待办可挂在根分支或 L1–L3 任意层，一条待办只属于一条分支。

### 2.4 七条不变量

1. 全树只有一个根；根不能删除、不能合并、不能放下。
2. 分支最多 3 层；不能建第 4 层。
3. 一条待办必须归属于某条分支；不选分支时自动挂在根分支上。一次有效完成对应一条有效提交；同日撤销完成时，两者一起更新。
4. 提交以写入时的自然日为纠错窗口；当天可修改文案或撤销完成，每次纠错留痕，跨天锁定。详见 E-02、E-04。
5. 分支只能合并到自己的父分支，不能跨父合并，也不能合并到子分支。
6. 只有整棵子树从未留下业务历史时，才可直接删除。合并保留原分支和原始提交归属，默认树是否显示由归档决定。
7. 只有根分支和默认树中进行中的分支能接收、完成待办。已合并分支及归档子树只读，提交的当天纠错按 E-02 执行。已放下分支取消归档后仍为已放下，重新开始才恢复进行中。

### 2.5 「完成」与「收尾」是两个动作

**这两个词不混用，也不互相替代。**

| 动作 | 作用对象 | 什么意思 | 结果 |
|---|---|---|---|
| **完成** | 一条**待办** | 这件事做完了 | 产生一条提交 |
| **收尾** | 一条**分支** | 这条线不再需要继续推进了 | 提交并入父分支；分支归档或留在默认树 |

界面上不会出现「完成分支」「收尾待办」这类说法。用户问「做完了」时，产品要能分清他指的是哪一件：待办完成是日常高频动作，分支收尾是一次性的结构决定。

**收尾的三种结果**

| 方式 | 含义 | 必填 | 结果 |
|---|---|---|---|
| **收尾：合并，并归档** | 做完了，这段属于父分支的一部分 | 可选一句说明 | 提交并入父分支历史；父分支出现汇合点；子分支自动归档、离开默认树 |
| **收尾：合并，留在树上** | 做完了，但这段想一直挂在树上看得见 | 一句小结 | 提交并入父分支历史；父分支出现汇合点；子分支标记完成、留在默认树，**仍计入活跃额度** |
| **放下** | 主动不做了 | 一句原因 | 默认树保留分支，历程用灰线标出放下日期；未完成待办停留在原分支；可「重新开始」，原因保留在历史里 |

**两种收尾方式都保留原分支的历史。** 合并后的提交标注来源，用户在历程中仍可回看这条线。收尾时主要决定这条分支要不要继续显示在默认树。

**收尾的入口位置**

| 入口 | 位置 | 说明 |
|---|---|---|
| 主入口 | 分支详情页右上角「更多」菜单的第一项 | 唯一完整入口。用户在这里能看到这条线的全部信息，做决定时不会信息不足 |
| 快捷入口 | 分支树上分支行的右键 / 长按菜单 | 菜单项与主入口一致，不提供跳过确认的直通 |
| 不做 | 分支树每行常驻按钮 | 收尾不可撤销，不该做成随手可点的按钮 |

**确认框措辞（两段式）**

第一步选去向：

```
收尾「主业」

这一段做完了。它的 47 条提交会并入「工作」的历史，
并在「工作」上留一个汇合点。

这段还要一直挂在树上吗？
  ● 不用了，从树上收起        ← 默认选中
    1.0 做完了，以后还有 2.0
  ○ 留着，作为一段完成的路
    考研这种，想让它在成长下面一直看得见

还有 3 条没做完的待办：
  [ 移到「工作」 ]  [ 取消掉 ]

                                  [ 取消 ]  [ 确认收尾 ]
```

第二步确认（仅在还有未完成待办或选了「收起」时出现）：

```
确认收尾「主业」？

47 条提交并入「工作」，3 条待办移到「工作」。
收尾之后不能撤销。

                    [ 再想想 ]  [ 确认收尾 ]
```

三条硬规则：

1. **按钮文字用「确认收尾」，不用「确定」**。动词要具体，避免用户不知道自己确认了什么。
2. **不可撤销必须在第二步用一句话写出来**，不能只靠灰色小字。
3. **两个选项都用用户的处境举例，不用功能名**。写「1.0 做完了，以后还有 2.0」而不是「归档」，写「考研这种」而不是「保留」，因为用户不认识「归档」这个词的后果。

**暂时不做可以保持进行中。** 历程按 F-02 显示符合条件的停滞分支。

**收尾同时处理历史、未完成待办和默认树的可见性。**

- 收尾时保存源分支、当时的父分支与收尾时间。原提交保留原始归属和日期。
- 源分支自己的未完成待办可移到父分支或取消。确认框列出条数和去向。父分支无法接收时，可先给待办改归属，也可确认取消剩余的待办后收尾。已放下后代的待办留在原分支。
- **进行中的分支可以收尾，前提是没有进行中的后代。** 已合并或已放下的后代留在默认树上时，父分支仍可收尾。
- **收尾不可撤销。**

**父分支的历程口径：合并前只看自己的提交，合并后才把子分支的提交并入。**

- 合并前：父分支的历程只显示挂在它自己身上的提交，子分支的提交不出现在父分支历程里（树上看得到子分支这条线，但那是子树视图，不是父分支的历程）。
- 合并后：父分支历程按原时间显示子分支的提交，含已经逐级并入子分支的历史。提交标注原始来源，周回顾、年轮和全树总数按原提交去重。
- 移动分支改变当前位置，已经发生的合并沿用收尾当时的父分支。

**放下会暂停该分支的待办。** 未完成待办移出「今天」，在分支详情和「全部待办」的「已放下」分组可查看。未归档时可以把待办移到可接收的分支。后代保留各自的状态，进行中的后代照常工作。重新开始后按原截止日期重新分组；祖先已合并时，先移到没有已合并祖先、且可接收待办的父分支，再重新开始。

**归档控制分支的可见性。** MVP 可在收尾时选择归档，V1 增加独立的手动归档和取消归档。只有已合并或已放下、且没有进行中后代的分支可以归档。

- 整棵子树退出默认树和快速添加候选，释放可见分支额度，并退出停滞计算。历程继续保留分叉、汇合点和提交，归档历史可展开查看。
- V1 取消归档时，须先恢复归档的祖先并通过可见额度校验。随父隐藏的后代随之显示，单独归档过的后代继续归档。各分支保留原生命周期状态。
- 归档子树的有效数据仍计入历史统计。同日纠错后同步重新计算。

**删除用于撤销空分支的创建。** 根分支不能删除。待删子树内的每条分支都须仍在进行中，且从未有待办、提交、里程碑、纠错痕迹或收尾、放下等历史。满足条件时可直接删除整棵子树。分支创建事件本身可随空分支一起删除，已授予的徽章保留快照。

### 2.6 查询与规模约束（产品级）

这一节写给后面的数据模型和界面，避免树长大以后查不动：

1. **默认树一次查完**。进应用时取根分支和最多 200 条默认可见分支。
2. **默认树与归档分开查**。历程按日期查询归档历史，V1「归档」区按一级分支浏览。
3. **分支保留待办数、有效提交数、最近有效提交日期。** 停滞按 F-02 在当前进行中的分支范围内取最近日期，纠错时刷新受影响的计数和日期。
4. **提交按分支和日期分页**。分支详情按时间倒序加载，历程按当前可见日期范围加载。
5. **路径唯一且可读**：分支路径形如 `工作/副业`，同级重名直接拒绝。
6. **移动分支校验父分支资格、深度、重名与额度。** 只能单独移动可见的进行中、已放下分支，目标须为可接收待办的父分支。移动后整棵子树深度不得超过 3，且不能移动到自身或子孙下。
7. **合并保留原提交。** 父分支历程按收尾事件查询并入的历史；收尾时选择归档或留在默认树。

### 4.3 今天（4）

| 编号 | 功能 | 说明 | 阶段 |
|---|---|---|---|
| C-01 | 今日清单 | 按下方规则显示「逾期 / 今天 / 无截止日期」，每条只出现一次。固定提供「全部待办」入口。收起清单时只露第一条，完成后自动露出下一条。收起是列表内操作，不含全屏和计时 | MVP |
| C-02 | 一键完成 | 点击立即完成，无须弹框。完成后可选补一句话，可在提交详情按 E-02 撤销完成 | MVP |
| C-03 | 本周摘要 | 在 G-01 的同一张卡片上增加「本周摘要」，每天显示当前周（周一至周日）截至当日的提交数、停滞分支提示。周回顾仍按 G-01 的日期窗口显示 | V1 |
| C-04 | 拖拽排序 | 手动调整今日顺序（与 D-08 分支排序是两套，不共用） | V1 |

**今日分组规则**

1. 纳入根分支与默认树中进行中分支的未完成待办。有计划日期且为今天的待办优先放入「今天」，保持原截止日期。
2. 其余待办按截止日期分组。今天到期放「今天」，逾期 1–30 天放「逾期」，无截止放「无截止日期」。显示顺序为逾期、今天、无截止日期。逾期用中性色，超过 5 条时默认折叠，可展开。无截止组默认折叠并显示条数。
3. 只对根分支与默认树中进行中分支的未完成待办提供「安排到今天」。入口：待办行右键 / 长按菜单，菜单项为「安排到今天」；已在今天的显示为「移出今天」。该操作只设置当日计划日期，不改原截止日期；跨自然日后按原截止日期重新分组。
4. 「全部待办」覆盖未来到期、长期逾期和根分支上的任务。已放下分支上的未完成待办单独分组，归档的待办可只读查看。

| D-04 | 收尾：合并到父 | 无进行中后代时方可收尾；源分支的未完成待办移交或取消，父分支出现汇合点。收尾可选**归档**或**留在默认树**，两种都能从历程查看历史。收尾不可撤销。入口与确认框文案见 §2.5 | MVP |

### 4.5 提交（4）

| 编号 | 功能 | 说明 | 阶段 |
|---|---|---|---|
| E-01 | 完成即提交 | 完成待办自动生成提交，不需额外操作；内容 = 待办标题 + 可选补一句 | MVP |
| E-02 | 提交当天纠错 | 写入当天可修改文案或撤销完成，跨天锁定。纠错以原始分支的历史留痕，历程展示有效提交。状态、统计和留痕更新见下方规则 | MVP |
| E-03 | 提交详情 | 时间、原始分支、一句话、前后有效节点（按时间排序的同一原始分支上下条），不设备注字段 | MVP |
| E-04 | 补记 | 可指定最近 7 个自然日内的代表日期（含今天），标注「补记」。纠错窗口按写入日计算，历程、停滞及回顾按代表日期计算 | V1 |

**当天纠错规则**

- 锁定时间为写入时本地时区的下一自然日零点。之后切换时区不改变该提交的锁定时间。
- 修改提交文案保留原始时间、分支和待办状态。撤销完成须一并恢复待办、作废这次提交、保留纠错痕迹并重算有效提交数、最近活动、待办进度和回顾。作废的提交不进入历程和统计，已授予徽章保留快照。
- 已收尾或归档分支上的提交当天仍可纠错。原分支无法接收待办时，撤销前显示最近可接收的上级分支，根分支兜底。恢复的待办保留原截止日期。无关联待办的补记撤销时只作废该提交。

### 4.6 历程、分支树与搜索（6）

| 编号 | 功能 | 说明 | 阶段 |
|---|---|---|---|
| F-01 | 时间树 | 每条一级分支一条横向泳道，一级分支的创建标记在自己的泳道可定位。子分支在创建时间从父线上岔出，在收尾时间汇合，点击节点可查看相关历史。根分支有提交、里程碑或汇合点时显示「我」泳道。横轴按实际时间比例，邻近节点聚合。默认展开未归档 L1，折叠子分支和已归档 L1。时间范围由 F-03 的同一个控件控制，默认近 90 天，超出部分滚动加载 | MVP |
| F-02 | 停滞虚线 | 只判断进行中且在默认树可见的分支，取它与同样在进行中的可见后代的最近有效提交日期。距今天超过 30 天时，在已展开泳道画出从该日期到今天的虚线，并标天数。该范围内从未有过有效提交时画淡实线。已放下分支以灰线和放下日期表达 | MVP |
| F-03 | 筛选与直达 | 历程页顶部**一个**时间范围控件，三档：近 90 天（默认）/ 今年 / 全部；另可按根分支、一级分支筛选。按分支筛选时隐藏其他泳道，正常进入沿用上次的筛选与范围。切到「今年」时若距 1 月 1 日不足 90 天，按今年实际起点显示，不与「近 90 天」重复设一档。首条提交、徽章或搜索直达时临时带入目标所在泳道及日期，展开对应节点并保留原筛选设置 | MVP |

## 5. 徽章体系

### 5.1 五条原则

1. **奖励结构，不奖励数量。** 「完成 100 个待办」只会催生 100 个「喝水」；「把一条子分支并回父分支」才代表你学会了安排生活。
2. **没有断签。** 不做连续打卡清零。连续类徽章只记录历史最高，断了不掉、不催、不红点。
3. **每枚都要能说清为什么给你。** 徽章详情里写当时的真实数据。
4. **徽章长在树上。** 徽章墙只是索引，主场是它出现在某条线的某一天。
5. **不设稀有度、不排名、不比朋友。**

### 5.2 四类 21 枚

MVP 上线 4 枚。V1 累计上线结构、时间、里程碑三类 16 枚。V2 新增 5 枚彩蛋，累计 21 枚。

**第一类：结构类（8 枚）——你学会了怎么安排**

| 徽章 | 获得条件 |
|---|---|
| 第一道岔 | 第一次创建子分支 |
| 汇流 | 第一次把子分支合并到父分支 |
| 收束 | 某个分支下所有子分支都已合并 |
| 双线并行 | 同一个父分支下两条子分支同时活跃 ≥14 天 |
| 断舍离 | 第一次「放下」分支并写了原因 |
| 有始有终 | 一个三级分支从创建到收尾，提交 ≥10 条 |
| 五面 | 五个一级分支都至少有 1 条提交 |
| 主干 | 某个一级分支连续 3 个月有提交 |

**第二类：时间类（4 枚）——你和时间的关系**

| 徽章 | 获得条件 |
|---|---|
| 起笔 | 第一条提交 |
| 补白 | 第一次回填过去的事件 |
| 常青 | 单条分支持续有提交 ≥6 个月 |
| 第一年 | 使用满 365 天 |

**第三类：里程碑类（4 枚）——你主动标记的人生**

| 徽章 | 获得条件 |
|---|---|
| 立碑 | 第一个里程碑 |
| 三碑 | 累计 3 个里程碑 |
| 碑上有字 | 里程碑写了备注 |
| 年轮有痕 | 同一年内 ≥3 个里程碑 |

**第四类：彩蛋类（5 枚）——不预告，撞见才有**

| 徽章 | 获得条件 |
|---|---|
| 夜航 | 连续 3 天在 23:00–5:00 完成待办 |
| 跨年 | 12 月 31 日或 1 月 1 日有提交 |
| 空白年 | 某一年只有 1 条提交 |
| 复活 | 停滞 ≥90 天的线重新有提交 |
| 满月 | 某个月每天至少有 1 条提交 |

> 「生日」徽章需要生日字段，等账号体系落地后再补。

### 5.3 获取与展示规则

- **首批判定**：生成有效提交、创建里程碑、创建子分支、合并分支时分别检查对应徽章，仅处理真实数据。
- **通知方式**：不弹窗、不打断。当天「今天」页底部出现一条轻提示。
- **MVP 展示**：「我的」用列表展示已获得的首批徽章。起笔、第一道岔、立碑、汇流分别直达首次提交、分支创建的分叉、里程碑、收尾汇合点。原事件因撤销完成或删除空分支而移除时，列表保留徽章及授予快照，并标明原事件已撤销。
- **徽章墙（V1）**：已获得的徽章按时间倒序，可按已上线的类别浏览。结构类与时间类只给接近达成的显示「还差什么」。V2 彩蛋获得后显示。
- **树上展示（V1）**：在获得那天的节点旁加一个小徽章标记，悬停或点击才展开名称，同一天不重复显示。
- **不可撤销**：徽章一旦获得不回收。

### 5.4 明确不做

| 不做 | 原因 |
|---|---|
| 排行榜 / 好友对比 | 一旦可比就会造假 |
| 稀有度标签 | 制造稀缺焦虑 |
| 断签惩罚 / 补签卡 | 会把工具变成负担 |
| 积分兑换 / 徽章换皮肤 | 把荣誉变成货币 |
| 强制分享 | 人生数据不该默认外流 |

## 6. 哪些功能真正值得做

### 6.1 护城河（4 项，不可砍）

| 功能 | 为什么是护城河 |
|---|---|
| **提交跨天锁定** | 当天可修正文案或撤销误操作，且保留痕迹。过了写入日，回看时仍能看到当时留下的提交。 |
| **停滞虚线** | 回看时能看到进行中的分支有多久没有提交，已放下的分支有自己的结束标记。 |
| **一棵树只有一种结构** | 从生活面到具体目标只有分支一种容器，不需要在项目和标签之间切换。 |
| **徽章长在树上** | 成就是和时间绑定的路标，不是收集品。 |

一句话注解保留为低成本增强，不再列为护城河。

### 6.2 必须有但不差异化（照做即可）

快速添加、文件导出与恢复、明暗主题、分支配色，以及 V1 的提醒、全局搜索、拖拽排序。

### 6.3 建议不做

| 不做 | 原因 |
|---|---|
| 社交 / 好友 / 排行 | 与「不做人生导师」冲突 |
| 强制打卡 / 连续签到 | 把工具变成 KPI |
| 自定义字段 / 多维表格 | 复杂度爆炸 |
| 番茄钟 / 时间统计 | 另一个产品的事 |
| 多人协作 | 人生是自己的 |
| 子任务 | 会让项目变成一张网 |
| AI 替你写总结 | AI 可以归类、起标题，**不能替你感受** |

| 阶段 | 一句话目标 | 包含 | 不含 |
|---|---|---|---|
| **MVP** | 验证用户能在历程里回看自己完成的事 | 29 项：首条提交直达历程、今天与全部待办、3 层分支树、收尾时归档或留在树上、当天纠错、时间树、停滞虚线、周回顾、文件导出与导入恢复（导入前留存副本）、4 枚可跳转历程的徽章、注解、纯本地 | 放下、独立的手动归档与取消归档、年轮、搜索、同步、补记、每日快照与备份库 |
| **V1** | 支持长期积累和组织个人历程 | 21 项：放下、手动归档与取消归档、年轮、累计 16 枚徽章、全局搜索、补记、批量录入、本周摘要、月回顾、分享图、每日快照与独立备份库、按快照恢复、异地备份 | 账号、同步、多端、模板、彩蛋徽章、匿名统计 |

> B-04 重复待办已定不做（2026-11-21），条目保留仅作记录，不计入任何阶段。

**最小验证范围（17 项）**

A-01 引导 · B-01 快速添加 · C-01 今日 · C-02 一键完成 · D-01 分支树 · D-02 分支详情 · D-03 新建与移动子分支 · D-04 收尾合并 · E-01 完成即提交 · E-02 提交当天纠错 · E-03 提交详情 · F-01 时间树 · F-02 停滞虚线 · F-03 筛选与直达 · J-03 导出 · J-04 从文件恢复 · L-01 无账号可用

**MVP 核心流程验收**

- 空树直接添加并完成待办，从完成反馈打开历程，在根分支看到提交。二级分支的首次提交在折叠或有筛选时也能直达。
- 子分支收尾并留在默认树后，父分支仍可收尾；父分支归档后，原有提交仍能在历程中查看，逐级合并的同一条提交在统计中只算一次。
- 误点完成后当天撤销，待办恢复、历程节点消失，分支历史有痕迹。当天收尾后再撤销时，确认框展示恢复去向。
- 将一条超过 30 天的逾期任务安排到今天，当天只出现一次，次日仍可从「全部待办」找到。
- 全量导出后在干净浏览器恢复，原始归属、提交、里程碑、徽章和历史事件一致。无效文件保留现有数据，成功替换后可下载并导回覆盖前的副本。

**MVP 种子试用**：5 个真实用户用它记录两周，观察第 15 天是否有人主动打开时间树往回看。

## 8. 决策记录

v0.1 的 9 个决策已全部收敛，结论如下：

| # | 决策 | 结论 |
|---|---|---|
| 1 | 并行线进 MVP 吗 | 作废。并行线概念取消，分支是核心，MVP 即支持 3 层 |
| 2 | 重复任务要不要 | 要，做成「模板待办」，不预生成实例 |
| 3 | 项目能跨领域吗 | 作废。单根一树，不存在跨领域 |
| 4 | 提交如何纠错 | 写入当天可修改文案或撤销完成并留痕，跨天锁定。撤销完成同时恢复关联待办 |
| 5 | 徽章分几次上线 | MVP 的 4 枚在「我的」列表可直达历程，V1 累计 16 枚，V2 加入 5 枚彩蛋 |
| 6 | 回顾的入口和日期 | 今天共用一张回顾卡片，周六、周日预览，周一查看同一日期区间的正式版，V1 加本周摘要。年轮在历程 |
| 7 | 账号的必要性 | 纯本地，登录延到 V2 |
| 8 | AI 放哪一层 | 当前版本不做 AI 录入（语音、截图已删）；若将来做，只归类、起标题，总结必须用户自己写 |
| 9 | 要不要子任务 | 不要 |

v0.2 新增并已定：

| # | 决策 | 结论 |
|---|---|---|
| 10 | 根分支几个 | 全树唯一一个，不可删、不可合并 |
| 11 | 最多几层 | 3 层（L1–L3），不能建第 4 层 |
| 12 | 分支能往哪合并 | 只能合并到自己的父分支 |
| 13 | 合并后子分支 | 提交在父分支历史里可见；两种形态：归档（离开默认树）或留在默认树；数据行始终保留 |
| 14 | 结束方式 | 收尾（合并到父，可选归档 / 留在树上）+ 放下（写原因）两种；「结束」并入收尾，不再独立 |
| 15 | 保留几种视角 | 只保留一种，取消项目模式 / 人生模式双词表 |
| 16 | 界面用词 | 「提交」，不用「记录」 |
| 17 | 旧数据怎么处理 | 新版本从空树开始。旧版存在真实用户数据时，切换前先提供旧版导出机会。新版文件恢复支持已声明兼容的格式 |
| 18 | 合并后的分支怎么处置 | MVP 收尾时选择归档或保留在默认树，历程可查看两种结果。留在默认树的分支计入可见额度，V1 再加手动归档和取消归档 |
| 19 | 要不要「暂停」状态 | **不要**。暂时不做就放着，靠停滞虚线表达 |
| 20 | 改版姿态 | **重做 Web 客户端**：保留分层、DI、测试设施，业务层重写 |
| 21 | 已投的登录后端 | **删除**。当前版本不做账号、不做同步；V2 若要做同步，重新设计，不沿用旧实现 |
| 22 | 待办是否必须先建分支 | **不需要**。不选分支的待办默认落在根分支上，直接记一笔就能开始 |
| 23 | 上手四项如何安排 | 功能保留。首次以真实待办完成后直达历程为目标，建分支可跳过，示例树独立预览 |
| 24 | 「做完了」指待办还是分支 | **两个不同的词，不混用。**「完成」只用于待办（产生提交）；「收尾」只用于分支（提交并入父分支 + 归档或留树）。详见 §2.5 |
| 25 | 收尾的入口与措辞 | 主入口在分支详情右上角「更多」菜单第一项；快捷入口在分支树右键 / 长按菜单；不做常驻按钮。两段式确认，不可撤销在第二步明写。完整文案见 §2.5 |
| 26 | 里程碑的日期精度 | **可以只到年月**，用于回填过去；同年月内按创建顺序排，不参与「某日有提交」类徽章判定 |
| 27 | 「安排到今天」的入口 | **右键 / 长按菜单**，同一位置在已安排时显示「移出今天」；不改原截止日期，跨日自动按截止日期重新分组 |
| 28 | 历程的时间范围与筛选 | **同一个控件**，三档：近 90 天（默认）/ 今年 / 全部；按分支筛选是另一个维度，两者独立，筛选与范围都记住上次选择 |

上限口径见 §2.3。根固定 1 个，各父节点默认可见子分支上限依次为 7、9、20，L1–L3 默认可见总数不超过 200。

## 10. v0.3 评审总结（2026-11-17）

v0.3 功能清单为 58 项（MVP 29 / V1 22 / V2 7）。下表保留当时的增删和编号变化。v0.4 的当前清单以 §4 为准。

| 删掉 / 合并的 | 原因 |
|---|---|

| 独立「专注模式」 | 只保留「收起」作为 C-01 的交互细节 |
| 「结束」状态 | 合并进收尾，可见性由归档开关表达 |
| D-08 分支模板 | 与 B-03 重复 |
| 「结项小结」 | 属于收尾流程，不单占编号 |
| 里程碑照片 | 本地照片存储成本高，价值弱 |
| 树上搜索 | 并入全局搜索 |
| 年度章节 | 并入年轮 |

新增 4 个编号：

| 新增 | 为什么 |
|---|---|
