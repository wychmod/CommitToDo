## 1. 一句话与三层结构

**一句话：把「事情做完了」变成「看得见的路」。**

| 层 | 回答 | 承载 |
|---|---|---|
| 做事层 | 我现在做什么 | 今天、分支、待办 |
| 提交层 | 我做完了什么 | 完成待办即产生一条提交；当天可改，跨天锁定 |
| 看见层 | 我这一年走成了什么样 | 分支树、里程碑、徽章、年轮 |

大多数待办软件只有做事层，做完就消失；日记软件只有提交层，写起来太累。**差别在提交层到看见层的这一段**——完成一次只需一次点击，但它会永久留在树上。

## 2. 对象与层级

### 2.1 全树长什么样

```
我                                  ← 根分支，全树唯一，不可删、不可合并
├── 工作                            ← 一级分支（生活面）
│   ├── 主业                        ← 二级分支（方向）
│   │   └── 小程序 1.0              ← 三级分支（有终点的目标）
│   ├── 副业
│   └── 周末兼职
├── 健康
│   ├── 跑步
│   │   └── 半马训练
│   └── 睡眠
└── 生活
    └── 搬家
```

- **待办可以挂在任意一级到三级分支上**，不必先建"项目"；**也可以不建分支直接记一笔，默认落在根分支上**。
- **完成待办 = 在那条线上打一个提交点**，线越长表示越活跃。
- **分支只能合并到自己的父分支**，合并后子分支保留为「已合并」。

### 2.2 只有 5 个对象

| 对象 | 是什么 | 关键字段 | 生命周期 |
|---|---|---|---|
| **分支** | 唯一的结构容器，可嵌套、可合并 | 名称、父分支、层级、颜色、状态、目标、起止 | 进行中 → 已合并 / 已放下 |
| **待办** | 最小可执行单元 | 标题、所属分支、截止、优先级、状态 | 完成 / 取消 |
| **提交** | 待办完成时自动产生，不可修改 | 一句话、时间、所属分支、关联待办 | 永存 |
| **里程碑** | 人为标记的锚点 | 标题、日期、备注 | 永存 |
| **徽章** | 达成条件后授予 | 类型、授予时间、当时数据 | 永存 |

被取消的四个概念：

| 旧概念 | 现在 |
|---|---|
| 领域 | 一级分支（工作 / 健康 / 生活） |
| 项目 | 二级或三级分支 |
| 并行线 | 就是分支 |
| 仓库 | 不存在。全应用只有一棵树 |

### 2.3 层级与上限

数字是为了让树能一次查完、不让用户迷路，不是拍脑袋的审美。

| 层 | 叫法 | 例子 | 每个父节点上限 | 全树活跃上限 |
|---|---|---|---|---|
| 根 | 根分支 | 我 | 1 | 1 |
| L1 | 一级分支 | 工作 / 健康 / 生活 / 关系 / 成长 / 兴趣 / 财务 | 根下 ≤7 | ≤7 |
| L2 | 二级分支 | 主业 / 副业 / 跑步 / 睡眠 | 每个 L1 ≤9 | ≤63 |
| L3 | 三级分支 | 小程序 1.0 / 半马训练 / 搬家 | 每个 L2 ≤20 | ≤200（全树活跃合计） |

规则：

1. **不能建第 4 层**；三级分支下面只能放待办。
2. 同一父分支下，名称不能重复。
3. **只有「活跃」分支计入上限**；已归档分支不计入、不参与默认查询。**收尾时选「留在默认树」的分支仍计入上限**——它在默认树上占一行位置，消耗的就是那 200 个额度里的一个。
4. 活跃分支达到 200 时，新建分支前必须先归档一条已合并 / 已放下的分支；没有可归档的，先合并或放下一条。
5. 待办可挂在 L1–L3 任意层，但一条待办只属于一条分支。

### 2.4 七条不变量

1. 全树只有一个根；根不能删除、不能合并、不能放下。
2. 分支最多 3 层；不能建第 4 层。
3. 一条待办必须归属于某条分支；不选分支时自动挂在根分支上；完成待办**必然**产生一条提交。
4. 提交**跨天不可修改**；当天可改可删，用于纠正录入误差，且修改与删除都留一条痕迹。纠错不设「更正提交」链。
5. 分支只能合并到自己的父分支，不能跨父合并，也不能合并到子分支。
6. 有提交或有待办的分支不能删；只能合并或放下。**整棵子树都为空（0 提交且 0 待办）的分支可直接删除。** 合并后行仍保留（提交仍引用它），只是默认树不显示。
7. **已收尾（已合并）的分支一律只读**，不论是否归档：不能再新增待办或提交。已归档的分支同样只读，取消归档后也只读。想做新事，开新分支。

### 2.5 分支的收尾与放下

| 方式 | 含义 | 必填 | 结果 |
|---|---|---|---|
| **收尾：合并，并归档** | 做完了，这段属于父分支的一部分 | 可选一句说明 | 提交并入父分支历史；父分支出现汇合点；子分支自动归档、离开默认树 |
| **收尾：合并，留在树上** | 做完了，但这段想一直挂在树上看得见 | 一句小结 | 提交并入父分支历史；父分支出现汇合点；子分支标记完成、留在默认树，**仍计入活跃额度** |
| **放下** | 主动不做了 | 一句原因 | 线变灰，保留在树上；30 天后进入停滞虚线；可「重新开始」恢复为进行中，原因保留在历史里 |

**为什么「合并」和「结束」合成一个动作。** 两者都表达「这段做完了，提交并入父分支」，唯一差别是这条线还要不要一直挂在默认树上。合并后提交带来源分支标签、归档区完整保留这条分支，所以「考研那段能不能被区分」在两种形态下都成立，不需要为它单独设一种结束方式。用户只需要回答一个直觉问题：**这段还要一直挂在树上吗？**

> 操作名称待定：`合并` / `收尾` / `并回` 之外还有别的候选，等详细功能拆分时再定稿；两种选择的文案也在那时确定。本节只锁定语义与结果。

**不设「暂停」状态。** 暂时不做就放着，30 天没有提交会自动变成停滞虚线，不需要额外操作。

**合并的语义和 Git 一致：合的是提交，不是待办清单。**

- 子分支上已完成的提交，合并后从父分支的历史里可见；提交本身不改内容、不改时间。
- 子分支上未完成的待办，合并时一并移到父分支；确认框里会显示条数，也可以选择取消掉。
- 只有没有活跃子分支的分支才能被合并；有子分支的先各自合并或放下。
- **合并不可撤销。**

**父分支的历程口径：合并前只看自己的提交，合并后才把子分支的提交并入。**

- 合并前：父分支的历程只显示挂在它自己身上的提交，子分支的提交不出现在父分支历程里（树上看得到子分支这条线，但那是子树视图，不是父分支的历程）。
- 合并后：子分支的提交并入父分支历程，时间顺序不变，标注来源子分支。
- 这与 Git 一致：分支指针在合并前感知不到对方，合并产生汇合点之后，历史才连成一条。

**归档是可见性开关，不是状态。** 合并时选「归档」会自动设上；选「留在树上」的不归档。手动归档只对已完成或已放下的分支开放，进行中的分支不能归档。归档后：

- 从默认分支树和快速添加的候选里消失，只出现在「归档」折叠区。
- 不计入活跃分支上限，不再参与停滞虚线提醒。
- 计数冻结，不再更新。
- 随时可以取消归档，回到默认树。
- **历程默认仍然显示归档分支**——历史不能被藏起来，只是默认树不查它。

**删除不是结束方式，是「撤销创建」。** 只对 **整棵子树都为空**（0 提交且 0 待办）的分支开放：这种分支还没产生任何历史，删掉不损失任何信息，数据行直接移除、不留痕迹。自己为空但下面挂着有内容的子分支时不能删，否则子分支会失去父指针。一旦有了提交或待办，就只能走合并或放下两条路——历史不能被抹掉。

### 2.6 查询与规模约束（产品级）

这一节写给后面的数据模型和界面，避免树长大以后查不动：

1. **树一次查完**：活跃分支 ≤200，进应用时一次取回活跃树，不做递归查询、不做分页。
2. **活跃与归档分开查**：默认树只查未归档分支；归档分支按一级分支懒加载，只在打开「归档」或「历程」时取。
3. **每条分支冗余三个计数**：待办数、提交数、最后提交时间。停滞虚线只看「最后提交时间」，不扫描全量提交。
4. **提交按「分支 + 时间」分页**：树上只显示每条线最近 1 条；点进分支详情再按时间倒序加载。
5. **路径唯一且可读**：分支路径形如 `工作/副业`，同级重名直接拒绝。
6. **移动分支要校验深度**：移动后整棵子树深度不得超过 3；不能移动到自己的子孙下。
7. **合并只改可见性**：子分支的提交不搬、不改；合并前父分支历程只含自己的提交，合并后才把子分支的提交并入；合并后子分支自动归档。

## 5. 徽章体系

### 5.1 五条原则

1. **奖励结构，不奖励数量。** 「完成 100 个待办」只会催生 100 个「喝水」；「把一条子分支并回父分支」才代表你学会了安排生活。
2. **没有断签。** 不做连续打卡清零。连续类徽章只记录历史最高，断了不掉、不催、不红点。
3. **每枚都要能说清为什么给你。** 徽章详情里写当时的真实数据。
4. **徽章长在树上。** 徽章墙只是索引，主场是它出现在某条线的某一天。
5. **不设稀有度、不排名、不比朋友。**

### 5.2 四类 21 枚

**第一类：结构类（8 枚）——你学会了怎么安排**

| 徽章 | 获得条件 |
|---|---|
| 第一道岔 | 第一次创建子分支 |
| 汇流 | 第一次把子分支合并到父分支 |
| 收束 | 某个分支下所有子分支都已合并 |
| 双线并行 | 同一个父分支下两条子分支同时活跃 ≥14 天 |
| 断舍离 | 第一次「放下」分支并写了原因 |
| 有始有终 | 一个三级分支从创建到收尾，提交 ≥10 条 |
| 五面 | 五个一级分支都至少有 1 条提交 |
| 主干 | 某个一级分支连续 3 个月有提交 |

**第二类：时间类（4 枚）——你和时间的关系**

| 徽章 | 获得条件 |
|---|---|
| 起笔 | 第一条提交 |
| 补白 | 第一次回填过去的事件 |
| 常青 | 单条分支持续有提交 ≥6 个月 |
| 第一年 | 使用满 365 天 |

**第三类：里程碑类（4 枚）——你主动标记的人生**

| 徽章 | 获得条件 |
|---|---|
| 立碑 | 第一个里程碑 |
| 三碑 | 累计 3 个里程碑 |
| 碑上有字 | 里程碑写了备注 |
| 年轮有痕 | 同一年内 ≥3 个里程碑 |

**第四类：彩蛋类（5 枚）——不预告，撞见才有**

| 徽章 | 获得条件 |
|---|---|
| 夜航 | 连续 3 天在 23:00–5:00 完成待办 |
| 跨年 | 12 月 31 日或 1 月 1 日有提交 |
| 空白年 | 某一年只有 1 条提交 |
| 复活 | 停滞 ≥90 天的线重新有提交 |
| 满月 | 某个月每天至少有 1 条提交 |

> 「生日」徽章需要生日字段，等账号体系落地后再补。

### 5.3 获取与展示规则

- **判定时机**：完成提交 / 创建里程碑 / 建子分支 / 合并分支时即时判定。
- **通知方式**：不弹窗、不打断。当天「今天」页底部出现一条轻提示。
- **MVP 展示**：4 枚徽章在「我的」里以简单列表呈现，不做徽章墙。
- **墙上展示**：四类分栏。结构类与时间类只给接近达成的显示「还差什么」；彩蛋类未获得时完全不显示。
- **树上展示**：在获得那天的节点旁加一个小徽章标记，悬停或点击才展开名称，同一天不重复显示。
- **不可撤销**：徽章一旦获得不回收。

### 5.4 明确不做

| 不做 | 原因 |
|---|---|
| 排行榜 / 好友对比 | 一旦可比就会造假 |
| 稀有度标签 | 制造稀缺焦虑 |
| 断签惩罚 / 补签卡 | 会把工具变成负担 |
| 积分兑换 / 徽章换皮肤 | 把荣誉变成货币 |
| 强制分享 | 人生数据不该默认外流 |

## 6. 哪些功能真正值得做

### 6.1 护城河（4 项，不可砍）

| 功能 | 为什么是护城河 |
|---|---|
| **提交跨天不可改** | 所有日记和待办软件都能编辑。敢说"过了今天这条就锁死"，回看才有分量。当天留出纠错窗口，改的是错别字，不是历史。 |
| **停滞虚线** | 别的软件只显示你做了什么，不显示你**没做**什么。 |
| **一棵树只有一种结构** | 从生活面到具体目标只有分支一种容器，不需要在项目和标签之间切换。 |
| **徽章长在树上** | 成就是和时间绑定的路标，不是收集品。 |

一句话注解保留为低成本增强，不再列为护城河。

### 6.2 必须有但不差异化（照做即可）

快速添加、提醒、搜索、导出、明暗主题、拖拽排序、分支配色。做不好用户会走，做好了也没人夸。

### 6.3 建议不做

| 不做 | 原因 |
|---|---|
| 社交 / 好友 / 排行 | 与「不做人生导师」冲突 |
| 强制打卡 / 连续签到 | 把工具变成 KPI |
| 自定义字段 / 多维表格 | 复杂度爆炸 |
| 番茄钟 / 时间统计 | 另一个产品的事 |
| 多人协作 | 人生是自己的 |
| 子任务 | 会让项目变成一张网 |
| AI 替你写总结 | AI 可以归类、起标题，**不能替你感受** |

## 7. 版本切分

| 阶段 | 一句话目标 | 包含 | 不含 |
|---|---|---|---|
| **MVP** | 验证「待办 → 提交 → 树上有节点」这个闭环有人要 | 29 项：引导、今天、3 层分支树、新建/移动/删除空分支、收尾合并、完成即提交、提交跨天不可改、时间树、停滞虚线、周回顾、备份导出、4 枚徽章、注解、纯本地 | 放下、归档、年轮、完整徽章、模板、同步、补记 |
| **V1** | 让「人生」这件事成立 | 22 项：合并的完整形态、放下、归档、年轮、21 枚徽章、重复待办、补记、批量导入、导入、分享图、月回顾、异地备份、匿名统计 | 账号、同步、多端、模板 |
| **V2** | 让长期使用与换设备成为可能 | 7 项：账号、端到端加密同步、第二端、彩蛋徽章、帮助与常见问题、分支模板 | 协作、社交 |

**如果只能做 15 项**：

A-01 引导 · B-01 快速添加 · C-01 今日 · C-02 一键完成 · D-01 分支树 · D-02 分支详情 · D-03 新建与移动子分支 · D-04 收尾合并 · E-01 完成即提交 · E-02 提交跨天不可改 · E-03 提交详情 · F-01 时间树 · F-02 停滞虚线 · J-02 自动备份 · L-01 无账号可用

这 15 项构成「建分支 → 做完了 → 线上有提交 → 能回看」的最小闭环。

**MVP 的验收只有一句话**：5 个真实用户用它记录两周，第 15 天有人主动打开时间树往回看。

## 8. 决策记录

v0.1 的 9 个决策已全部收敛，结论如下：

| # | 决策 | 结论 |
|---|---|---|
| 1 | 并行线进 MVP 吗 | 作废。并行线概念取消，分支是核心，MVP 即支持 3 层 |
| 2 | 重复任务要不要 | 要，做成「模板待办」，不预生成实例 |
| 3 | 项目能跨领域吗 | 作废。单根一树，不存在跨领域 |
| 4 | 记录"不可改"的强度 | **当天可改可删（留痕），跨天完全锁定**；不设更正提交链 |
| 5 | 徽章一次做全还是先几枚 | 先 4 枚（起笔 / 第一道岔 / 立碑 / 汇流），放「我的」列表，不做墙 |
| 6 | 回顾是独立入口吗 | 嵌入今天（卡片）+ 历程（年轮） |
| 7 | 账号的必要性 | 纯本地，登录延到 V2 |
| 8 | AI 放哪一层 | 当前版本不做 AI 录入（语音、截图已删）；若将来做，只归类、起标题，总结必须用户自己写 |
| 9 | 要不要子任务 | 不要 |

v0.2 新增并已定：

| # | 决策 | 结论 |
|---|---|---|
| 10 | 根分支几个 | 全树唯一一个，不可删、不可合并 |
| 11 | 最多几层 | 3 层（L1–L3），不能建第 4 层 |
| 12 | 分支能往哪合并 | 只能合并到自己的父分支 |
| 13 | 合并后子分支 | 提交在父分支历史里可见；两种形态：归档（离开默认树）或留在默认树；数据行始终保留 |
| 14 | 结束方式 | 收尾（合并到父，可选归档 / 留在树上）+ 放下（写原因）两种；「结束」并入收尾，不再独立 |
| 15 | 保留几种视角 | 只保留一种，取消项目模式 / 人生模式双词表 |
| 16 | 界面用词 | 「提交」，不用「记录」 |
| 17 | 旧数据怎么处理 | **不迁移，直接删除**。新版本从空树开始 |
| 18 | 合并后的分支怎么处置 | 收尾时二选一：归档（离开默认树、不计入上限）或留在默认树（仍计入活跃上限）；数据行始终保留；历程里保留一个汇合点 |
| 19 | 要不要「暂停」状态 | **不要**。暂时不做就放着，靠停滞虚线表达 |
| 20 | 改版姿态 | **重做 Web 客户端**：保留分层、DI、测试设施，业务层重写 |
| 21 | 已投的登录后端 | **删除**。当前版本不做账号、不做同步；V2 若要做同步，重新设计，不沿用旧实现 |
| 22 | 待办是否必须先建分支 | **不需要**。不选分支的待办默认落在根分支上，直接记一笔就能开始 |
| 23 | 上手四项去留 | **全部保留**。引导改为 1 个一级 + 1 个二级 + 1 条待办，三步即可完成 |

唯一待确认：无。上限数字已确认：L1 ≤7、L2 ≤9、L3 ≤20、活跃 ≤200。

**留给详细设计定稿的两处措辞**（语义已锁定，只是名字未定）：

1. 「做完了」这个动作叫什么：`合并` / `收尾` / `并回` 等待选，以及两个选项（归档 / 留在树上）在界面上的文案。
2. 该动作在分支详情里的入口位置与确认框措辞。

## 9. 下一轮怎么走

产品层评审已结束。接下来是两条并行的工作线：

### 9.1 视觉规范（先做）

旧版视觉体系已整体归档，新版需要从零设计。建议按以下顺序产出：

1. **配色与令牌**：7 个分支色相（对应 K-03 的 ≤7 规则）、明暗两套、语义色
2. **分支树的视觉语言**：泳道图的行高、连线、节点、汇合点、停滞虚线的具体形态
3. **页面草图**：今天、分支树、分支详情、历程、年轮各一版
4. **组件清单**：从页面反推需要哪些组件

### 9.2 数据模型与查询设计

- 分支表（父指针 + `path` + `depth` + 三个计数 + 状态 + 归档标记）
- 待办表、提交表、里程碑、徽章
- 索引设计：`[isArchived+parentId]`、`[branchId+createdAt]`、`path` 前缀
- `syncState` 字段与 V2 预留（见 ARCHITECTURE §7）

### 9.3 之后的实现顺序

1. 数据层与领域模型
2. 今天 + 快速添加
3. 分支树与分支详情
4. 完成与提交（跨天锁定是难点）
5. 时间树泳道渲染
6. 回顾与徽章
7. 数据与备份

每个功能点出稿时给：用户故事 → 交互与状态 → 边界与异常 → 验收标准。

## 10. 评审总结（2026-11-17）

功能清单最终定为 58 项（MVP 29 / V1 22 / V2 7）。下表是评审中删掉 / 合并的项与新增的编号；两者不构成简单加减，期间还包含编号顺移与范围调整。

| 删掉 / 合并的 | 原因 |

| 「结束」状态 | 合并进收尾，可见性由归档开关表达 |
| D-08 分支模板 | 与 B-03 重复 |
| 「结项小结」 | 属于收尾流程，不单占编号 |
| 里程碑照片 | 本地照片存储成本高，价值弱 |
| 树上搜索 | 并入全局搜索 |
| 年度章节 | 并入年轮 |

| 新增 | 为什么 |
|---|---|
