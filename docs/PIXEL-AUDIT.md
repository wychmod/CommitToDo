# 像素级 UI 核对

本文是 [`VISUAL-AUDIT.md`](./VISUAL-AUDIT.md) 的接续：旧文按「结构 → 样式」级别列偏差；本文把标准收紧到像素，逐页给出「画稿值 / 实测值 / 差值」三列，并记录修复提交、残余差异与待定项。旧文已完成的结构类条目不再重复，只在仍影响像素位置时引用。

- 代码基准：`91a64cc`（本轮开始时的 HEAD）
- 画稿基准：`design/images/*.png`（应用页均为 1440×960/1040/1123 的原尺寸渲染，可直接 1:1 叠图）；结构值同时以 `design/source/*.mjs` 与同名 `.css` 为准
- 核对时间：2026-11-22（UTC+8）
- 目标视口：1440×画稿高（DPR 1，浅色）；390×844（DPR 2，mobile + touch）只按断点规则核对，不套 1440 画稿
- 滚动位置：每页导航后 `window.scrollTo(0, 0)`，截图为视口截图（非 fullPage），与画稿同高
- 数据：IndexedDB `committodo`，5 分支 / 8 待办 / 3 提交 / 1 里程碑 / 4 徽章；示例文案与画稿示例不同，文字区域差异不计入 UI 偏差，只按盒子几何与令牌值比对
- 截图与叠图：`2026-11-22/ui-pixel-audit/`（不入库）；临时测量脚本在 `%TEMP%/pixel-audit/`
- 叠图算法：画稿与实测各转灰度 → 1px 高斯模糊 → 绝对差；阈值 24/255 以上的像素计为差异，同时输出红（画稿）青（实测）叠图与差异热区图。文字抗锯齿与示例数据会抬高比例，因此比例只作趋势参考，结论以盒子测量为准
- 严重度：**阻断**＝不可见/不可达/重叠；**明显**＝可用但几何或令牌值可见不符；**细节**＝1–3 px 或仅在放大下可见

## 复现方式

```powershell
# 1) 工作树启动（避开其他线的 5173/5175/5182）
cd web; npm run dev -- --port 5180 --strictPort

# 2) Chrome DevTools MCP：固定视口、DPR、主题、滚动
#    emulate viewport: "1440x<画稿高>x1", colorScheme: "light"
#    navigate url → evaluate () => scrollTo(0,0) → take_screenshot(filePath)

# 3) 叠图（Python + Pillow）
python %TEMP%\pixel-audit\diff.py design\images\<page>.png <shot>.png <out-prefix> 24
```

页面测量统一返回 `getBoundingClientRect()` 的 x/y/w/h 与 `getComputedStyle` 的 fontSize / lineHeight / letterSpacing / padding / gap / gridTemplateColumns / backgroundColor / borderColor。
