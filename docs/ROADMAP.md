## 1. 规划原则

- 不按日期排期，按**阶段门禁**推进；每个阶段只验证一个核心假设。
- 每个阶段都有明确的「不包含」，范围蔓延优先记入「暂不排期」。
- 先修地基（数据安全、模型、假开关），再做增长功能。
- 每个阶段结束必须能回答：假设是否成立？下一步是否值得投入？
- 不以功能数量衡量进度，以「用户是否完成核心闭环」衡量。

> **主用户已定（2026-11-13）：程序员 / 技术型知识工作者。** 下表「目标用户」列只区分**验收对象**与**观察对象**——观察对象的数据可以看，但不作为阶段门禁的判据。

| 阶段 | 目标 | 核心假设 | 目标用户（验收对象） | 观察对象 | 退出条件 |

| **MVP** | 验证「任务 → 提交 → 主线 → 图」闭环 | 用户愿意为了看图而记录 | 主用户：程序员种子 | — | 5 人完成闭环；7 天回看；迁移与备份不丢数据 |

对排期的直接约束：

- MVP 的 13 项（M-01 ~ M-13）全部按主用户可用性验收，**不为降低门槛而删结构字段**。
- 引导类需求（M-07 Onboarding）在主用户语境下可以简化：一棵示例树 + 一句「这就是 git log」即达标。
- 分享类需求（V1-07 年度章节、V1-08 分享）在主用户语境下是加分项，不作为 MVP 门禁。

## 4. MVP

### 4.1 目标

让一个新用户在 10 分钟内建立 3 条主线，记录一周，周末看到一张能读懂的主线图。

### 4.2 范围

分两批，先地基后闭环。

#### MVP-A 地基（必须先完成）

| 编号 | 事项 | 验收 |
|---|---|---|
| M-01 | 新增 `LifeArea`、`Milestone` 与设置页领域管理；`Repository` 增加 `areaId`；迁移旧数据；导出格式升 v2（兼容 v1） | 旧库仓库 / 分支 / 任务 / 提交计数一致；领域可改名 / 改色 / 归档，主线归属可改 |
| M-02 | 双视角与词表：项目 / 人生两套分组与文案；全局词表（界面禁止哈希、分支名、英文前缀）；知识注解一句话文案（4 个触发点）；模式开关（onboarding 首选项 + 设置可改） | 切换不改数据与统计口径；全站走查无英文标识符；任一词条只有一个来源；同一组件不写两遍 |
| M-03 | 自动备份真实可用（每日首次启动快照，保留最近 7 份） | 清空 IndexedDB 后可恢复 |
| M-04 | 示例数据加「示例」标识，或改为空状态引导 | 新用户不误认示例为自有数据 |
| M-05 | 提醒设置隐藏，或实现真实调度 | 不存在「可开启但不触发」的开关 |
| M-06 | 路由级拆包 + 全局 ErrorBoundary | 首屏 gzip < 500 kB；渲染错误有兜底 |

#### MVP-B 闭环

| 编号 | 事项 | 验收 |
|---|---|---|
| M-07 | Onboarding：选领域 → 建 3 条主线 → 可选回填 1–3 个过去节点（基础表单） | 5 人测试中 ≥4 人无指导下完成 |
| M-08 | 今天视图适配新模型 | 今日 / 逾期 / 待提交可用 |
| M-09 | 主线视图：进度、最近提交、停滞提示 | 14 天无提交标记「停滞」 |
| M-10 | 历程视图（人生树基础形态，**单一渲染**）：完成记录 + 里程碑合并时间轴、并行线关系图；真实时间轴、节点为「一句话 + 日期 + 主线色」、里程碑大节点、停滞主线虚线 | 可按领域 / 主线 / 时间筛选；两种模式共用同一渲染，仅着色与分组不同；图上无任何哈希或分支名 |
| M-11 | 完成提交支持一句话（可选） | 留空可完成；默认消息自动生成 |
| M-12 | 周复盘：提交数、领域分布、停滞主线、一个反思问题 | 每周自动生成，可编辑保存 |
| M-13 | 关键路径 E2E + CI | onboarding → 建任务 → 完成 → 回看 全通过 |

### 4.3 验收标准

- **A-01 可用性**：5 名种子用户，≥4 人无指导下完成「建 3 条主线 → 加 1 个任务 → 完成 → 在历程图找到这次提交」。
- **A-02 回看**：连续使用 7 天后，≥3 人能说出「哪条主线本周没有推进」。
- **A-03 数据**：旧库迁移后仓库 / 分支 / 任务 / 提交计数一致；抽样 10 条字段一致。
- **A-04 恢复**：清空浏览器数据后，从自动备份恢复，任务与提交完整。
- **A-05 质量**：`lint` / `tsc` / `test` / `build` / E2E 全绿。
- **A-06 诚实性**：所有可见开关都有真实行为；未实现功能不显示为可用。

### 4.4 不包含

- 账号与同步、AI、分享卡片、年度报告、子任务 UI、标签、团队协作、原生 App。

### 4.5 依赖与风险

- **依赖**：现有 Dexie 迁移机制、DI 容器、四个主视图、本地模式。
- **风险**：
  - 模型迁移丢数据 → 迁移前自动导出、计数校验、保留旧库。
  - 模式切换文案遗漏 → 集中文案表（单一来源）+ 两种模式的关键页面截图走查。
  - 界面漏出英文标识符 → 把「无哈希 / 无分支名」写进 M-02 验收，并在 E2E 里断言页面文本不含 `[0-9a-f]{7,}` 与 `feat(`。
  - 周复盘无数据可看 → 模板 + 示例提交 + 空状态引导。

## 5. V1

### 5.1 目标

让用户愿意把过去的人生节点补进来，并主动回看与分享。

### 5.2 范围

| 编号 | 事项 | 验收 |
|---|---|---|
| V1-01 | 里程碑照片：可选照片、缩略图、替换 / 删除 | 上传失败不阻塞文字内容；可重试 |
| V1-02 | 回填引导增强：模板、示例文案、3–5 个过去节点 | 10 人测试中 ≥6 人完成 |
| V1-03 | 分叉 / 合并 / 放下仪式：原因、合并说明 | 历程图可追溯；归档可恢复 |
| V1-04 | 年轮 / 年度章节 | 按年聚合提交与里程碑 |
| V1-05 | 周 / 年分享卡片 | 3 秒内生成；可隐藏任务标题；无 PII |
| V1-06 | 5 条主线模板（健康 / 事业 / 关系 / 成长 / 财务） | 一键套用，可改 |
| V1-07 | 洞察增强：领域分布、停滞主线、连续提交 | 口径与 PRD 一致 |
| V1-08 | 子任务 UI + 标签 | 父子关系可见；标签可筛选 |
| V1-09 | 提醒真实调度 | 截止前按设置触发；失败有提示 |
| V1-10 | 主线排序与置顶 | 手动排序；置顶最多 3 条 |
| V1-11 | 任务迁移 | 可移动到另一条支线 / 主线；写 update 提交 |
| V1-12 | 人生树完整形态：按年分区形成年度章节带、时间密度缩放（近期放大 / 远期压缩）、同日多次记录折叠 | 500 节点可交互；年度带可折叠；与 V1-04 年度章节口径一致 |

### 5.3 验收

- **B-01**：10 名目标用户中 ≥6 人完成至少 3 个过去里程碑的回填。
- **B-02**：≥3 人主动生成或分享周报 / 年报卡片。
- **B-03**：分享卡片默认隐藏任务标题，用户可显式选择展示。
- **B-04**：合并 / 放下均有提交记录，可在历程图追溯。
- **B-05**：年度章节中的每条汇总可下钻到原始提交。

### 5.4 不包含

- 同步、多端、AI、团队、原生 App。

## 6. V2

### 6.1 目标

让长期使用成立：换设备不丢、记录成本更低、账号有意义。

### 6.2 范围

| 编号 | 事项 | 验收 |
|---|---|---|
| V2-01 | 端到端加密同步 | 服务端不可读明文；密钥仅用户持有 |
| V2-02 | 多端：Web + 第二个端（小程序 / 桌面二选一，按数据定） | 只读链路先跑通，再写操作 |
| V2-03 | 账号安全闭环：重认证、解绑、双账号合并 | 安全审计通过 |
| V2-04 | AI：周复盘草稿、任务拆解、提交消息建议 | 默认不自动写入；可编辑 / 拒绝 |
| V2-05 | 备份 / 恢复演练与可观测性 | 每版本一次恢复演练；错误可追踪 |
| V2-06 | 付费边界（如需要）：同步 / AI 增值 | 不削弱本地免费核心 |

### 6.3 验收

- **C-01**：双设备 A 写入后，设备 B 10 秒内可见；离线修改有明确冲突策略。
- **C-02**：清空环境后可从云端恢复全部数据与提交。
- **C-03**：AI 建议采纳率 / 编辑率可观测；无确认不写入。
- **C-04**：账号注销、导出、删除闭环；注销后数据不可恢复提示明确。

### 6.4 不包含

- 团队协作、社交、内容社区。

## 7. 阶段门禁

| 门禁 | 条件 | 不满足时 |
|---|---|---|
| MVP → V1 | A-01 ~ A-06 全过；20 人种子样本 D7 留存 ≥30%（建议阈值） | 留在 MVP 修闭环，不叠加人生功能 |
| V1 → V2 | B-01 ~ B-05 全过；「多设备 / 数据安全」进入用户反馈 Top 2 | 先强化备份与导出，不急着做同步 |
| V2 上线 | C-01 ~ C-04 全过；安全与恢复演练通过 | 延期，不以「先上线再补」处理 |

> 阈值为建议值，需在真实样本中校准；不得用未经验证的数字对外承诺。

## 9. 数据迁移

1. Dexie v5：新增 `areas`、`milestones`；`repositories` 增加 `areaId`。
2. 迁移前自动导出一次 JSON 备份，并保留旧库。
3. 旧仓库默认归入「未分类」领域，引导用户批量调整；不猜测归属。
4. 迁移后计数校验：repositories / branches / tasks / commits 数量一致。
5. 失败回滚：保留旧库与备份文件；新库不覆盖旧库。
6. 导出格式升级到 v2；导入兼容 v1。
