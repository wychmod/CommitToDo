## 1. 背景与目标

### 1.1 背景

任务工具解决了「做完」，但没有解决「在推进什么」；日记工具解决了「记录」，但没有解决「推进」。用户完成了很多事，却很难回答三个问题：

- 这周我到底推进了哪条主线？
- 哪些长期方向已经停滞，但一直没被看见？
- 过去一年，我的人生轨迹是什么形状？

Commit 用 Git 的提交模型把两者接起来：任务完成即提交，提交挂在主线上，主线归属人生领域；所有提交按时间连起来，就是可回看、可分叉、可合并的历程。

### 1.2 目标

1. 让用户用不超过 3 秒记录一次提交。
2. 让用户用一张图回答「我在推进什么」。
3. 让用户一年后还能回看自己的主线与人生节点。

### 1.3 成功指标

| 指标 | 定义 | 目标（建议，待校准） |
|---|---|---|
| 激活率 | 完成 onboarding（3 条主线 + 1 个任务）的新用户 ÷ 新用户 | ≥60% |
| D7 留存 | 第 7 天有提交的激活用户 ÷ 激活用户 | ≥30% |
| 周提交数 | 每周每活跃用户的提交数 | ≥5 |
| 自定义消息率 | 带自定义消息的完成提交 ÷ 全部完成提交 | ≥30% |
| 回填率 | 创建 ≥1 个里程碑的激活用户 ÷ 激活用户 | ≥40% |
| 分享率 | 生成分享卡片的周活用户 ÷ 周活用户 | ≥5% |

> 以上为待验证目标，不是已验证结论；对外不得作为承诺。

## 2. 产品定位

**Commit 把人生当成一条主线，把每件小事变成一次提交。**

- 情感版传播语：**把答应自己的事，一件件兑现。**
- 结构版传播语：**人生有主线，也允许支线。**

### 2.1 不是什么

- 不是团队项目管理工具（不做甘特图、成员、权限）。
- 不是笔记 / 知识库（不做第二大脑）。
- 不是社交产品（不做 feed、排行榜、打卡竞赛）。
- 不是人生导师（只呈现事实与问题，不给建议）。

### 2.2 差异化

| 对比对象 | 他们有 | 他们缺 | Commit 的差异 |
|---|---|---|---|
| Todoist / 滴答清单 | 任务、提醒、协作 | 归属与历程；图是装饰 | 任务挂在主线，提交形成历程 |
| Notion | 自由、可定制 | 结构与节奏；维护成本高 | 固定模型，降低维护成本 |
| 日记 / 时间线 App | 记录、回忆 | 推进与决策 | 记录即推进，提交即证据 |
| 人生规划 App | 目标拆解、打卡 | 真实的分支 / 合并 / 版本 | Git 语义是结构，不是装饰 |

## 3. 目标用户与场景

> **用户优先级已定（2026-11-13）**：主用户 = 程序员 / 技术型知识工作者，是 MVP 与 V1 的唯一验收对象。扩散用户进入验收范围的时点是 V1 之后，MVP 不为其做体验妥协。决策依据见 [`PRODUCT-STRATEGY.md`](./PRODUCT-STRATEGY.md) §3。

### 3.1 用户

| 优先级 | 类型 | 画像 | 核心诉求 | 使用频率 | 进入验收阶段 |
|---|---|---|---|---|---|
| **P0（主用户）** | 程序员 / 技术型知识工作者 | 已在用 Git 思维，能忍受结构化输入 | 可追溯、可分支、可回看 | 每天 | MVP |
| P1（扩散） | 25–35 岁城市知识工作者 | 正在做年度规划、周复盘、人生节点记录 | 年度规划、周复盘、人生节点 | 每周 | V1 之后 |

FR 条目凡标注「MVP」者，一律以 P0 用户的可用性为验收标准；P1 相关需求（如引导、分享美化）标注为 V1。

### 3.2 核心场景

**场景 A：周一早上，决定先做什么**
打开「今天」，看到三条主线各有一个待办；完成其中一个，写一句「把定位文档收尾」，提交自动进入事业线。

**场景 B：周日晚上，复盘一周**
打开「主线」，看到事业线本周 5 次提交、健康线 14 天没有提交；系统提示「健康线已停滞」，用户决定下周只保一条主线。

**场景 C：年末，回看一年**
打开「历程」，看到 3 个里程碑、120 次提交、两条支线合并回主线；生成年度章节，选择隐藏任务标题后分享。

### 3.3 非目标场景

- 多人协作、任务分派、审批流。
- 长篇日记、图文排版、知识管理。
- 社交互动、排行榜、挑战赛。

## 4. 核心概念

### 4.1 两个轴

| 轴 | 结构 | 回答的问题 |
|---|---|---|
| 归属轴（树） | 人生领域 → 主线 → 支线 → 任务 | 这件事属于我人生的哪一块 |
| 历程轴（图） | 提交 → 分叉 → 合并 → 里程碑 | 我是怎么走到今天的 |

### 4.2 实体

| 实体 | 产品名 | 关键字段 | 说明 |
|---|---|---|---|
| `LifeArea` | 人生领域 | `id` · `name` · `color` · `icon` · `sortOrder` · `isDeleted` | 默认健康 / 事业 / 关系 / 成长 / 财务 |
| `Repository` | 主线 | 现有字段 + `areaId` | 长期方向，必须归属一个领域 |
| `Branch` | 支线 | 现有字段 | 从主线或提交分叉；`main` 为主线主干 |
| `Task` | 任务 / 小事 | 现有字段 | 必须归属一条支线 |
| `Commit` | 提交 / 足迹 | 现有字段 | 不可变；完成 / 更新 / 合并 / 删除 |
| `Milestone` | 里程碑 | `id` · `areaId` · `repositoryId?` · `title` · `note` · `occurredAt` · `photoRef?` · `isDeleted` | 独立时间锚点；照片存储形态 V1 定 |

### 4.3 不变量

1. 一条主线必须归属且只归属一个领域。
2. 一条支线必须归属一条主线；分叉记录 `parentBranchId`。
3. 一个任务必须归属一条分支（`main` 主干或支线）；任务完成必须产生一条提交。
4. 提交不可修改、不可删除；纠错通过新提交表达。
5. 里程碑不参与完成率统计，只进入历程时间轴。
6. 完成率 = `done ÷ (todo + inProgress + done)`；`cancelled`（放下）不计入分母。

> 完成率为 MVP 起的统一口径；现有页面若与该口径不一致，按此修正，并在 MVP 验收中核对。

### 4.4 两种视角

代码层保留 `Repository` / `Branch`，产品层用**两种视角**呈现：

| | 项目模式（默认） | 人生模式 |
|---|---|---|
| 组织方式 | 项目 → 并行线 → 待办 | 人生领域 → 主线 → 小事 |
| 记录示例 | 「修好 Safari 下登录页崩溃」 | 「第一次跑完 10 公里」 |
| 管什么 | 交付 | 历程 |

**两种模式都说中文，界面上不出现英文标识符**（哈希、分支名、`feat(...)` 前缀、裸 Git 术语），完整清单见 [`PRODUCT-STRATEGY.md`](./PRODUCT-STRATEGY.md) §7.2。

两种模式共用一套实体与一份数据，差别在分组方式、文案表与着色规则；**不新增第二套实体，也不做两套图**。Git 词汇仅在知识注解中出现（FR-39）。

## 6. 功能需求

### 6.1 领域与主线

| 编号 | 需求 | 规则与验收要点 | 阶段 |
|---|---|---|---|
| FR-01 | 领域管理 | 默认 5 个领域；可改名、改色、排序、归档；归档不删除其下主线；至少保留 1 个领域 | MVP |
| FR-02 | 创建主线 | 名称与领域必填；自动创建 `main` 分支（主线主干）；同领域重名给出提示但不阻塞 | MVP |
| FR-03 | 创建支线 | 可从主线或某次提交分叉；记录 `parentBranchId`；继承主线领域 | MVP |
| FR-04 | 合并支线 | 未完成任务迁移到目标主线；已完成任务与提交保留在原支线；原支线归档；写 merge 提交；合并说明必填（一句话） | MVP |
| FR-05 | 放下主线 / 支线 | 选择原因（不再重要 / 被替代 / 阶段性结束 / 其他）+ 一句话；其下任务一并归档；软删除；可从归档恢复 | V1 |
| FR-06 | 主线排序与置顶 | 手动排序；置顶最多 3 条；顺序跨会话保留 | V1 |

### 6.2 任务与提交

| 编号 | 需求 | 规则与验收要点 | 阶段 |
|---|---|---|---|
| FR-07 | 任务 CRUD | 标题必填；描述 / 优先级 / 截止日期可选；`parentTaskId` 字段保留，UI 在 V1 | MVP |
| FR-08 | 任务状态 | `todo → inProgress → done`；任意状态可 → `cancelled`（文案「放下」）；`done` 写入 `completedAt` | MVP |
| FR-09 | 完成任务生成提交 | 状态变更与提交写入必须原子；提交类型 `complete`；默认消息「完成：{标题}」 | MVP |
| FR-10 | 提交消息 | 默认自动生成；自定义最多 140 字；允许留空；不得阻塞完成操作 | MVP |
| FR-11 | 提交时间线 | 按时间倒序；显示类型、任务、支线、消息；支持按类型筛选 | MVP |
| FR-12 | 任务排序与筛选 | 排序：更新时间 / 优先级 / 截止日期；筛选：状态 / 优先级 / 关键词 | MVP |
| FR-13 | 子任务 | 支持父子关系；父任务完成时提示未完成子任务数，但不强制；子任务独立提交 | V1 |
| FR-14 | 任务迁移 | 可移动到另一条支线 / 主线；写 update 提交；保留原创建时间 | V1 |

## 7. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 首屏 < 2 秒（中端设备）；首屏 gzip < 500 kB；1000 条任务列表滚动 60fps；500 节点图可交互 |
| 离线 | 核心功能全部离线可用；同步为可选能力 |
| 隐私 | 本地优先；默认不接入第三方分析；分享卡片默认隐藏任务标题；支持导出与删除 |
| 可访问性 | 键盘可达；对比度满足基本可读性；交互控件有 `aria-*`；不依赖颜色单独传达状态 |
| 文案 | 界面正文不出现英文标识符（哈希 / 分支名 / `feat(...)` 前缀 / 裸 Git 术语）；所有条目为可朗读的完整中文短句；术语只出现在知识注解中 |
| 兼容性 | Chrome / Edge / Safari 最近两个大版本；iOS 15+ / Android 12+ PWA |
| 可靠性 | 自动备份每日执行；迁移失败可回滚；导入前自动备份；错误有兜底页面 |

## 8. 数据与指标

### 8.1 埋点事件

| 事件 | 触发时机 | 关键字段 |
|---|---|---|
| `onboarding_completed` | 完成 3 条主线 + 第 1 个任务 | `areaCount` · `lineCount` · `durationMs` |
| `task_created` | 创建任务 | `lineId` · `source`（quick / form） |
| `task_completed` | 任务完成 | `lineId` · `hasCustomMessage` · `durationMs` |
| `commit_message_added` | 提交时填写自定义消息 | `length` · `lineId` |
| `milestone_created` | 创建里程碑 | `areaId` · `hasPhoto` · `backfilled` |
| `review_opened` | 打开周复盘 / 年报 | `type` · `week` |
| `share_card_created` | 生成分享卡片 | `type` · `hideTitles` |
| `mode_switched` | 切换工程 / 人生模式 | `from` · `to` · `entry`（settings / onboarding / 视图内） |
| `life_tree_opened` | 以人生模式打开历程视图 | `lineCount` · `windowDays` · `hasMilestone` |

### 8.2 指标口径

| 指标 | 口径 |
|---|---|
| 激活率 | 完成 onboarding 的新用户 ÷ 同期新用户 |
| D7 留存 | 注册 / 首次使用后第 7 天有提交的用户 ÷ 激活用户 |
| 周提交数 | 统计周内 `commit` 总数 ÷ 周活跃用户 |
| 自定义消息率 | 带自定义消息的完成提交 ÷ 全部完成提交 |
| 回填率 | 创建 ≥1 个里程碑的激活用户 ÷ 激活用户 |
| 分享率 | 生成分享卡片的周活用户 ÷ 周活用户 |

> 目标值见 §1.3，均为建议值，需在真实样本中校准。

## 9. 权限与安全

- **本地模式**：无需账号，数据仅存本机；导出与删除由用户完全控制。
- **账号模式**：可选；用于同步与恢复。云端认证沿用现有 CloudBase + PostgreSQL 方案（RLS、HMAC、限流、幂等）。
- **分享**：默认隐藏任务标题与备注；用户显式选择后才展示；分享图片不包含邮箱、真实姓名、头像等 PII。
- **同步（V2）**：端到端加密；服务端不可读明文；密钥仅用户持有；提供恢复密钥与丢失提示。
- **注销**：明确告知不可恢复；注销前强制导出提醒。

## 10. 异常处理

| 场景 | 处理 |
|---|---|
| 首次使用无数据 | Onboarding 引导建 3 条主线；提供模板；不强制回填 |
| 迁移失败 | 停止迁移，保留旧库与备份，提示导出并联系支持 |
| 导入冲突 | 导入前预览；提供「跳过 / 覆盖 / 合并」；默认跳过；导入前自动备份 |
| 自动备份失败 | 设置页显示失败时间与原因；提供重试与手动导出 |
| 存储配额不足 | 提示清理或导出；禁止静默失败 |
| 照片上传失败（V1） | 保留文字内容；照片可重试；不阻塞里程碑创建 |
| 通知权限被拒绝 | 说明用途；不反复弹窗；提供站内提醒替代 |
| 同步冲突（V2） | 明确策略（最后写入优先 + 冲突副本）；冲突可查看与合并 |
| 账号注销 | 二次确认 + 输入确认词；提示先导出；注销后不可恢复 |

## 11. 风险与假设

### 11.1 关键风险

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 记录成本高 | 高 | 高 | 自动消息、可选一句话、周复盘代偿 |
| 冷启动图空白 | 高 | 中 | 回填、模板、导入 |
| 双人群定位撕裂 | 中 | 高 | 一套引擎两套皮；对外只讲一个叙事 |
| 数据丢失 / 无同步 | 中 | 极高 | 自动备份、导出、V2 加密同步 |
| 产品膨胀 | 高 | 中 | 不做清单；每个视图必须回答问题 |

### 11.2 待验证假设

| 编号 | 假设 | 验证方式 | 阈值（建议） |
|---|---|---|---|
| H1 | 用户愿意补一句话 | 自定义消息率 | ≥30% |
| H2 | 回填提升首周留存 | A/B：有 / 无回填引导 | D7 +10pp |
| H3 | 用户能读懂主线图 | 5 人可用性测试 | ≥4 人 |
| H4 | 分享带来回流 | 分享链接来源参数 | 分享率 ≥5%，回流 ≥1% |
| H5 | 人生树能让程序员在没有人生叙事需求时也留下来 | 观察：MVP 种子中人生模式打开率与次月留存 | 人生模式周活 ≥30%，且不显著低于项目模式 |
