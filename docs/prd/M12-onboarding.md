# M12 首次引导与示例树（MVP）

## 1. 背景与目标

第一次打开时，用户面对的是空工作区。引导要用三步把「建线 → 记一笔 → 完成并看见提交」走通；示例树则让暂时不想录入的人先看清产品长什么样，并且不污染真实数据。

目标：无数据用户进入今天页时看到三步引导，能在不读说明的情况下完成第一次提交；也能一键载入一棵只读示例树，随时删除。

## 2. 范围与非目标

**范围**

- A-01 首次引导：建第一条分支、记第一条待办、完成并看首条提交；可跳过；跳过不等于删除注解。
- A-02 示例树：3–4 条分支、8–12 条提交、2 个里程碑；与真实数据隔离；只读；一键删除。
- O06-first-task、O06-first-commit、O06-sample-tree 三个视图。
- 引导状态的本机保存与清空数据后的重置。

**非目标**

- 不做多页教程、视频、强制遮罩、逐元素高亮。
- 不做示例数据的编辑、完成、导出、参与统计或徽章。
- 不做账号注册引导（V2-01）。
- 不新增表或字段；示例数据不写入真实业务表。

## 3. 用户故事与主流程

**故事 1｜第一次打开，按三步走**

无数据进入 `/today` → 顶部出现引导卡「1/3 建一条分支」→ 输入「工作」并选色 → 保存 → 卡片变为「2/3 记第一笔」→ 输入「今天整理桌面」→ 保存 → 卡片变为「3/3 完成它」→ 勾选完成 → 出现「已提交 16:42」与「去历程看看」→ 点击进入历程并定位首条提交 → 引导结束。

**故事 2｜我只想先看看**

无数据进入今天页 → 引导卡上点「先看看示例」→ 载入示例树 → 顶部横幅「这是示例，不会进入你的数据」→ 浏览分支、提交、里程碑 → 点「删除示例」→ 回到真实空工作区。

**故事 3｜跳过引导**

点「跳过」→ 引导卡收起，今天页显示普通空态与「记一笔」→ 下次进入不再自动展开引导 → 四个概念的注解仍可在对应页面查看。

**故事 4｜清空后重新开始**

在数据页清空本机数据 → 回到今天页 → 引导重新从 1/3 开始，示例数据也已清除。

**异常与边界**

- 引导步骤未完成就离开：已完成的步骤保留；下次进入从下一步继续。
- 引导中新建分支失败：停留当前步骤，保留输入并显示原因。
- 第一条待办保存成功但未完成：停在 3/3，待办保留在今天清单。
- 完成第一条待办后没有立刻去历程：引导可结束，之后从回执或最近提交进入历程。
- 示例载入失败：显示原因 + 重试；不进入半载入状态。
- 示例数据已在：不重复载入，直接进入示例并保留原删除入口。
- 已存在真实数据：不自动出现引导，也不提供示例入口。
- 跳过后再想查看引导：仅当仍无真实数据时可从今天页空态「重新查看引导」进入；有真实数据后不提供。
- 示例删除失败：示例仍在，提示重试；真实数据不受影响。
- 从示例返回真实工作区：真实数据仍为空，引导状态不变。

## 4. 界面与交互

### 4.1 首次引导（A-01）

- 位置：`/today` 内的独立引导画面，跳过或继续记录后恢复今天清单。
- 进度：1/3、2/3、3/3；已完成步骤打勾，可回看不可重复执行。
- 每步都有「跳过」；跳过作用于整个引导，不删除已创建的数据。
- 步骤完成由真实动作触发，不提供「下一步」假按钮。

| 步骤 | 内容 | 完成条件 |
| --- | --- | --- |
| 1/3 建一条分支 | 名称 + 预设色相；可跳过，直接使用根分支 | 成功创建一条分支 |
| 2/3 记第一笔 | 标题 + 可选日期；默认落到第 1 步的分支，未建则根分支 | 成功创建一条待办 |
| 3/3 完成它 | 勾选完成；展示回执与「去历程看看」 | 成功生成首条提交 |

- 第 3 步完成后，今天页切换到独立的完成画面，用户选择「去历程看看」或「继续记录」后引导结束。

### 4.2 首次待办（O06-first-task）

- 单字段优先：标题；日期可选；分支默认第 1 步创建的分支或根分支。
- 保存后立即回到今天页，不进入详情、不弹二次确认。

### 4.3 首条提交回执（O06-first-commit）

- 显示任务名、所属分支、时间「已提交 16:42」。
- 提供「去历程看看」（进入 M06 并定位该提交）与「继续记录」。
- 不自动跳转，不自动关闭，由用户选择。

### 4.4 示例树（O06-sample-tree）

- 顶部横幅：「这是示例，不会进入你的数据」+「删除示例」。
- 内容：3–4 条分支（覆盖 L1/L2/L3）、8–12 条提交、2 个里程碑；只读。
- 分支默认展开，提交默认显示五条，可展开为完整列表。页底可返回今天并保留示例。
- 可浏览分支树、时间树节点与里程碑详情；不提供完成待办、编辑、收尾、删除分支等写操作。
- 示例中的提交、里程碑、徽章不计入真实统计、搜索、导出、备份与额度。
- 删除示例：一次确认后清除示例命名空间，返回真实空工作区；不影响真实数据（此时通常为空）。

### 4.5 五种状态

| 状态 | 表现 |
| --- | --- |
| 空 | 无真实数据：显示引导或「重新查看引导」；示例为空时不适用 |
| 加载 | 示例载入时显示进度；打开示例页后，读数据期间显示骨架 |
| 错误 | 引导动作失败保留输入；示例载入或删除失败说明 + 重试 |
| 只读 | 示例树整体只读，所有写操作不可用并说明原因 |
| 无权限或未登录 | 不适用；MVP 无账号，引导不得要求登录 |

### 4.6 移动端

- 390 px：引导画面步骤纵向排列，表单单列，主操作具有独立触控区。
- 示例树为全屏页面，横幅固定可见；删除入口在横幅内，不依赖滚动到底部。

## 5. 数据与规则

| 数据 | 位置 | 用途 |
| --- | --- | --- |
| 引导状态 | 本机 UI 状态（`localStorage`） | 是否已开始、已完成步骤、是否跳过 |
| 示例数据 | 独立本机命名空间 | 分支/待办/提交/里程碑演示，不写真实业务表 |
| 真实业务表 | `branches`、`tasks`、`commits`、`milestones`、`badges`、`settings` | 只在用户执行真实动作时写入 |

规则：

- 引导触发条件：根分支之外无分支、无待办、无提交、无里程碑；清空本机数据后重新满足。
- 引导完成或跳过写入本机 UI 状态；不写 `settings`，不改表结构。
- 示例隔离：示例使用独立命名空间，不进入真实树、四计数、徽章、搜索、导出、备份与周/月/年统计；不触发任何徽章。
- 示例只读：不允许在示例中完成待办或写入；示例删除为物理清除，不写 `events`。
- 示例入口只在无真实数据时出现；真实数据产生后入口隐藏，示例命名空间不参与任何真实功能。
- 清空本机数据时同时清除引导状态与示例命名空间。
- 引导中创建的数据是真实数据，正常计入统计、额度与徽章；跳过不删除已创建内容。

## 6. 验收标准

1. 清空本机数据后进入 `/today`，直接出现「1/3 建一条分支」引导画面。
2. 创建第一条分支后步骤变为 2/3；创建第一条待办后变为 3/3；完成待办后出现首条提交回执与「去历程看看」。
3. 点「去历程看看」进入历程并定位该提交；返回今天页，引导已结束。
4. 点「跳过」后引导收起，今天页显示普通空态；刷新或重新进入不再自动展开。
5. 引导中离开再回来，已完成步骤保留，从下一步继续；未完成步骤的输入在本次离开后不保留时需明确提示（当前不保留）。
6. 跳过引导后，四个概念的注解仍可在对应页面查看；无真实数据时可从空态「重新查看引导」恢复。
7. 从引导载入示例树，内容包含 3–4 条分支、8–12 条提交、2 个里程碑，顶部横幅可见，所有写操作不可用。
8. 示例中的提交与里程碑不进入真实分支树、四计数、徽章、搜索与导出文件。
9. 点「删除示例」并确认后，示例数据清除，回到真实空工作区；真实数据不受影响。
10. 已存在真实数据时，今天页不出现引导卡，也不出现示例入口。
11. 清空本机数据后，引导与示例状态一并重置，重新从 1/3 开始。
12. 示例载入失败时显示原因与重试，不出现半载入的树。
13. 390 px 下引导卡步骤纵向可读，按钮不挤压；示例横幅固定可见。

## 7. 依赖与阶段、未决问题

- 阶段：MVP。
- 依赖：M02（建分支）、M03（记待办与完成）、M05（首条提交详情）、M06（历程直达）。
- 后续消费：V1 的回填过去（V1-07）可复用引导中的日期输入；V2-01 登录引导独立。
- 冲突与处理：
  - A-02 要求「与真实数据隔离」，但 `branches` 等表没有示例标记字段；本 PRD 用独立命名空间实现，不改表结构。
  - A-01 使用 `/today` 内的独立引导画面，步骤和完成态共享路由。
- 未决问题：
  - 示例树的具体内容（分支名、提交文案、里程碑）未定稿。
  - 真实数据产生后示例数据长期保留但不展示入口，是否需要自动清理，待产品确认。
  - 离开引导时未完成步骤的输入是否要草稿保留，当前不保留。

### 8.2 必须自动化的用例

| 测试文件 | 被测对象 | 断言要点 | 边界 |

**最值钱的回归用例**：`sample-namespace.test.ts` 里的「载入只写示例命名空间、真实业务表行数不变」守的是示例记录被直接写进 `branches` / `commits` 这一类 bug——示例分支会出现在真实树、计入四计数并进入导出文件，删除示例时还可能连真实数据一起清掉。手工验收时示例树看起来完全正常，只有在导出文件或年轮统计里才对得上账。其次是 `onboarding-state.test.ts` 里的「离开再进入从下一步继续」：守的是把进度只存在组件内存里、刷新就回 1/3 的实现，这条要反复进出页面才会暴露，容易被当成浏览器刷新问题而不是代码问题。

说明：引导状态、示例规格与命名空间隔离都可以脱离 React 断言，已全部进单测；引导卡位置、键盘与示例横幅的固定可见留在 8.3。

### 8.3 只能人工验收

1. **引导画面**：清空本机数据后，分别以 1440 和 390 px 宽度进入 `/today`。确认进度为 1/3，页面无横向溢出，跳过后显示今天清单。
2. **390 步骤纵向与键盘**：前置 处于 2/3；操作 在 390 px 打开输入框并弹起键盘；判定 三步纵向排列、按钮不换行挤压、保存按钮可见且可点。为什么不能进单测：真实键盘与响应式布局无法在单测中复现。
3. **示例树横幅固定与只读**：前置 已载入示例；操作 在 O06-sample-tree 滚动到底；判定 横幅始终可见、「删除示例」不依赖悬停、完成与编辑等写操作不可用并给出原因。为什么不能进单测：滚动粘性与悬停行为属于真实浏览器。
4. **去历程后返回引导已结束**：前置 处于 3/3 并已完成；操作 点「去历程看看」再返回今天页；判定 引导不再出现、真实数据仍在。为什么不能进单测：跨路由跳转与页面生命周期无法用纯函数覆盖。
5. **载入或删除示例失败**：前置 无真实数据；操作 在 DevTools 中使 IndexedDB 写入失败后载入示例，再恢复后重试；判定 显示原因 + 重试、不出现半载入的树、真实数据不受影响。为什么不能进单测：需真实浏览器制造写入失败；回滚本身由 8.2 覆盖。
