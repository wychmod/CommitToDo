# M10 数据导出与从文件恢复（MVP）

## 1. 背景与目标

MVP 没有账号和云端，用户必须能自己掌握数据：随时导出一份完整 JSON，换机或误操作后能整体恢复。导出不是「备份功能」的半成品，而是本阶段唯一的数据出口；导入是整体替换，不做合并。

目标：用户能导出一份可读、可再次导入的完整数据文件；能在导入前看到文件摘要、先留存当前数据副本，再整体替换；失败时不破坏现有数据。

## 2. 范围与非目标

**范围**

- J-03 导出：JSON 含 `schemaVersion`、导出时间、全部业务数据与设置；浏览器下载。
- J-04 从文件恢复：校验 → 摘要 → 必须先导出当前数据副本 → 整体替换 → 重算四计数 → 重载。
- P08 数据与备份页（MVP 部分）、S08-restore-file、O05-clear-local。
- 清空本机数据（不可恢复，两步确认）。

**非目标**

- 不做每日快照、独立备份库、按快照恢复、异地备份（V1-06）。
- 不做云端上传、账号绑定、加密导出、增量导入、合并导入。
- 不做旧格式迁移：只接受当前 `schemaVersion`。
- 不导出示例树数据；不把示例数据写入真实导出文件。

## 3. 用户故事与主流程

**故事 1｜换机前导出**

`/data` → 点「导出 JSON」→ 浏览器下载 `committo-export-2026-11-21.json` → 页面显示「已导出：N 条分支 / M 条待办 / K 条提交」与导出时间。

**故事 2｜在新设备恢复**

`/data` → 「从文件恢复」→ 选择 JSON → 页面显示文件摘要（导出时间、`schemaVersion`、分支/待办/提交/里程碑/徽章数量）→ 若本机已有数据，必须先点「先导出当前数据」并完成下载 → 「替换并恢复」→ 确认 → 数据整体替换、四计数重算、页面重载。

**故事 3｜文件不对，停止**

选择一个非 JSON 或字段缺失的文件 → 显示具体原因（不是 JSON / 缺少 `schemaVersion` / 版本不匹配 / 数据结构缺失）→ 现有数据不变，可重新选择。

**故事 4｜清空重来**

`/data` → 「清空本机数据」→ 确认框说明不可恢复，并提供「先导出」→ 再次确认 → 清空全部本机数据与设置 → 回到首次使用状态。

**异常与边界**

- 本机无数据：导出按钮不可用并说明「还没有可导出的数据」；导入仍可用。
- 导入文件版本高于或低于当前 `schemaVersion`：拒绝，提示「请使用与当前版本一致的文件」，不做迁移。
- 导入中途失败：回滚到导入前状态，原数据完整保留。
- 导入完成后：页面重载，主题等设置以导入文件为准；当前会话的滚动与筛选状态清除。
- 导出时浏览器下载被拦截：提示允许下载并重试；不显示「已导出」。
- 导入文件含已撤销提交：按原样保留 `voidedAt`，不重新计入统计（R3）。
- 清空时正在编辑：先结束编辑，再执行清空；清空失败时数据保留。
- 示例树数据：不进入导出；导入不会带入示例命名空间；清空时一并清除。
- 文件名重复：浏览器自动加序号，不覆盖旧文件。

## 4. 界面与交互

### 4.1 P08 数据与备份（MVP）

| 区块 | 内容 |
| --- | --- |
| 数据概览 | 分支 / 待办 / 提交 / 里程碑 / 徽章数量；最近导出时间（本机记录） |
| 导出 | 「导出 JSON」；无数据时禁用并说明 |
| 从文件恢复 | 「选择文件」→ S08-restore-file |
| 危险区 | 「清空本机数据」→ O05 |

- 不显示快照列表、快照恢复、异地备份；这些在 V1-06。
- 页头返回「我的」，导航选中「我的」。

### 4.2 从文件恢复（S08-restore-file）

1. 选择文件后先本地解析，不写入。
2. 摘要区显示：文件名、导出时间、`schemaVersion`、各实体数量。
3. 若本机已有数据：显示强制步骤「先导出当前数据」，导出完成后「替换并恢复」才可用。
4. 确认文案写明：将整体替换当前全部数据、不合并、不保留当前数据（除刚导出的文件）。
5. 执行时显示进度态；成功后重载到 `/today`；失败留在本页并说明原因。

### 4.3 清空本机数据（O05）

- 第一步：说明将删除全部分支、待办、提交、里程碑、徽章与设置，不可恢复；提供「先导出」。
- 第二步：按钮文案「清空并重新开始」，点击后执行。
- 成功后清除本机数据、示例命名空间、偏好与最近视图，进入 M12 首次使用状态。
- 失败时不清空，提示重试。

### 4.4 五种状态

| 状态 | 表现 |
| --- | --- |
| 空 | 无数据：概览显示 0，导出禁用；导入与清空可用 |
| 加载 | 概览骨架；导入解析与写入显示进度，不阻塞关闭页面提示 |
| 错误 | 解析失败、版本不符、写入失败均就地说明；现有数据不变 |
| 只读 | 不适用；本页操作都是本机写入 |
| 无权限或未登录 | 不适用；MVP 无账号，导出与导入不要求登录 |

### 4.5 移动端

- 390 px：概览单列，三个区块纵向排列；文件选择调用系统选择器；确认框为全屏步骤页，可返回。
- 危险区与普通操作保持间距，避免误触。

## 5. 数据与规则

| 数据 | 内容 |
| --- | --- |
| 导出文件 | `schemaVersion`、`exportedAt`、`appVersion`、`branches`、`tasks`、`commits`、`milestones`、`badges`、`settings`、`events` |
| 导入摘要 | 各实体数量、导出时间、`schemaVersion`、文件名 |
| 本机记录 | 最近导出时间（仅用于 P08 展示） |
| 导入前副本 | 当前数据的完整 JSON 文件，由用户先执行导出得到 |

规则：

- R7 四计数：导入或清空后的恢复流程结束前，按实际待办与有效提交全量重算 `branches` 的四个计数，不信任文件中的旧值。
- R3：导入保留 `voidedAt`；已撤销提交不进入统计。
- `schemaVersion` 必须与当前应用一致；不做旧版本迁移，不猜测缺失字段。
- 导入为整体替换：先清空当前业务数据，再写入文件数据；单事务或可回滚，任一步失败恢复原数据。
- 导出不含示例命名空间；不含任何设备标识、登录凭证或云端信息。
- 文件为明文 JSON，不含加密；界面必须提示「文件包含全部数据，请自行妥善保管」。
- 清空范围：业务表、设置、示例命名空间、本机 UI 状态；不清除浏览器下载目录中的已导出文件。

## 6. 验收标准

1. 有数据时点「导出 JSON」，下载文件名含日期，文件包含 `schemaVersion`、`exportedAt` 与分支/待办/提交/里程碑/徽章/设置/事件数据。
2. 导出后页面显示导出时间与各实体数量，数量与数据概览一致。
3. 无数据时导出按钮不可用并说明原因；导入与清空仍可用。
4. 选择合法文件后，摘要显示文件名、导出时间、`schemaVersion` 与各实体数量；本机有数据时「替换并恢复」在完成当前数据导出前不可用。
5. 完成「先导出当前数据」后，「替换并恢复」可用；确认后数据整体替换、页面重载，四计数按导入内容重算。
6. 导出 → 清空 → 导入同一文件，分支、待办、提交、里程碑、徽章与设置全部恢复；已撤销提交仍为已撤销且不计入统计。
7. 选择非 JSON 文件被拒绝，显示「不是有效的 JSON」，现有数据不变。
8. 选择缺少 `schemaVersion` 或版本不一致的文件被拒绝，提示版本要求，现有数据不变。
9. 模拟导入写入中途失败：回滚到导入前状态，原数据完整，页面提示失败。
10. 清空本机数据需两步确认；成功后业务数据、设置与示例数据全部清除，进入首次使用状态。
11. 导出文件不包含示例树数据；导入不会带入示例命名空间。
12. 390 px 下概览与三个区块单列，文件选择与确认流程可用。

## 7. 依赖与阶段、未决问题

- 阶段：MVP。
- 依赖：M01（设置与本机状态）、各业务表结构。
- 后续消费：V1-06 在 P08 增加快照、按快照恢复、异地备份；V2-02 增加同步。
- 冲突与处理：
  - P08 画稿同时出现快照与恢复，MVP 只做导出/导入；快照与异地备份归 V1-06（R17）。
  - 旧数据不迁移：只接受当前 `schemaVersion`。
- 未决问题：
  - 「导入前副本」当前采用「必须先完成一次导出」的硬门槛，是否需要改为系统自动留存一份内部副本，待技术线确认存储方案。
  - 导入文件大小上限与超时提示未定义。
  - 清空本机数据是否保留「最近导出时间」本机记录，当前一并清除。

| `web/src/data/restore-transaction.test.ts` | 整体替换事务（使用 `fake-indexeddb`） | 清空与写入在同一事务内提交；写入中途抛错后每张表与导入前逐行相等；成功后 `branches` 四个计数等于重算值；清空阶段不残留示例命名空间 | 文件各表为空数组；写入第 3 张表时抛错；同一文件连续导入两次结果相同；本机原本有数据与本机为空各一例 |

**最值钱的回归用例**：`restore-transaction.test.ts` 里的「写入中途失败必须回滚到导入前状态」守的是「先清空再写入」被拆成两个事务这一类 bug——写入失败后用户现有数据已被清空，页面仍停在 S08 显示「导入失败」，原数据却永久没了。手工点页面时几乎不会制造写入失败，即使失败，用户看到的也只是「导入失败」，很难意识到数据已丢。其次是 `counters.test.ts` 新增块里的「四计数按导入内容重算、不信任文件旧值」：守的是直接采用文件里 `branches` 旧计数的实现，导入手工改过或旧文件后今天页额度、分支进度全错，而页面不报任何异常。

说明：Dexie 事务与 `useLiveQuery` 刷新本身按 AGENTS.md 不属纯逻辑，但导入替换的一致性已同意用 `fake-indexeddb` 纳入 `npm test`；文件选择、下载与重载留在 8.3。

### 8.3 只能人工验收

1. **真实文件选择与下载**：前置 有真实数据；操作 1440 与 390 各点一次「导出 JSON」，再用系统选择器选一个合法文件；判定 下载文件可被再次选中并解析出相同的导出时间与实体数量。为什么不能进单测：依赖浏览器下载与系统文件选择器。
2. **下载被拦截**：前置 有真实数据；操作 在浏览器中禁止该站点下载后点导出；判定 提示允许下载并重试，不显示「已导出」。为什么不能进单测：由浏览器权限决定，代码侧无法断言。
3. **导入进度与重载结果**：前置 本机有数据，另备一份主题与设置不同的导出文件；操作 执行替换并恢复；判定 执行中有进度态、成功后重载到 `/today`、主题以文件为准、原滚动与筛选状态清除。为什么不能进单测：页面重载与全局 UI 状态应用属于浏览器行为。
4. **清空两步确认的焦点流转**：前置 有数据；操作 390 px 打开 O05，走完两步；判定 第一步说明与「先导出」可见，第二步按钮为「清空并重新开始」，结束后回到首次使用状态，键盘弹起时按钮可见。为什么不能进单测：多步确认、焦点与键盘是真实浏览器交互。
5. **写入失败的可见提示**：前置 有数据；操作 在 DevTools 中使 IndexedDB 写入失败后执行替换；判定 页面留在 S08、给出原因、原数据仍可浏览。为什么不能进单测：需真实浏览器制造写入失败；回滚本身由 8.2 覆盖。
