# V2-01 账号与登录（V2）

## 1. 背景与目标

MVP 与 V1 都是纯本机产品，没有「我是谁」。V2 引入身份层，只解决一件事：把本机数据归属到一个账号，为后续多设备同步提供主体。登录是可选的，不登录也能完整使用本机工作区。

本 PRD 交付 L-02：P09 登录、P10 注册、P11 找回密码、S11 两个找回步骤视图、O07 站内登录提示，以及 `/settings#account` 的账号分区。

目标：用户在需要账号的功能旁看到登录入口，登录后回到原来的操作位置；不登录时任何本机功能都不被拦截；登录只做归属，不在这一层合并数据。

## 2. 范围与非目标

**范围**

- 可选登录：登录、注册、退出登录。
- 找回密码三步：填写邮箱、检查邮箱、设置新密码。
- 登录成功后把本机数据归属到 `principalId`，并返回有效的应用内 `next`。
- `/settings#account` 账号分区与 O07 站内登录提示。
- 未登录访问账号相关分区时的拦截与返回路径。

**非目标**

- 不做多设备同步、离线补传、冲突处理（V2-02）。
- 不做账号数据与本机数据的合并、覆盖或选择；合并交给同步层。
- 不做第三方登录、手机号登录、免密登录；渠道以 V2 技术决策为准。
- 不做账号注销、换绑邮箱、修改密码、登录设备管理（设备列表归 V2-02）。
- 不做端到端加密；密码不以明文保存或传输。
- 不改表结构；`users` 表随本 PRD 启用，其他表不改字段。

## 3. 用户故事与主流程

**故事 1｜一直不登录**

用户从未登录，打开 `/today`、建分支、完成待办、导出与备份全部可用；界面不出现登录弹窗或强制跳转。

**故事 2｜从同步入口登录**

`/settings#sync` 显示 O07 行内提示「登录后可多设备同步」→ 点「登录」→ 进入 `/auth/login?next=/settings%23sync` → 输入邮箱与密码 → 成功后回到 `/settings#sync`。

**故事 3｜注册新账号**

登录页点「创建账号」→ `/auth/signup?next=...` → 输入邮箱、密码、确认密码 → 注册成功 → 回到 `next`；本机数据归属到新账号。

**故事 4｜忘记密码**

登录页点「找回密码」→ `/auth/recover` → 填写邮箱 → 进入「已发送」步骤 → 邮件中的链接打开设置新密码步骤 → 设置成功后回登录页，可用新密码登录。

**故事 5｜退出登录**

`/settings#account` 点「退出登录」→ 一次确认，说明「本机数据保留，同步停止」→ 退出后回到本机工作区 `/today`；数据仍在本机可继续使用。

**异常与边界**

- 邮箱格式不合法：就地提示，不发请求，输入保留。前端只做粗校验——`@` 存在且两侧非空、域名部分含 `.`；`a@b` 这类粗校验通过但实际无效的地址交服务端判定。
- 密码错误或账号不存在：统一提示「邮箱或密码不正确」，不区分两者，避免暴露账号是否存在。
- 网络失败或服务不可用：提示可重试，不清空输入、不跳转。
- 已登录时访问 `/auth/login`、`/auth/signup`：直接回到 `/today`，不显示登录表单。
- `next` 缺失、为空、不是站内路径（含 `//`、`http://`、`javascript:`）：登录成功后落到 `/today`。
- `next` 指向 `/auth/*`：落到 `/today`，避免登录循环。
- 本机已有数据、账号也已有数据：登录只把本机数据归属到账号，不在本层合并；界面提示「登录后由同步接管，合并规则以同步说明为准」。
- 找回密码的邮箱不存在：仍显示「已发送」，不暴露账号是否存在。
- 找回链接过期或已使用：设置新密码步骤说明失效原因，并提供重新发送入口。
- 未登录访问 `/settings#account` 或 `/settings#sync`：显示 O07 行内提示与登录入口，不整页跳转；页面其他设置仍可改。
- 退出登录时正在同步：先停止同步并保留本地数据，不删除任何记录。
- 找回密码过程中关闭页面再打开：已发送步骤不保留表单内容，需重新填写邮箱。

## 4. 界面与交互

对应页面：**P09**（`/auth/login`）、**P10**（`/auth/signup`）、**P11**（`/auth/recover`）；视图：**S11-recover-sent**、**S11-recover-reset**、**O07-sync-entry**；分区：`/settings#account`。

视觉对照采用 2026 年 11 月 22 日确认的双栏明暗稿与账号设置三种状态。桌面左侧是表单，右侧是同一静态时间树与提交回执。认证路由或找回步骤切换时更新左侧，顶栏品牌和「打开本机工作区」保持可用。[最新 Web 认证与账号设置画稿](../web-auth/DESIGN.md)

### 4.1 登录（P09）

- 独立认证壳，顶栏左侧显示品牌，右侧提供「打开本机工作区」。[登录画稿](../web-auth/DESIGN.md#登录)
- 字段：邮箱、密码；密码提供显示 / 隐藏切换。
- 操作：登录、前往注册、找回密码、打开本机工作区。
- 提交中按钮禁用并显示加载；失败就地显示统一错误，不跳转。
- 成功后按 `next` 规则返回；返回后恢复原页面滚动与分区定位（如 `#sync`）。

### 4.2 注册（P10）

- 沿用登录布局。表单显示邮箱、密码和确认密码，主按钮为「创建账号」。[注册画稿](../web-auth/DESIGN.md#创建账号)
- 两次密码不一致时就地提示，不发请求。
- 成功后直接登录并归属本机数据，按 `next` 返回。
- 提供「返回登录」与「打开本机工作区」。

### 4.3 找回密码（P11）

- 同一路由的三步复用顶栏与右侧图形，左侧步骤指示随流程更新。
  1. 填写邮箱，说明「我们会向该邮箱发送重置链接」。提交后进入已发送步骤。[找回画稿](../web-auth/DESIGN.md#找回密码)
  2. 已发送（S11-recover-sent），对任意格式有效的邮箱显示相同的查收说明与垃圾邮件提示，同时显示用户填写的地址，提供「重新发送」「修改邮箱」与「返回登录」。重新发送有冷却时间。[检查邮箱画稿](../web-auth/DESIGN.md#检查邮箱)
  3. 设置新密码（S11-recover-reset），由邮件链接进入。输入新密码与确认密码，使用「保存新密码」。成功后提示已重置并回登录页。[设置新密码画稿](../web-auth/DESIGN.md#设置新密码)
- 链接失效、已使用或过期：在第三步说明原因，提供「重新发送」。
- 三步都不显示账号是否存在。

### 4.4 账号分区与站内提示（`/settings#account`、O07）

- `/settings#account` 未登录时显示 O07 行内提示与「登录」「注册」入口。其余设置分区仍可使用。
- 已登录时显示邮箱、登录状态与退出登录。退出前用对话框说明「本机数据保留，同步停止」，提供取消和确认。同步状态与设备入口由 V2-02 提供。[三种账号设置状态](../web-auth/DESIGN.md#账号设置)
- O07 出现在需要账号的入口旁，形态为行内提示，不是弹窗；点击携带当前路径作为 `next`。
- 登录入口不放在今天页、分支树、历程等核心操作路径上，不打断本机使用。

### 4.5 五种状态

| 状态 | 表现 |
| --- | --- |
| 空 | 不适用；账号分区未登录时显示 O07 提示，不显示空白表单 |
| 加载 | 登录、注册、找回提交时按钮显示加载并禁用；页面不整屏遮挡 |
| 错误 | 字段错误就地提示；网络失败显示可重试；不暴露账号是否存在 |
| 只读 | 已登录账号分区显示邮箱为只读；本机数据与设置不因登录变为只读 |
| 无权限或未登录 | 账号与同步分区显示 O07 与登录入口；核心本机功能不拦截，不要求登录 |

### 4.6 移动端

- 390 px 下认证三页呈现单列表单。键盘弹起时主按钮可见，顶栏「打开本机工作区」始终可点。
- 找回密码三步为全屏步骤页，可返回上一步；邮件链接在系统浏览器打开时保持单列布局。
- 账号分区与 O07 行内提示不遮挡底部导航。

## 5. 数据与规则

| 表 | 字段 | 用途 |
| --- | --- | --- |
| `users` | `_id`、`email`、`passwordHash`、`createdAt`、`updatedAt` | 账号主体与登录校验 |
| 业务表 | `ownerId`（身份层称 `principalId`） | 登录后把本机数据归属到账号 |
| 本机状态 | 会话凭证、`next`、最近登录邮箱 | 登录态与返回路径；不写入业务表 |

规则：

- 登录可选：未登录时所有 MVP/V1 功能可用，认证不进入核心路径。
- 身份层只做归属：登录成功后把本机真实数据的归属标记为当前账号；不删除、不覆盖、不合并已有账号数据。
- 合并边界：本机与账号都有数据时，本层不做取舍；由 V2-02 的同步与冲突规则处理。
- `principalId` 是身份层的账号归属键，写入业务表时对应 0.12 的 `ownerId`；`users._id` 是账号主键；不在本层新增业务字段。
- 密码只保存哈希，不保存明文；日志与错误信息不含密码。
- 错误统一：登录失败不区分「账号不存在」与「密码错误」；找回密码不显示邮箱是否注册。
- 邮箱校验：前端只做粗校验（`@` 存在且两侧非空、域名含 `.`），真实有效性由服务端判定；前端不引入正则库或格式白名单。
- `next` 白名单：只接受以单个 `/` 开头的站内路径，拒绝 `//`、协议头、`javascript:`、`/auth/*`；不合法时落到 `/today`。
- 会话失效：需要账号的请求返回未登录时，显示 O07 行内提示与登录入口，携带当前路径为 `next`；不把用户踢出本机工作区。
- 退出登录：清除本机会话，保留本机业务数据与设置；停止同步；回到 `/today`。
- 找回密码：重置链接一次性、有有效期；具体时长由后端配置，PRD 不固定数值。
- 本机数据归属不改变四计数、统计、徽章与排序。

## 6. 验收标准

1. 未登录状态打开 `/today`、`/branches`、`/history`、`/data`，全部可用，不出现登录弹窗或强制跳转。
2. 未登录访问 `/settings#account` 与 `/settings#sync`，显示 O07 行内提示与登录入口；同页其他设置仍可修改。
3. 从 `/settings#sync` 点登录，登录页地址携带 `next=%2Fsettings%23sync`；登录成功后回到 `/settings` 并定位到同步分区。
4. 登录成功时 `next` 缺失或为非法值（`//evil`、`http://...`、`javascript:...`、`/auth/login`），最终落到 `/today`。
5. 已登录访问 `/auth/login` 或 `/auth/signup`，直接回到 `/today`，不显示表单。
6. 输入非法邮箱（缺 `@`、`@` 两侧为空、域名无 `.`）时，登录与注册都不发请求，就地提示，输入保留；`a@b` 通过前端粗校验，由服务端判定是否真实可用。
7. 输入错误密码与不存在的邮箱，两次提示文案完全一致，均为「邮箱或密码不正确」。
8. 注册时两次密码不一致，就地提示且不发请求；一致时注册成功并按 `next` 返回。
9. 找回密码填写任意邮箱后都进入「已发送」步骤，不显示该邮箱是否存在；重新发送有冷却。
10. 通过有效链接进入设置新密码步骤，设置成功后可用新密码登录；过期或已使用的链接显示失效原因与重新发送入口。
11. 登录成功后本机真实数据的归属标记为当前 `principalId`；数据条数、四计数、统计与徽章不变，也没有发生合并或删除。
12. 本机与账号都有数据时登录，界面提示「由同步接管」，本层不出现选择保留哪一份的弹窗。
13. 退出登录后回到 `/today`，本机数据仍可读写，同步停止，会话清除；再次打开账号分区显示 O07。
14. 网络失败时登录、注册、找回均显示可重试，输入不清空、页面不跳转。
15. 390 px 下认证三页单列可操作，键盘弹起时主按钮可见，「打开本机工作区」始终可用。

## 7. 依赖与阶段、未决问题

- 阶段：V2。
- 依赖：全部 MVP/V1 页面可用；CloudBase 身份能力；V2-02 消费本 PRD 的 `principalId` 与登录态。
- 后续消费：V2-02 同步与设备管理、V2-04 第二端读取同一账号数据。
- 冲突与处理：
  - `UI-PAGES` 写明「邮箱与密码流程是 V2 画稿的示例渠道，实际渠道按 V2 技术决策落实」：本 PRD 不固定渠道，验收按落地渠道执行；当前流程以邮箱 + 密码描述。
  - `FRAMEWORK` L-02 明确「与已有账号数据的合并交给同步层」：本 PRD 只做归属，不设计合并、覆盖与冲突处理。
  - `P07` 画稿的账号分区在 V2 才出现：MVP/V1 的 P07 不显示该分区，登录入口只在 V2 出现。
- 未决问题：
  - 实际登录渠道（手机号 / 微信 / 邮箱 OTP）与找回方式尚未定案；**待定**，本 PRD 只固定页面关系与 `next` 规则。邮箱校验已定为前端粗校验、真实校验交服务端。
  - 密码最小长度、重置链接有效期、登录失败限流策略未定，需后端给出。
  - 账号注销、换绑邮箱、修改密码、会话有效期与多端同时登录策略未在 L-02 定义。
  - 退出登录后本机数据是否保留 `principalId` 归属（当前按「保留数据、停止同步」处理），需与同步层确认。

最值钱的回归用例有两个。第一个是 `auth-next.test.ts` 的「`//evil`、`http://`、`javascript:` 与 `/auth/*` 一律回退 `/today`」，它守的是登录成功后的开放重定向：攻击者构造 `/auth/login?next=//evil.example` 就能把用户带去站外，或形成 `/auth/login` 自循环。手工点页面时通常只看得到一次成功的站内回跳，不会主动输入这些载荷，且浏览器地址栏在跳转完成后只剩目标页，事后无法判断中间经过哪里。

第二个是 `auth-form.test.ts` 的「密码错误与账号不存在返回同一错误码」，它守的是错误文案差异泄露账号是否注册。人工验收要分别输入一个存在的邮箱和一个不存在的邮箱，再逐字对照两段提示；只要后端漏出一个分支、前端少映射一种错误，差异只在并排比对时才显形，单独走一遍流程发现不了。
