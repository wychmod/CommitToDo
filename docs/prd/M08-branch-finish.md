# M08 收尾与删除空分支（MVP）

## 1. 背景与目标

一条线走完时要能体面地结束：提交留在历程里，未完成的待办交回父线，子分支标记为「已合并」；而从未真正开始过的空分支要能干净删除，不留垃圾节点。这两个动作都不可轻易撤销，必须在写入前把后果讲清楚。

目标：用户能把子分支收尾到父分支，并选择「归档」或「留在树上」；能把整棵子树为空的子分支物理删除；两种操作都有明确的两段式确认，失败时不产生半完成状态。

## 2. 范围与非目标

**范围**

- D-04 收尾：只能合并到自己的父分支；父分支必须可接收；收尾后子分支保留为「已合并」；未完成待办随合并移入父分支；提交并入父分支历程并保留原始来源。
- 收尾后二选一：归档（不进默认树、不计活跃额度、只读）或留在默认树（只读、仍计活跃额度）。
- D-05 删除空分支：仅当整棵子树没有待办、提交、里程碑与子分支时物理删除；不可恢复；不写事件、不产生徽章。
- B06 收尾确认、B07 收尾后形态、B10 删除空分支确认；P03 的「已合并」页头。

**非目标**

- 不做放下、重新开始、取消归档（V1-01）；MVP 收尾归档后没有界面恢复入口。
- 不做跨层合并、合并到非父分支、批量收尾、批量删除。
- 不做删除有内容的子树；不做回收站。
- 不改表结构。

## 3. 用户故事与主流程

**故事 1｜把完成的目标收尾**

进入「工作 / 主业 / 小程序 1.0」详情 → 更多菜单点「收尾」→ 确认框列出：将合并到「主业」、N 条提交并入、M 条未完成待办移到父分支、子分支将变为只读 → 继续 → 选择「归档」或「留在树上」→ 最终确认 → 子分支状态变为已合并，按选择归档或留在树中；父分支详情出现其提交并标注来源。

**故事 2｜收尾但暂时不想让它消失**

收尾第二步选「留在树上」→ 分支仍在默认树、只读、显示「已合并到主业」→ 页脚活跃额度不变（该分支仍计入 200）→ 不能再接收待办。

**故事 3｜收尾并归档**

收尾第二步选「归档」→ 分支从默认树消失、不计活跃额度、只读 → 可在历程中查看其历史 → 父分支历程仍显示其提交与里程碑。

**故事 4｜删掉一个建错的空分支**

在一条没有任何待办、提交、里程碑和子分支的分支上点「删除」→ 确认框写明「删除后不可恢复，不保留历史」→ 确认 → 分支物理删除，回到父分支详情；默认树与额度立即更新，历程中没有它的痕迹。

**异常与边界**

- 根分支不能收尾、不能删除；菜单不提供对应动作。
- 父分支已放下、已归档或已合并：不能接收，收尾入口不可用并写明原因。
- 父分支达到 L2/L3 直接子分支上限：不影响收尾（子分支已在父下，不新增），但收尾后不能借此新增子分支。
- 收尾过程中写入失败：子分支仍为进行中、待办仍在原分支、提交未移动；提示失败并可重试，不出现部分移动。
- 删除条件不满足：删除项不可用，列出原因（有待办 / 有提交 / 有里程碑 / 有子分支），不显示确认框。
- 删除写入失败：分支仍存在，提示重试。
- 收尾后撤销：MVP 不提供；确认框必须写明归档后本版本暂无界面恢复入口，留在树上也不可改回进行中。
- 已合并分支再次收尾：不可用。

## 4. 界面与交互

### 4.1 收尾（B06 / B07）

入口：P03 分支详情「更多」首项；P02 树行尾菜单（M02 已预留）。

**第一段确认（B06）** 必须列出：

| 项 | 内容 |
| --- | --- |
| 合并去向 | 父分支名称与路径 |
| 提交 | 将并入父分支的提交数量，注明保留原始来源 |
| 未完成待办 | 将移入父分支的待办数量；已完成与已取消待办留在原分支 |
| 子分支 | 成为「已合并」，只读 |
| 不可撤销 | 「收尾后不能改回进行中」 |

**第二段确认（B07）** 二选一：

| 形态 | 后果 |
| --- | --- |
| 归档 | 不进默认树、不计入 200 活跃额度、只读；可在历程查看；MVP 无界面恢复入口 |
| 留在树上 | 仍在默认树、计入 200 活跃额度、只读；显示「已合并到 X」 |

最终按钮文案必须区分两种形态，不能都用「确定」。

### 4.2 收尾后的呈现（P03）

- 页头状态：`已合并到「主业」· 11 月 13 日`；若已归档，追加「已归档」。
- 待办、提交、子分支、目标全部只读；不显示收尾入口。
- 提交流显示本分支原有的提交；父分支提交流显示并入的提交并标注「来自 主业 / 小程序 1.0」。
- 里程碑留在原分支，父分支历程按 M06 规则显示并入子分支的里程碑并标注来源。

### 4.3 删除空分支（B10）

- 仅当整棵子树同时满足：无待办（含已取消）、无提交、无里程碑、无子分支。
- 确认框列出：分支名称与路径、「删除后不可恢复」「不保留历史」「不会产生徽章」。
- 确认后物理删除；不写 `events`、不写 `deletedAt`。
- 删除后返回父分支详情；若父分支是根，返回 `/branches`。
- 删除根分支不允许。

### 4.4 五种状态

| 状态 | 表现 |
| --- | --- |
| 空 | 不适用；收尾与删除都针对已有分支 |
| 加载 | 打开确认前先算清提交数、待办数、删除条件；计算中按钮不可用 |
| 错误 | 计算失败：不打开确认框，说明原因 + 重试；写入失败：保留原状态并提示 |
| 只读 | 已合并、已归档、已放下分支不提供收尾；空分支删除只对进行中分支开放 |
| 无权限或未登录 | 不适用；MVP 无账号 |

### 4.5 移动端

- 两段式确认改为全屏步骤页，步骤指示「1 后果 → 2 去向 → 3 确认」，可返回上一步。
- 删除确认不依赖长按；按钮点击区域不小于 44 px。

## 5. 数据与规则

| 表 | 字段 | 用途 |
| --- | --- | --- |
| `branches` | `_id`、`parentId`、`path`、`depth`、`status`、`archivedAt`、`finishedAt`、`finishedIntoId`、`taskTotal`、`taskDone`、`commitCount`、`ownLastCommitAt` | 收尾状态、归档、额度、计数 |
| `tasks` | `branchId`、`status`、`completedCommitId` | 未完成待办移入父分支 |
| `commits` | `branchId`、`sourceBranchId`、`voidedAt` | 提交并入父分支 |
| `milestones` | `branchId` | 留在原分支，父历程按来源显示 |
| `events` | `entityType='branch'`、`action='finish'` | 收尾留痕；删除空分支不写 |

规则：

- R12 收尾：只能合并到直接父分支；父分支必须 `active` 且未归档；子分支 `status=merged`、写 `finishedAt` 与 `finishedIntoId`；选择归档时写 `archivedAt`。
- 待办：`open` 待办改 `branchId` 为父分支；`done` 与 `cancelled` 留在原分支；父分支四计数按 R7 重算。
- 提交：`branchId` 改为父分支，`sourceBranchId` 保留原子分支；已撤销提交同样迁移，但不计入有效提交（R3）。
- 里程碑：不改 `branchId`；父分支历程按 `finishedIntoId` 关系纳入已并入子分支的里程碑并标注来源（M06）。
- 额度：归档后不计入 200；留在树上仍计入；L1/L2/L3 直接子分支上限不变。
- R13 删除空分支：整棵子树无待办、无提交、无里程碑、无子分支才可删；物理删除；不可恢复；不写 `events`、不产生徽章；根分支不可删。
- 四计数：收尾后子分支计数保留为历史值；父分支按合并后的待办与有效提交重算 `taskTotal` / `taskDone` / `commitCount` / `ownLastCommitAt`。
- 事务：收尾与删除均在单事务内完成，任一步失败全部回滚。

## 6. 验收标准

1. 对一条含 3 条提交、2 条未完成待办、1 条已完成待办的子分支执行收尾，第一段确认准确显示去向、提交数、未完成待办数与「不可撤销」。
2. 第一段确认后进入第二段，必须二选一才能提交；最终按钮文案能区分「归档」与「留在树上」。
3. 选择「留在树上」后：子分支仍在默认树、状态为已合并、只读、仍计入 200；待办与目标不可编辑。
4. 选择「归档」后：子分支不在默认树、不计入 200、只读；历程仍可查看；父分支提交流出现并入的提交并标注来源。
5. 收尾后 2 条未完成待办出现在父分支，1 条已完成待办仍在原子分支；父分支 `taskTotal` / `taskDone` / `commitCount` 与 R7 口径一致。
6. 父分支的 `ownLastCommitAt` 取合并后有效提交的最大值；已撤销提交迁移后仍不计入。
7. 根分支的「更多」菜单不出现收尾与删除；对已合并分支再次收尾不可用。
8. 父分支为已放下、已归档或已合并时，收尾入口不可用并写明原因。
9. 人为使写入失败：子分支仍为进行中，待办与提交未移动，页面提示可重试。
10. 对含待办、提交、里程碑或子分支的任一条分支，删除项不可用并逐条列出原因。
11. 对整棵子树为空的子分支执行删除，确认后物理删除，默认树、额度与历程同步更新，且不产生 `events` 与徽章。
12. 删除根分支不可用；删除写入失败时分支仍存在。
13. 390 px 下收尾为三步全屏流程，可返回上一步；删除确认可点击完成。

## 7. 依赖与阶段、未决问题

- 阶段：MVP。
- 依赖：M02（分支结构）、M04（详情与入口）、M05（提交来源）、M07（里程碑）。
- 后续消费：M09 周回顾（收尾不计提交）、M11 汇流徽章、V1-01 取消归档与重新开始、V1-02 年轮。
- 冲突与处理：
  - 「归档只读且可逆」在 MVP 只有数据可逆，界面恢复入口属 V1-01；收尾确认必须明确告知。
  - 里程碑是否随合并迁移，文档只写提交；本 PRD 选择「留在原分支、父历程按关系纳入」，不改字段。
- 未决问题：
  - 父分支历程纳入已并入子分支里程碑的查询与来源标注，需技术线确认可行性与性能。
  - 收尾时「留在树上」的分支是否允许 V1 再归档，需与 V1-01 对齐。
  - 删除空分支后是否需要在父分支留一条不可见的时间痕迹，当前按「无痕迹」处理。
