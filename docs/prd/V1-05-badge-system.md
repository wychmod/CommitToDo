# V1-05 徽章体系完整（V1）

## 1. 背景与目标

MVP 只发四枚「第一次」徽章。长期使用后，值得被看见的不是次数，而是结构：一条线走完、一次放下、五条线都有进展、六个月没有断。V1 把徽章补齐到 16 枚，并给它们一个能被浏览、能解释「为什么给你」、能落回树上的家。

本 PRD 交付 H-02 累计 16 枚、H-03 徽章墙、H-04 徽章详情、H-05 树上标记，以及 S06-badge-wall、S06-badge-detail 两个视图。

目标：用户能在「我的」按类别看到 16 枚徽章的获得与差距；点开已获得的徽章能读到授予时的真实数据与落在树上哪天；在历程中看到徽章与那一天绑定。

## 2. 范围与非目标

**范围**

- H-02 结构类 8 枚、时间类 4 枚、里程碑类 4 枚，共 16 枚（含 MVP 已上线 4 枚）。
- H-03 徽章墙：按类别浏览、已获按时间倒序、结构类与时间类对接近达成显示差距。
- H-04 徽章详情：授予原因、授予时快照、落在树上哪一天、定位授予事件。
- H-05 树上标记：历程节点旁的小标记，悬停或点击展开名称，同一天不重复显示。
- 徽章发放的幂等、补查、失败不回滚与导入不重算。

**非目标**

- 不做 5 枚彩蛋徽章（V2-03），不做 21 枚总数。
- 不做排行榜、好友对比、稀有度、积分兑换、徽章分享图。
- 不做自定义徽章、手动授予或撤销徽章。
- 不新增表或字段；只使用 `badges` 现有字段。
- 不改任何既有统计口径与表结构。

## 3. 用户故事与主流程

**故事 1｜第一次放下，拿到断舍离**

对一条分支执行放下并填写原因 → 当天今天页底部出现轻提示「解锁『断舍离』」→ 徽章墙结构类出现该徽章，详情写明「你第一次放下一段路，并写下了原因」。

**故事 2｜看到一个分支收束**

把「工作」下最后一条进行中的子分支收尾 → 判定「工作」的所有子分支都已合并 → 发放「收束」；快照记录父分支名、子分支数量与收尾日期。

**故事 3｜在徽章墙看到差距**

打开「我的 → 徽章墙」→ 结构类顶部显示「7 / 16」→ 未获得的「三碑」显示「还差 2 个里程碑」→ 未获得的「第一年」显示灰点与条件说明。

**故事 4｜点开一枚徽章**

点击「汇流」→ 详情页显示：为什么给你（一句话）、当时数据（「把『小程序 1.0』并回『主业』，47 条提交，2026-11-13」）、「落在 11 月 13 日」→ 点「在历程查看」定位到合并点。

**故事 5｜在历程里看到徽章**

打开 `/history` → 11 月 13 日的节点旁有一个小徽章标记 → 悬停展开「汇流」；同一天若还有「立碑」，标记只出现一次，展开后列出两枚。

**异常与边界**

- 撤销触发事件（如撤销那条提交）：徽章保留，列表与详情标注「原事件已撤销」，跳转不可用。
- 删除空分支：若该分支曾触发「第一道岔」，徽章保留，标注来源不可用；不收回。
- 同一天解锁多枚：今天页轻提示按发放顺序逐条出现；徽章墙上同一天的标记合并为一个。
- 写入徽章失败：不回滚主操作；下次启动或再次进入「我的」时补查；同一枚只发一次。
- 同一动作同时满足多枚条件（如第一次收尾同时让父分支「收束」）：同一事务后逐枚判定，各发一枚，提示按目录顺序排队。
- 已归档分支仍参与徽章判定与历史统计；放下的分支不参与「收束」的「已合并」条件。
- 导入或恢复数据：按文件中的 `badges` 原样保留，不重算、不补发；文件缺少已满足条件的徽章也不补。
- 时钟回拨或跨时区：徽章一旦授予不撤回；「连续」类判定按业务日期 `YYYY-MM-DD` 的本地顺序计算。
- 根分支不参与「第一道岔」「汇流」「收束」的触发，也不作为「五面」「主干」的候选。
- 徽章日期无法确定（导入的历史数据缺少 `snapshot.eventDate`）：树上标记退回使用 `grantedAt` 的本地日期。

## 4. 界面与交互

对应页面：**P06「我的」** 的徽章区；视图：**S06-badge-wall**、**S06-badge-detail**；树上标记落在 **P04 历程**。

### 4.1 徽章目录（16 枚）

`catalogId` 为唯一常量标识，展示名以本表为准；`category` 取 `structure` / `time` / `milestone`。16 枚均只授一次，`periodKey` 统一为 `all`。

| catalogId | 名称 | 类别 | 获得条件 | 快照最小内容 |
| --- | --- | --- | --- | --- |
| `first-commit` | 起笔 | time | 第一条有效提交（R3） | 提交 ID、分支、日期、文案 |
| `first-fork` | 第一道岔 | structure | 第一次创建子分支（`depth ≥ 2`，未删除） | 分支 ID、路径、创建日期 |
| `first-milestone` | 立碑 | milestone | 第一个里程碑（未删除） | 里程碑 ID、标题、日期精度、分支 |
| `first-merge` | 汇流 | structure | 第一次收尾（`status=merged`） | 子分支、父分支、收尾日期、提交数 |
| `all-merged` | 收束 | structure | 某个分支下至少 1 个子分支，且其全部未删除子分支均为 `merged`（含已归档） | 父分支、子分支数、最后收尾日期 |
| `dual-lanes` | 双线并行 | structure | 同一父下两条子分支的活跃区间交集 ≥14 天 | 父分支、两条子分支、交集起止日 |
| `let-go` | 断舍离 | structure | 第一次放下分支（R15，原因必填） | 分支、放下日期、原因 |
| `well-ended` | 有始有终 | structure | 一条 L3 分支从创建到收尾，提交 ≥10 条 | 分支、创建日、收尾日、提交数 |
| `five-faces` | 五面 | structure | 5 条一级分支各自至少有 1 条有效提交 | 5 条一级分支名与首次提交日 |
| `trunk` | 主干 | structure | 某条一级分支连续 3 个自然月有有效提交 | 一级分支、起止月份、每月提交数 |
| `backfill` | 补白 | time | 第一次创建日期在过去的里程碑（A-04 回填） | 里程碑、回填日期、事件日期 |
| `evergreen` | 常青 | time | 单条分支持续 6 个自然月有有效提交 | 分支、起止月份、每月提交数 |
| `first-year` | 第一年 | time | 自根分支 `createdAt` 起满 365 天 | 起始日、第 365 天日期 |
| `three-milestones` | 三碑 | milestone | 累计 ≥3 个里程碑（未删除） | 第 3 个里程碑 ID、累计数 |
| `milestone-note` | 碑上有字 | milestone | 任一米碑的 `note` 非空 | 里程碑 ID、标题、备注摘录 |
| `year-marks` | 年轮有痕 | milestone | 同一年内 ≥3 个里程碑 | 年份、3 个里程碑 ID 与日期 |

- 「活跃区间」= `createdAt` 到 `finishedAt` / `droppedAt` 中较早者；两者都为空时算至判定时刻。归档不改变历史活跃区间。
- 「连续月份」按本地自然月计算，月份内至少 1 条有效提交即算；「常青」只计本分支自己的提交，不含后代。
- 「五面」「主干」的一级分支提交含其后代；根分支不计入候选。
- 「补白」不依赖 E-04 补记（本版不实现），只认 A-04 口径的「日期在过去的里程碑」。

### 4.2 徽章墙（S06-badge-wall）

- 入口：P06「我的」→「徽章墙」；页头显示「已获得 N / 16」。
- 分类切换：结构 / 时间 / 里程碑；默认结构类。
- 分类内排序：已获得在前，按 `grantedAt` 倒序；未获得在后，按目录顺序。
- 已获得项：徽章名、获得日期、一句来源；点击进入详情。
- 未获得项：
  - 三类统一：达成度 ≥50% 时显示「还差 N」；未达 50% 显示灰点与条件一句话。
  - 里程碑类同样按此规则显示差距，不因类别例外。
  - 不可点击进入详情；条件与差距就地展示。
- 空态：一枚未获得时，页头仍显示「0 / 16」，顶部一句「完成第一条待办，拿到第一枚徽章」+「去今天」。
- 徽章墙只读，不提供授予、删除、排序或分享。

### 4.3 徽章详情（S06-badge-detail）

- 内容固定四段：
  1. 名称、类别、获得日期。
  2. 为什么给你：一句人话，来自目录的固定文案，可带入快照中的名词。
  3. 当时数据：按快照逐项显示（分支名、提交数、里程碑数、月份区间等），**不随之后数据变化**。
  4. 落在树上哪天：`snapshot.eventDate`；附「在历程查看」。
- 原事件已撤销或来源已删除：在「当时数据」上方加一行「原事件已撤销 / 来源不可用」，跳转置灰。
- 详情页不允许编辑备注、不允许删除徽章。

### 4.4 树上标记（H-05）

- 位置：P04 历程的时间节点（提交、里程碑、合并点）旁；根分支泳道同样适用。
- 绑定日期：优先 `snapshot.eventDate`，缺失时用 `grantedAt` 的本地日期。
- 同一天多枚：只渲染一个标记，标记上显示数量；悬停或点击展开当天全部徽章名。
- 不与提交圆点、里程碑菱形重叠；窄屏用同一位置的点状标记，点击展开，不依赖悬停。
- 标记只在已获得徽章出现；不预告未获得徽章。
- 切换时间范围或分支筛选时，标记随节点一起出现或隐藏，不做额外筛选。

### 4.5 五种状态

| 状态 | 表现 |
| --- | --- |
| 空 | 徽章墙无已获得：显示「0 / 16」、说明与「去今天」；历程无徽章时不渲染标记，不留空位 |
| 加载 | 徽章墙保留分类与卡片骨架；历程标记后到不阻塞泳道渲染 |
| 错误 | 徽章读取失败：说明 + 重试，不显示「0 枚」冒充空；写入失败：主操作不回滚，下次补查 |
| 只读 | 徽章不可编辑、不可删除；原事件撤销时只读标注并禁用跳转 |
| 无权限或未登录 | 不适用；V1 无账号，徽章与徽章墙不要求登录 |

### 4.6 移动端

- 390 px：徽章墙分类切换横向可滚；徽章卡单列，已获得与未获得同列排列。
- 徽章详情为全屏面板，保留关闭与「在历程查看」。
- 历程标记点击展开当天列表，展开层不遮挡底部导航。

## 5. 数据与规则

| 表 | 字段 | 用途 |
| --- | --- | --- |
| `badges` | `catalogId`、`category`、`periodKey`、`grantedAt`、`snapshot`、`sourceEntityId` | 发放、幂等、详情、树上标记 |
| `commits` | `_id`、`branchId`、`date`、`voidedAt` | 起笔、有始有终、五面、主干、常青 |
| `branches` | `_id`、`parentId`、path、`depth`、`title`、`status`、`createdAt`、`finishedAt`、`droppedAt`、`dropReason`、`archivedAt`、`deletedAt` | 第一道岔、汇流、收束、双线并行、断舍离、有始有终、五面、主干、常青、第一年 |
| `milestones` | `_id`、`branchId`、`title`、`note`、`achievedAt`、`datePrecision` | 立碑、三碑、碑上有字、年轮有痕、补白 |

规则：

- R18 徽章：目录固定 16 项，是常量不是表；授予写 `catalogId` / `category` / `periodKey` / `snapshot`；同一用户同一 `catalogId` 只授一次（唯一键 `[ownerId+catalogId+periodKey]`）；「还差 N」现算。
- 快照不可变：授予后不再随分支、提交、里程碑变化；`snapshot.eventDate` 决定树上标记的日期。
- 发放时机：创建提交、创建里程碑、创建子分支、收尾、放下、重新开始、进入「我的」时检查；一次写入后按目录顺序逐枚判定。
- 幂等：已存在同 `catalogId` 的授予记录即跳过；撤销后不重新发放。
- 失败补查：徽章写入失败不影响主操作；下次启动或进入「我的」时补查；补查不产生重复。
- 导入/恢复：徽章原样保留，不重算、不补发、不收回。
- 有效提交：所有涉及提交的条件只算 `voidedAt == null`。
- 已归档：仍参与条件判定与历史统计；归档不改变已授予徽章。
- 彩蛋徽章：V1 不判定、不显示；目录保持 16 项，不预留空位。
- 徽章不参与额度、排序、统计与分享图数字。

## 6. 验收标准

1. 徽章墙显示「已获得 N / 16」，N 与 `badges` 中实际条数一致；分类切换后每类数量与目录一致（结构 8 / 时间 4 / 里程碑 4）。
2. 第一次放下分支并填写原因后获得「断舍离」，重复放下不再获得第二枚。
3. 某父分支有 2 条子分支，全部收尾后获得「收束」；其中一条为放下状态时不获得。
4. 同一父下两条子分支的活跃区间交集达到 14 天后获得「双线并行」；交集只有 13 天时不获得。
5. 一条 L3 分支从创建到收尾有 10 条有效提交时获得「有始有终」；9 条时不获得。
6. 5 条一级分支各有至少 1 条提交后获得「五面」；其中一条只有子分支提交时仍计入。
7. 某条一级分支连续 3 个自然月有提交后获得「主干」；中间断一个月不获得。
8. 创建一条日期在过去的里程碑后获得「补白」；创建日期为今天的里程碑不触发。
9. 单条分支连续 6 个自然月有有效提交后获得「常青」；使用「本分支自己的提交」口径，子分支提交不替父分支计入。
10. 根分支创建满 365 天后获得「第一年」；提前一天不获得。
11. 第 3 个里程碑获得「三碑」；第一个带非空备注的里程碑获得「碑上有字」；同一年第 3 个里程碑获得「年轮有痕」。
12. 同一次写入同时满足多枚条件时，各获得一枚，轻提示与徽章墙记录不重复、不遗漏。
13. 已获得「起笔」后撤销其提交：徽章仍在，详情显示「原事件已撤销」，跳转不可用；再次完成待办不重复发放。
14. 人为使徽章写入失败：主操作成功；下次进入「我的」时补发且只发一次。
15. 未获得的徽章在达成度 ≥50% 时显示「还差 N」，未达 50% 时显示灰点与条件；三类同一阈值，里程碑类不例外。
16. 徽章详情展示的快照内容在之后新增提交、收尾、改名后保持不变；「落在树上哪天」与 `snapshot.eventDate` 一致。
17. 同一天获得两枚徽章，历程该日只出现一个标记，展开后列出两枚；不同日期分别出现。
18. 导入包含徽章的文件后徽章原样保留，不重算、不补发；文件缺少已满足条件的徽章也不补发。
19. 390 px 下徽章墙单列可浏览，详情为可关闭全屏面板，历程标记可点击展开。

## 7. 依赖与阶段、未决问题

- 阶段：V1。
- 依赖：M11（首批 4 枚与发放机制）、M02（分支结构）、M03（提交）、M07（里程碑）、M08（收尾）、V1-01（放下与归档）、V1-07（回填过去，触发补白）。
- 后续消费：V2-03 在 16 枚基础上追加 5 枚彩蛋，累计 21 枚；V1 的 16 项判定不变，徽章墙页头的分母在 V2 变为 21，并新增「彩蛋」分类。
- 冲突与处理：
  - M11 首枚徽章原写作「第一步」，`FRAMEWORK` H-01 与 §5.2 写作「起笔」。**已定：统一为「起笔」**，M11 已改齐；本 PRD 与 M11 展示名一致，机制不变。
  - `FRAMEWORK` 「补白」写「第一次回填过去的事件」，但 E-04 补记已按 0.12 不实现。本 PRD 按 A-04 的「回填过去」口径解释为「第一次创建日期在过去的里程碑」。
  - `FRAMEWORK` H-03 写「结构类与时间类仅对接近达成的徽章显示差距」，「接近」未定义。本 PRD 暂定达成度 ≥50% 且未获得。
  - `PAGE-DATA-CROSSCHECK` 提到徽章 `type` 字段，0.12 已改为 `catalogId` / `category`；本 PRD 按 0.12。
- 未决问题：
  - 「常青」是否应含后代提交：本 PRD 按本分支自己的提交（与 R7 `commitCount` 一致）；若改成含后代，只改统计范围，不改目录。
  - 「双线并行」的 14 天是否要求自然日连续、是否受归档影响：本 PRD 按活跃区间交集 ≥14×24 小时、归档不影响历史区间处理。
  - 「五面」「主干」是否含后代提交：本 PRD 按含后代；若产品要求只算本分支自己的提交，需同步改条件与验收。
  - 徽章墙「还差 N」的达成度阈值 50% 与各枚的分母口径需在实现前复核。
  - 树上标记是否也需要出现在 P02 分支树（无时间轴）：本 PRD 只落在 P04 历程。

**最值钱的回归用例**：`badge-grant.test.ts` 的「同 `catalogId` 只授一次」。它守的是重复进入「我的」或重复触发同一动作时重复写入徽章的 bug——徽章墙按 `catalogId` 去重展示，重复行在页面上看不出来，只有直接查 `badges` 条数才会发现「16 枚变成 17 条」。手工点页面几乎无法发现。

另一条是 `badge-structure.test.ts` 的「收束：子分支为放下状态时不授予」。若把 `dropped` 误当 `merged`，树上看「子分支都不再进行中」，条件看起来成立；只有核对放下原因与状态才会发现判定口径错了。

### 8.3 只能人工验收

1. **徽章墙分类与排序视觉**：前置已获 5 枚、未获 11 枚；打开徽章墙并切换三类；判定为「已获得 5 / 16」、已获在前按日期倒序、未获灰点或「还差 N」、切类不闪空态；1440 与 390 各一次。为什么不能进单测：排序与差距可测，颜色、灰点与卡片布局只能在渲染层核对。
2. **空态与入口**：前置清空 `badges`；打开徽章墙；判定为「0 / 16」、出现「完成第一条待办，拿到第一枚徽章」与「去今天」，历程不渲染标记也不留空位；1440 与 390 各一次。为什么不能进单测：空态是页面组合结果。
3. **同一天解锁多枚的轻提示**：前置一次收尾同时满足「汇流」与「收束」；判定为今天页底部按目录顺序逐条出现、每条可关闭、不重叠遮挡导航；1440 一次。为什么不能进单测：提示队列与动效时序。
4. **详情跳转与撤销置灰**：前置已获「汇流」；打开详情并点「在历程查看」；撤销该条提交后再进详情；判定为定位到合并点、撤销后出现「原事件已撤销」且跳转不可用；1440 一次。为什么不能进单测：跨页定位与禁用态。
5. **树上标记展开**：前置同一天两枚徽章；在 P04 悬停与点击标记；判定为只出现一个标记、显示数量、展开列出两枚、不与提交圆点或里程碑菱形重叠；1440 与 390 各一次。为什么不能进单测：悬停、点击与碰撞布局。
6. **写入失败补查**：前置在 DevTools 使 `badges` 写入失败；完成一次放下；判定为主操作成功、当次无徽章、再次进入「我的」补发且只发一次；1440 一次。为什么不能进单测：需要注入运行时写失败。
7. **加载骨架与标记后到**：前置节流网络；打开徽章墙与 P04；判定为徽章卡保留骨架、泳道先渲染、标记稍后出现不导致跳动；1440 一次。为什么不能进单测：首帧时序与布局稳定。
8. **390 px 徽章墙与详情**：判定为分类横向可滚、卡片单列、详情为可关闭全屏面板、标记展开层不遮挡底部导航。为什么不能进单测：响应式布局与触摸区域。
