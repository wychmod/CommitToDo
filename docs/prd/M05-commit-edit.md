# M05 提交纠错与提交详情（MVP）

## 1. 背景与目标

提交是「我做完了什么」的唯一记录。它必须可信：写下的当天可以改文案或撤销误操作，过了当天就锁定，任何人回看时看到的都是当时留下的样子。

目标：用户点开任意一条提交，能看清时间、原始分支、文案与前后节点；在写入当天内能改一句话或撤销完成，撤销后待办、计数与时间线同步回退，跨天后只读。

## 2. 范围与非目标

**范围**

- E-02 提交当天纠错：写入当天可修改文案或撤销完成；跨天锁定；每次纠错留痕。
- E-03 提交详情：时间、原始分支、一句话、前后有效节点；不设备注字段。
- O03 提交详情视图；P03 提交流与 P01 回执进入同一详情。
- 撤销完成后的待办恢复、计数回退、提交作废与来源分支处理。

**非目标**

- 不做补记（E-04 与 0.12 删除 `commits.isBackfill` 冲突，本版不做）。
- 不做提交删除；作废只写 `voidedAt`（R2）。
- 不做短 hash 展示，不新增 `hash` 字段（R5）。
- 不做跨天解锁、管理员撤销、批量撤销。
- 不新增表或字段。

## 3. 用户故事与主流程

**故事 1｜当天改一句话**

完成待办后从回执进入提交详情 → 点「编辑文案」→ 修改一句话 → 保存 → 详情与时间线显示新文案；时间、原始分支、待办完成状态不变；历史留一条“修改文案”。

**故事 2｜点错了，撤销完成**

提交详情显示「撤销完成」→ 确认框说明「待办会回到未完成，这条提交不再计入历程与统计」→ 确认 → 待办回到进行中待办列表，分支计数回退，提交从时间线与最近提交中消失；详情仍可打开并标明「已撤销」。

**故事 3｜跨天回看**

第二天打开同一条提交 → 编辑与撤销不可用，页面写明「提交已跨天锁定」；仍可查看时间、分支、文案与前后节点。

**故事 4｜分支已经收尾后才撤销**

在已收尾分支的提交上点撤销 → 确认框先显示「原分支已收尾，待办将恢复到『工作』」→ 确认 → 待办归入最近可接收的上级分支，保留原截止日期；提交作废，父分支计数回退。

**异常与边界**

- 撤销写入失败：待办仍为完成、提交仍有效，提示失败并可重试；不允许出现“待办已恢复但提交还在”。
- 连续点两次撤销：第二次无副作用，不重复回退计数。
- 提交已被作废：详情只读，显示「已撤销」与撤销时间；不提供再次撤销。
- 提交不存在：应用内 404，提供回原页面。
- 时区变化：锁定时间按写入时的本地时区计算，之后切换时区不改变锁定时刻。
- 已归档分支上的提交：当天仍可改文案或撤销；跨天只读。
- 徽章：撤销导致触发事件消失时，已授予徽章保留快照并标明原事件已撤销（M11 展示）。

## 4. 界面与交互

对应视图：**O03 提交详情**；入口为 P01 回执、P03 提交流、P04 时间树节点、V1-04 搜索结果。

### 4.1 详情内容

| 元素 | 规则 |
| --- | --- |
| 时间 | 「2026 年 11 月 20 日 16:42」；不显示短 hash、`_id`（R5） |
| 原始分支 | `sourceBranchId` 对应的分支名与路径；若提交已并入父分支，另显示当前归属 |
| 文案 | `summary`；当天可编辑，跨天只读 |
| 关联待办 | 有 `taskId` 时显示待办标题，可跳到待办详情（O02） |
| 前后节点 | 同一原始分支上按时间排序的相邻有效提交；各显示日期与文案，可点击切换 |
| 状态 | 有效 / 已撤销（含撤销时间） |

### 4.2 当天可做的操作

- **编辑文案**：只改 `summary`；保存后保留 `date`、`at`、`branchId`、`sourceBranchId`、`taskId` 与待办完成状态。
- **撤销完成**：二次确认，写明影响：待办回到未完成、提交不再计入历程与统计、计数回退。
- 撤销前若原分支已收尾或已归档，确认框必须显示待办恢复去向（最近可接收的上级分支，根分支兜底）。
- 撤销成功后关闭确认框，详情变为「已撤销」，并回到来源页面时列表已更新。

### 4.3 跨天锁定

- 锁定时刻 = 写入时本地时区下「写入日的下一自然日 00:00」。
- 到达锁定时刻后，编辑与撤销按钮不可用，显示「提交已跨天锁定」；不提供隐藏入口。
- 锁定只影响文案与撤销，不影响查看与前后节点跳转。

### 4.4 五种状态

| 状态 | 表现 |
| --- | --- |
| 空 | 不适用；提交详情必须有一条提交 |
| 加载 | 保留标题、时间与正文骨架；前后节点可后到 |
| 错误 | 读取失败：说明 + 重试；写入失败：保留编辑内容或撤销前状态 |
| 只读 | 跨天、已撤销、无关联待办可恢复时，按钮不可用并写明原因；查看始终可用 |
| 无权限或未登录 | 不适用；MVP 无账号 |

### 4.5 移动端

- 390 px 使用全屏面板，标题、时间、文案、前后节点纵向排列；编辑与撤销按钮固定可见。
- 确认框限制焦点在框内，屏幕阅读器可读到标题、影响说明与按钮文案。

## 5. 数据与规则

| 表 | 字段 | 用途 |
| --- | --- | --- |
| `commits` | `_id`、`branchId`、`sourceBranchId`、`taskId`、`date`、`at`、`summary`、`voidedAt`、`updatedAt` | 详情、编辑、撤销、前后节点 |
| `tasks` | `status`、`completedAt`、`completedCommitId`、`dueDate`、`branchId` | 撤销后恢复待办 |
| `branches` | `taskDone`、`commitCount`、`ownLastCommitAt` | 撤销后计数回退 |
| `events` | `entityType='commit'`、`action`、`payload`、`at` | 修改文案、撤销完成留痕 |

规则：

- R2 撤销完成：只置 `commits.voidedAt`，不物理删；待办回到 `open` 并清空 `completedAt` / `completedCommitId`；`taskDone`、`commitCount`、`ownLastCommitAt` 在同一事务内回退。
- R3 有效提交：`voidedAt == null`；撤销后的提交不进入历程、最近提交、回顾与任何统计。
- R5 短 hash：不展示；详情只用日期与时刻。
- 文案格式：完成时生成的初始文案为「待办标题 —— 补一句」，本 PRD 只编辑已生成的 `summary`；编辑后以用户文本为准，不重新拼接标题，也不新增字段。
- 四计数（R7）：撤销后按剩余有效提交重算 `ownLastCommitAt`；不能简单减一，需取剩余最大值。
- 锁定：按写入时本地时区计算，切换时区不改锁定时刻；`date` 与 `at` 不因编辑文案而变化。
- 来源分支：合并后 `branchId` 为父、`sourceBranchId` 为原分支；「前后节点」按 `sourceBranchId` 查询，避免把不同来源的提交混在一条线上。
- 撤销后的待办去向：原分支可接收则留在原分支；已合并、已放下或已归档则移到最近的可接收祖先，根分支兜底；保留原 `dueDate`。
- 徽章：撤销不改已授予徽章与其 `snapshot`；「原事件已撤销」由徽章展示层判断，见 M11。

## 6. 验收标准

1. 从 P01 回执进入 O03，显示「2026 年 11 月 20 日 16:42」形式的时间、原始分支、文案与前后有效节点，不出现短 hash 或内部 ID。
2. 写入当天修改文案并保存：详情与时间线显示新文案，`date`、`at`、分支与待办状态不变；历史留一条修改记录。
3. 写入当天点「撤销完成」并确认：待办回到未完成列表，`completedAt` 与 `completedCommitId` 清空，分支 `taskDone` 与 `commitCount` 各减 1，`ownLastCommitAt` 变为剩余有效提交的最大值。
4. 撤销后该提交不再出现在时间线、最近提交、周回顾与任何计数中，但详情仍可打开并显示「已撤销」。
5. 撤销后再次点撤销（或并发重复请求）不产生第二次回退，计数不出现负数。
6. 写入次日打开同一条提交：编辑与撤销不可用，页面写明「提交已跨天锁定」；查看与前后节点跳转正常。
7. 在已收尾分支的提交上撤销：确认框显示恢复去向；确认后待办出现在该上级分支，保留原截止日期。
8. 已归档分支上的提交当天可改文案、可撤销；跨天只读。
9. 撤销写入失败时，待办仍为完成、提交仍有效，页面提示可重试；不出现半完成状态。
10. 修改系统时区后，原提交的锁定状态不变。
11. 提交不存在时显示应用内 404 与返回入口，不白屏。
12. 390 px 下详情为可关闭的全屏面板，编辑与撤销按钮可见，确认框焦点被限制。

## 7. 依赖与阶段、未决问题

- 阶段：MVP。
- 依赖：M03（完成生成提交）、M04（提交流入口与来源标注）。
- 后续消费：M06 时间树节点、M09 周回顾、M11 徽章、V1-04 搜索、V1-02 年轮。
- 冲突与处理：
  - `FRAMEWORK` E-04 补记属 V1，但 0.12 已删除 `commits.isBackfill` 并明确「无补记入口」：本 PRD 不设计补记，V1-07 只记录原文与冲突。
- 未决问题：
  - 「前后节点」是否包含里程碑，当前只取提交，不混入里程碑。
  - 撤销后待办恢复到祖先分支时，是否需要在待办历史中显式标注“因撤销自动改归属”，当前只写 `events`。
  - 已撤销提交的详情是否长期保留入口，当前保留，且可从分支历史或搜索进入（搜索 V1）。
