# V1-08 排序与置顶（V1）

## 1. 背景与目标

默认顺序按日期与创建时间排，能覆盖大多数情况，但覆盖不了「这条我要先做」「这条线是当前主线」。V1 给两类对象加手动顺序：今天页的待办可以在组内拖拽；分支树的同级分支可以拖拽排序，并可以把一条分支置顶。

本 PRD 交付 C-04 今日顺序与 D-08 分支排序、置顶，复用 P01、P02 与 B01 行尾菜单，不新增页面。

目标：用户拖过一次之后，刷新、重开、换天回来，顺序仍然是他排的样子；置顶的分支始终在最前，取消后回到原来的位置。

## 2. 范围与非目标

**范围**

- C-04 今日顺序：今天页三个分组内拖拽调整待办顺序，写入 `tasks.order`。
- D-08 分支排序：同一父分支下拖拽调整同级顺序，写入 `branches.order`；新分支仍默认末尾。
- D-08 置顶：分支可置顶与取消，不限个数；置顶块排在同级最前，写入 `pinnedAt`。
- P01、P02 的拖拽交互与行尾菜单扩展；移动端提供「上移 / 下移」。

**非目标**

- 不做跨组拖拽改日期，不做跨父拖拽改归属（跨父移动归 B05）。
- 不做按名称、日期、颜色的自动排序规则，不做排序方案切换。
- 不做「全部待办」页的拖拽（V1-04 之后仍保持默认分组顺序）。
- 不做归档区、历程泳道的排序。
- 不做批量上移、批量置顶、置顶排序方案设置。
- 不改表结构；只使用既有 `order` 与 `pinnedAt` 字段。

## 3. 用户故事与主流程

**故事 1｜把今天最想做的拖到最前**

今天页「今天」组有 6 条 → 按住第 5 条拖到第 1 位 → 松手后立刻生效 → 刷新页面，顺序保持；新添加一条待办，出现在该组末尾。

**故事 2｜组内顺序不跨越日期**

把「无截止日期」组的一条拖到「今天」组上方 → 松手后回到原组原位，提示「跨组拖拽不会改日期，请用『安排到今天』」→ 日期不变。

**故事 3｜把当前主线置顶**

`/branches` 在「工作」行尾菜单点「置顶」→ 该分支移到同级最前并显示置顶标记；再置顶「健康」→ 最近置顶的「健康」在最前；取消「工作」置顶 → 它回到原 `order` 位置。

**故事 4｜调整同级顺序**

按住「工作」下的「主业」拖到「副业」之后 → 松手生效 → 刷新后顺序保持；「主业」的子分支随父行一起移动，层级不变。

**异常与边界**

- 拖拽到同组之外：不接受落点，行回弹，日期与归属不变，给一次说明。
- 拖拽中被拖行的已完成状态变化（后台完成）：该行从列表消失，落点取消，提示「这条已完成」。
- 排序写入失败：顺序回到拖拽前，提示重试；不出现「界面已换位、刷新回原样」的静默失败。
- 今天页某组只有 1 条待办：不显示拖拽把手，不响应长按。
- 新分支：无论是否置顶过其他分支，新分支仍追加到同级末尾（M02 口径）。
- 置顶分支被放下或收尾：仍保持置顶，直到用户取消；已归档分支不显示置顶标记，取消归档后恢复原置顶状态。
- 根分支不能置顶、不能参与同级排序；归档区与已归档子树不能排序。
- 父分支被移动：子分支保持各自 `order` 与置顶状态，随父一起换位置。
- 置顶数量无上限；置顶块内部不提供拖拽，按置顶时间倒序。
- 移动端不提供拖拽：只用行尾菜单的「上移 / 下移」，边界处对应项禁用。

## 4. 界面与交互

对应页面：**P01** 今天页、**P02** 分支树；菜单：**B01** 行尾菜单。

### 4.1 今日顺序（C-04）

- 入口：P01 三个分组内的待办行，桌面按住行拖动；移动端用行尾「上移 / 下移」。
- 拖拽只在同一分组内生效；拖动时显示插入位置，跨组区域不显示可用落点。
- 松手后立即写入并重排；不出现保存按钮，不给二次确认。
- 组内默认顺序仍按 M03：截止日期升序、同日按创建顺序；任一条被手动拖拽后，该组改用 `order` 升序。
- 新添加的待办进入所属组末尾；完成、取消、改日期后按新的分组与 `order` 展示。
- 收起态下不允许拖拽；展开后可拖拽。
- 「全部待办」页不提供拖拽，但同一待办在两个页面的相对顺序一致。

### 4.2 分支排序（D-08）

- 入口：P02 同级分支之间拖动；拖动父行时其可见子树随行移动，层级不改变。
- 只在同一父分支内生效；拖到其他父分支的行上不显示可用落点。
- 松手后写 `order` 并重排；新分支仍追加到同级末尾。
- 置顶分支组成同级最前的置顶块；置顶块内部按 `pinnedAt` 倒序（最近置顶在前），不可拖拽。
- 非置顶分支之间可拖拽；取消置顶后按原 `order` 回到非置顶区的位置。
- 已归档子树不参与排序；已合并、已放下但仍可见的分支可以排序与置顶。

### 4.3 置顶（D-08）

- 入口：B01 行尾菜单「置顶 / 取消置顶」；P03 页头显示置顶状态。
- 置顶不限个数；一次点击生效，不弹确认。
- 置顶标记在 P02 行首或行尾固定位置，不挤压分支名；同一分支只显示一个标记。
- 取消置顶后 `pinnedAt` 清空，分支回到非置顶区的 `order` 位置。
- 根分支不提供置顶；已归档分支不提供置顶，取消归档后按原状态恢复。

### 4.4 桌面与移动端

- 桌面：拖拽提供插入线，行高不变；拖到不可落点显示禁止光标。
- 390 px：不提供拖拽；行尾菜单提供「上移」「下移」，到组首 / 组尾时对应项置灰。
- 移动端置顶入口与桌面一致，均在该行「更多」内；点击区域不小于 44 px。

### 4.5 五种状态

| 状态 | 表现 |
| --- | --- |
| 空 | 组内无待办：无拖拽把手；同级只有一个分支：无拖拽把手与上移 / 下移 |
| 加载 | 保留行高与顺序骨架；加载完成后按 `order` 渲染，不先按默认顺序闪一下 |
| 错误 | 排序写入失败：回到拖拽前顺序并提示重试；置顶写入失败：标记与位置不变并提示 |
| 只读 | 已归档子树、已合并分支的详情只读，但已合并且仍在树上的分支允许排序与置顶；归档区不提供排序 |
| 无权限或未登录 | 不适用；V1 无账号，排序与置顶不要求登录 |

## 5. 数据与规则

| 表 | 字段 | 用途 |
| --- | --- | --- |
| `tasks` | `_id`、`branchId`、`group`（派生）、`order`、`dueDate`、`plannedDate`、`createdAt`、`status` | 组内顺序与默认顺序回退 |
| `branches` | `_id`、`parentId`、`path`、`depth`、`order`、`pinnedAt`、`status`、`archivedAt` | 同级顺序、置顶块、子树随行 |

规则：

- 今日顺序：`tasks.order` 为组内升序；未设置 `order` 的待办按 M03 默认（截止日期升序、同日创建顺序）排在已设置项之后。
- 分组派生：待办属于逾期 / 今天 / 无截止由 R8 现算；`order` 只决定组内相对位置，不改变分组。
- 跨组与跨父拖拽：不写任何字段，落点回弹；改日期用 O02 或「安排到今天」，改归属用 B05。
- 分支顺序：同一 `parentId` 下按 `order` 升序；置顶块在前，按 `pinnedAt` 倒序；非置顶按 `order` 升序。
- 新分支：取同级最大 `order` 之后追加，`pinnedAt` 为空（M02 口径）。
- 置顶：`pinnedAt` 非空即置顶；取消置顶写空；置顶不改 `order`、`parentId`、`path`、`depth`。
- 排序与置顶不改四计数（R7）、额度（R16）、停滞（R4）与今天分组（R8）。
- 归档：已归档子树不参与排序与置顶展示；取消归档后恢复原 `order` 与 `pinnedAt`。
- 移动父分支：子分支的 `order` 与 `pinnedAt` 保持不变。
- 排序写入失败必须回滚界面顺序；不做乐观更新后静默失败。
- 排序不写 `events`、不触发徽章、不进入任何统计。

## 6. 验收标准

1. 在「今天」组把第 5 条拖到第 1 位，松手后立即生效；刷新页面顺序保持，`tasks.order` 已更新。
2. 把一条待办拖到另一组的区间，落点不可用并回弹；该待办日期、分组与顺序均不变，出现一次说明。
3. 组内手动排序后新增一条待办，新待办出现在该组末尾；原有相对顺序不变。
4. 某组只有 1 条待办时无拖拽把手；收起态不能拖拽，展开后可拖拽。
5. 在 P02 把同一父下的「主业」拖到「副业」之后，刷新后顺序保持；父行拖动时其可见子树一起移动，层级不变。
6. 把分支拖到另一个父分支的行上，落点不可用并回弹；`parentId` 不变。
7. 连续置顶 A、B 两条分支：置顶块顺序为 B、A；取消 A 置顶后，A 回到非置顶区的原 `order` 位置。
8. 置顶数量不受限制；置顶块内部不可拖拽，非置顶区可拖拽。
9. 已合并、已放下且仍可见的分支可置顶与排序；已归档分支不提供置顶；根分支不提供置顶。
10. 新建分支出现在同级末尾，即使同级已有置顶分支。
11. 父分支被移动到新的父下，其子分支的 `order`、`pinnedAt` 与层级保持不变。
12. 模拟排序写入失败：行回到拖拽前位置并提示重试；模拟置顶写入失败：标记与位置不变并提示。
13. 排序与置顶后，分支 `taskTotal` / `taskDone` / `commitCount` / `ownLastCommitAt` 不变，今天分组不变。
14. 390 px 下无拖拽，行尾「上移 / 下移」可用，组首与组尾对应项置灰；置顶入口可用。
15. 「全部待办」不可拖拽，但同一待办与今天页的相对顺序一致。

## 7. 依赖与阶段、未决问题

- 阶段：V1。
- 依赖：M02（分支 `order` 与新分支末尾）、M03（今天分组与默认顺序）、B01 菜单；M08 与 V1-01 提供已合并、已放下、已归档状态。
- 后续消费：无；排序与置顶只影响展示顺序。
- 冲突与处理：
  - `FRAMEWORK` K-04 字号调节已定 Web 端不做；V1-08 只保留 C-04 与 D-08，不含字号。
  - `TECH-ARCHITECTURE` 写「同父内 `pinnedAt` 非空排最前，其余按 `order`」，未写多个置顶之间的顺序：本 PRD 定为按 `pinnedAt` 倒序。
  - `FRAMEWORK` C-04 只写「手动调整今日顺序」，未写跨组行为：本 PRD 定为跨组不生效，避免拖拽隐式改日期。
  - M03 的默认顺序（截止日期升序、同日创建顺序）仍然有效；手动拖拽后该组改用 `order`，未拖拽的组继续按默认顺序。
- 未决问题：
  - 今日手动顺序是否应按天重置：本 PRD 按「长期保留」，跨天继续生效；若产品希望每天回到默认顺序，需要增加按日清除 `order` 的规则。
  - 置顶块内部是否需要手动排序：当前按置顶时间倒序且不可拖拽。
  - 「全部待办」是否需要同等的拖拽能力：当前只读展示顺序。
