# M03 今天、待办与完成（MVP）

## 1. 背景与目标

今天页回答「我现在做什么」，待办是产品里唯一可执行的最小单元。本 PRD 交付从记一笔到点完成的完整闭环：待办进入逾期 / 今天 / 无截止三组，点一下即完成并自动生成一条提交，页面立即出现「已提交 16:42」的回执。

目标：用户不建分支、不写日期，也能在 10 秒内记下并完成第一条真实待办；刷新后待办状态、提交与分支计数一致。

## 2. 范围与非目标

**范围**

- C-01 今日清单：三组、每条只出现一次、逾期折叠、无截止折叠、全部待办入口、清单收起。
- C-02 一键完成：点击立即完成，无确认框；完成后可选补一句；撤销入口在提交详情（M05）。
- B-01 快速添加：一句话识别截止日期与所属分支，失败保留输入并给纠正入口。
- E-01 完成即提交：完成待办自动生成提交，内容为待办标题 + 可选一句。
- P01 今天页、`/today/all` 全部待办、S01-all-todos、O01-quick-add、O02-todo-detail。
- 待办的编辑、取消、改归属、安排到今天 / 移出今天。
- P01 的「最近提交」区块。

**非目标**

- 不做提交文字纠错与撤销完成（M05）；不做停滞提醒与虚线（M06）；不做拖拽排序（V1-08）；不做批量导入（V1-07）；不做补记（按 0.12 无补记入口）。
- 不做分支收尾（M08）、放下（V1-01）、归档（V1 手动归档）。
- 不新增表或字段；不恢复已删除的 `tasks.priority`。

## 3. 用户故事与主流程

**故事 1｜空工作区记下第一条**

`/today` 空态 → 点「记一笔」→ 输入「明天交周报」→ 识别为明天到期、默认根分支「我」→ 保存 → 待办出现在今天页（到期日为明天时不进今天组，进入全部待办的未来到期；若输入「今天交周报」则进今天组）。

**故事 2｜完成一件事**

在今天组点待办前的勾选 → 立即完成，不弹确认 → 该行变为回执「已提交 16:42」→ 可选补一句 → 焦点落到下一条待办 → 刷新后仍为完成态，提交仍在。

**故事 3｜从全部待办里捞回一条**

今天页点「全部待办」→ 在「未来到期」找到三天后的待办 → 行尾菜单「安排到今天」→ 返回今天页，该条只出现一次。

**故事 4｜改一条待办的归属和日期**

点待办名称打开详情 → 改标题、备注、截止日期、计划日期、所属分支 → 保存 → 今天页分组随日期变化，原分支进度相应更新。

**故事 5｜放弃一条待办**

详情里点「取消」→ 待办从今天与全部待办中移出，分支 `taskTotal` 减一（按 R7 口径不计 `cancelled`），提交不受影响。

**异常与边界**

- 快速添加无法识别日期或分支：保留原输入，显示「没认出日期/分支」与手动选择入口；不静默丢弃文本。
- 输入的日期已过去：按逾期组处理，不自动改成今天。
- 完成写入失败：勾选回弹，待办仍为未完成，就地提示失败并可重试；不出现“界面已完成、库里没有提交”。
- 同一条待办连点两次完成：只允许一次有效完成，第二次不产生第二条提交。
- 待办所属分支已合并、已归档或已放下：只读，显示原因，不提供完成与编辑。
- 取消的待办在详情历史中保留；不物理删除。
- 跨自然日：昨天打开今天页未刷新，零点后重新进入按当天日期重算三组。

## 4. 界面与交互

### 4.1 今天页（P01）

页头显示两组计数：「N 条有截止日期 · 另有 M 条无截止日期」。三组顺序固定：

| 组 | 纳入 | 默认状态 |
| --- | --- | --- |
| 逾期 | 有截止、`dueDate < today`，且 `plannedDate != today` | 超过 5 条默认折叠，显示条数；中性色，不用红色 |
| 今天 | `dueDate = today`，或 `plannedDate = today`（含原本逾期的） | 展开 |
| 无截止日期 | `dueDate = null` | 默认折叠，显示条数 |

- 每条待办只出现一次；组内按截止日期升序，同日按创建顺序。
- 每行提供三个独立入口：勾选完成、点名称打开详情、行尾「更多」（安排到今天 / 移出今天 / 取消）。
- 清单可收起：收起时只露第一条，完成后自动露出下一条；收起是列表内操作，不进入全屏、不启动计时。
- 「最近提交」区块：按 `at` 倒序显示最近若干条有效提交（R3），点击进入提交详情（M05）。
- 停滞提醒区块由 M06 交付；本 PRD 不实现。
- 周回顾卡片由 M09 交付；本 PRD 只留出页面底部位置。
- 页脚固定「全部待办」入口。

### 4.2 全部待办（`/today/all`，S01-all-todos）

- 默认按「逾期 / 未来到期 / 无截止」分组；另提供「根分支」「已放下」「已归档」筛选，筛选可叠加（如「已归档 + 根分支」），同一待办只出现一次。
- 「已放下」在 D-06 上线前为空组；「已归档」只读展示，进入详情时说明只读原因。
- 符合条件的待办可在行尾菜单「安排到今天」；已在今天的显示「移出今天」。
- 只对根分支与默认树中进行中分支的未完成待办提供该操作。

### 4.3 快速添加（O01）

- 入口位于今天页与全局悬浮「记一笔」。
- 单行输入；自动识别截止日期与分支名；识别结果在保存前以文字回显（如「明天 · 工作」）。
- 未指定分支时默认根分支「我」；未识别日期时 `dueDate` 为空。
- 识别失败不阻断保存：保留输入，提供日期与分支的手动选择。
- 保存成功后清空输入、关闭面板，今天页对应组即时更新。

### 4.4 待办详情（O02）

- 字段：标题（必填）、备注、截止日期、计划日期、所属分支、状态。
- 操作：保存、完成、取消待办、改归属、安排到今天 / 移出今天。
- 历史：创建、编辑、完成、取消、改归属的留痕；完成记录可跳到对应提交详情。
- 改归属只允许移到根分支或默认树中进行中的分支；不可接收的分支置灰并写明原因。
- 取消待办需一次确认，说明「取消后不再出现在今天与全部待办，历史仍保留」。

### 4.5 五种状态

| 状态 | 表现 |
| --- | --- |
| 空 | 今天无任何待办：一句「今天还没有要做的」+「记一笔」；全部待办为空：一句说明 + 回今天 |
| 加载 | 保留页头、三组标题与行高；不整屏 spinner；加载后不跳动 |
| 错误 | 读取失败：保留外框，说明 + 重试；写入失败：勾选回弹、表单保留输入 |
| 只读 | 所属分支已合并、已归档或已放下：行与详情只读，写明原因；已完成待办不回列表 |
| 无权限或未登录 | 不适用；MVP 所有待办操作不要求登录 |

### 4.6 移动端

- 390 px：今天页侧栏（最近提交、回顾）并入主列，顺序为清单 → 最近提交 → 回顾。
- 快速添加为全屏面板，键盘弹起时保存按钮可见；待办详情为全屏面板，保留关闭入口。
- 行尾「更多」用长按或显式按钮触达，不依赖悬停。

## 5. 数据与规则

| 表 | 字段 | 用途 |
| --- | --- | --- |
| `tasks` | `_id`、`branchId`、`title`、`note`、`dueDate`、`plannedDate`、`status`、`order`、`completedAt`、`completedCommitId`、`cancelledAt`、`createdAt`、`updatedAt`、`deletedAt` | 今天三组、详情、全部待办、历史 |
| `commits` | `_id`、`branchId`、`sourceBranchId`、`taskId`、`date`、`at`、`summary`、`voidedAt` | 完成回执、最近提交、分支提交流 |
| `branches` | `taskTotal`、`taskDone`、`commitCount`、`ownLastCommitAt` | 行内进度、页脚额度、停滞判定（M06 消费） |
| `events` | `entityType='task'`、`action`、`payload`、`at` | 待办历史 |

规则：

- R1 完成待办：同一事务内 `tasks.status=done`、写 `completedAt` 与 `completedCommitId`，生成一条 `commits`（`taskId` 指回、`date` 取完成日、`at` 取当前时刻、`branchId` 取当前分支、`sourceBranchId` 同值），同步更新分支 `taskDone` / `commitCount` / `ownLastCommitAt`。
- E-01 提交内容：`summary` 默认等于待办标题；用户补一句后为「标题 —— 补一句」，不新增字段，不覆盖已生成的 `at` 与 `date`。
- R8 今天三组：有截止为 `dueDate <= today` 或 `plannedDate = today`；**`plannedDate = today` 优先归今天组（含原本逾期的）**；只有 `plannedDate != today` 且 `dueDate < today` 才归逾期组；无截止取 `dueDate == null`；父分支 `dropped` 或归档的待办不进今天。R8 由技术线同步补充该例外。
- R7 四计数：`taskTotal` 只算未删且 `status != cancelled`；`taskDone` 只算 `done`；完成、取消、改归属后同事务更新。
- R3 有效提交：最近提交只显示 `voidedAt == null` 的提交。
- 计划日期：「安排到今天」只写 `plannedDate = today`，不改 `dueDate`；跨自然日后按原 `dueDate` 重新分组。
- 日期：`dueDate` / `plannedDate` 存 `YYYY-MM-DD`；`at` 存 UTC 毫秒；界面按本地时区显示。
- 快速添加：识别失败不创建半成品；保存前必须能确定标题。

## 6. 验收标准

1. 空工作区点「记一笔」，输入「今天交周报」，保存后待办出现在今天组，归属根分支「我」。
2. 输入「明天交周报」，保存后不进今天组，可在 `/today/all` 的「未来到期」找到。
3. 快速添加输入无法识别的内容时，文本保留，出现手动选择日期与分支的入口；保存后待办仍可创建。
4. 点今天组待办的勾选，立即完成且无确认框；行变为「已提交 HH:mm」，时间与当前本地时刻一致。
5. 完成一条待办后，`commits` 恰好新增 1 条，`taskId` 指向该待办，分支 `taskDone` 与 `commitCount` 各 +1；刷新后结果不变。
6. 连点两次完成不产生第二条提交；完成写入失败时勾选回弹，待办仍为未完成并提示可重试。
7. 完成后补一句，提交文案变为「标题 —— 补一句」；不补时等于标题。
8. 逾期超过 5 条时默认折叠并显示条数；展开后可逐条查看；无截止组默认折叠并显示条数。
9. 同一待办在逾期、今天、无截止三组中只出现一次；页头「N 条有截止日期 · 另有 M 条无截止日期」与组内条数一致。
10. 对一条未来到期待办执行「安排到今天」，返回今天页后只出现一次并进今天组；对一条逾期任务执行同一操作，也进今天组、不再出现在逾期组；次日重新进入，按原截止日期回到未来到期或逾期。
11. 取消一条待办后，它从今天与全部待办消失，`taskTotal` 相应减少，历史仍可在详情查看。
12. 把待办改到另一条进行中分支后，原分支与新分支的进度分别更新；目标分支不可接收时不可选并写明原因。
13. 已归档或已合并分支上的待办只读，完成与编辑不可用，原因可见。
14. 390 px 下侧栏并入主列，快速添加与待办详情为可关闭的全屏面板。
15. 在全部待办中同时选择「已归档」与「根分支」，只显示同时满足两条的待办；切换筛选不产生重复行。

## 7. 依赖与阶段、未决问题

- 阶段：MVP。
- 依赖：M01（外框、空态）、M02（根分支与可接收分支）。
- 后续消费：M04 分支详情、M05 撤销与提交详情、M06 时间树与停滞、M09 周回顾、M11 首条提交徽章、M12 首次引导。
- 冲突与处理：
  - `FRAMEWORK` C-01 与 `TECH-ARCHITECTURE` R8 的「安排到今天」冲突**已定**：显式安排到今天的待办归今天组，不再算逾期；技术线同步为 R8 补该例外。本 PRD 按此口径。
  - `FRAMEWORK` 2.2 提到待办「优先级」，0.12 已删除 `tasks.priority`：本 PRD 不出现优先级，不提供优先级排序。
- 未决问题：
  - 快速添加支持的自然语言日期格式清单未定义，需在实现前给出最小集合与失败口径。
  - 「最近提交」显示条数未定，页面空间允许时建议 3–5 条。
