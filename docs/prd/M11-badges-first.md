# M11 首批徽章与「我的」（MVP）

## 1. 背景与目标

MVP 只发四枚徽章，每枚都对应一个真实的「第一次」：第一次提交、第一次分叉、第一个里程碑、第一次汇流。徽章不是积分，它把用户带回历程里的那个位置，让第一次被看见。

目标：四个触发动作发生时各发一枚徽章，快照当时的事实；「我的」页能看到已获得的徽章并跳回历程；撤销触发事件不收回徽章。

## 2. 范围与非目标

**范围**

- H-01 首批 4 枚徽章：起笔（首条有效提交）、第一道岔（第一条子分支）、立碑（第一个里程碑）、汇流（第一次收尾合并）。
- 徽章发放、快照、幂等与失败补查。
- P06「我的」页 MVP 部分：已获徽章列表、设置入口、数据与备份入口。
- 今天页底部的当天解锁轻提示。
- 徽章跳转历程（复用 M06 直达）。

**非目标**

- 不做累计 16 枚、徽章墙、徽章详情页、树上标记（V1-05）。
- 不做 5 枚彩蛋徽章（V2-03）。
- 不做徽章分享、导出图片、徽章排序自定义。
- 不新增表或字段；只使用 `badges` 现有字段。

## 3. 用户故事与主流程

**故事 1｜完成第一条待办，拿到起笔**

在空工作区完成第一条待办 → 今天页底部出现轻提示「解锁『起笔』· 看第一段路」→ 点「看第一段路」进入历程并定位到该提交 → 关闭提示。

**故事 2｜建了第一条子分支，拿到第一道岔**

在 L1 下新建第一条子分支 → 当天首次回到今天页时出现「解锁『第一道岔』」→ 在「我的」看到该徽章与获得日期。

**故事 3｜钉下第一个里程碑，拿到立碑**

新建第一个里程碑 → 发放「立碑」；快照记录标题、日期精度与所属分支。

**故事 4｜第一次收尾，拿到汇流**

把子分支收尾到父分支 → 发放「汇流」；快照记录去向与收尾日期。

**故事 5｜撤销了那条提交，徽章还在**

撤销触发「起笔」的提交 → 徽章仍显示，列表中标注「原事件已撤销」；不重新发放，也不删除。

**异常与边界**

- 同一天解锁多枚：按解锁顺序依次显示轻提示，一次一条，可逐条关闭；不堆叠遮挡今天清单。
- 当天未打开今天页：轻提示不保留到次日，不补发提示；徽章本身已在「我的」。
- 撤销触发事件后再完成一条同类事件：不重复发放同一 `catalogId`。
- 徽章写入失败：不回滚主操作；下次启动或下次进入「我的」时补查并补发；同一徽章只发一次。
- 触发数据已被删除（如空分支不存在）：徽章快照仍保留，不因源数据消失而删除；列表标注来源不可用。
- 根分支不能收尾，因此「汇流」只由子分支收尾触发。
- 导入或恢复数据后：按文件中的 `badges` 原样保留，不重算、不重新发放；若文件缺少某枚已满足条件的徽章，也不补发（快照不复算）。

## 4. 界面与交互

### 4.1 P06「我的」（MVP）

| 区块 | 内容 |
| --- | --- |
| 页头 | 标题「我的」；不显示账号、头像或登录入口 |
| 已获徽章 | 4 枚的获得态列表：名称、获得日期、来源一句；未获得的 4 枚不显示（MVP 不做徽章墙） |
| 徽章操作 | 「看历程」跳转对应位置；触发事件已撤销时显示「原事件已撤销」并禁用跳转 |
| 设置 | 进入 P07 |
| 数据与备份 | 进入 P08 |
| V1/V2 分区 | 本阶段不显示徽章墙、账号、同步 |

- 空态：一句「完成第一条待办，拿到第一枚徽章」+「去今天」。
- 徽章列表按获得时间倒序；不显示进度、差距或未获得徽章。

### 4.2 当天轻提示

- 位置：今天页底部、清单之后；不遮挡底部导航，不自动消失。
- 内容：徽章名 + 一句来源 + 「看历程」+ 关闭。
- 同一时间只显示一条；多条按发放顺序排队，关闭一条后显示下一条。
- 只在发放当天出现；跨天不补。

### 4.3 跳转

- 起笔 → 首条有效提交所在泳道与日期。
- 第一道岔 → 第一条子分支的创建位置。
- 立碑 → 第一个里程碑节点。
- 汇流 → 收尾合并点。
- 跳转复用 M06 的直达规则：不改写用户保存的时间范围与分支筛选。

### 4.4 五种状态

| 状态 | 表现 |
| --- | --- |
| 空 | 无已获徽章：说明 + 去今天；今天页无解锁提示时不占位 |
| 加载 | 「我的」页徽章区骨架；今天页提示后到，不阻塞清单 |
| 错误 | 徽章读取失败：说明 + 重试；不显示空列表冒充「没有徽章」 |
| 只读 | 徽章不可编辑、不可删除；触发事件已撤销时只读标注 |
| 无权限或未登录 | 不适用；MVP 无账号，页面不出现登录要求 |

### 4.5 移动端

- 390 px：徽章卡单列；轻提示固定在内容流末尾，不悬浮遮挡导航。
- 跳转后返回，保留历程的筛选与位置。

## 5. 数据与规则

| 表 | 字段 | 用途 |
| --- | --- | --- |
| `badges` | `catalogId`、`category`、`earnedAt`、`snapshot`、`createdAt` | 发放、展示、跳转、撤销标注 |
| `commits` | `_id`、`voidedAt`、`branchId`、`date` | 起笔条件与跳转 |
| `branches` | `depth`、`status`、`finishedAt`、`finishedIntoId` | 第一道岔、汇流条件与跳转 |
| `milestones` | `_id`、`branchId`、`achievedAt` | 立碑条件与跳转 |

规则：

- R18 徽章：目录固定 16 枚，MVP 只启用 4 枚；按 `catalogId` 幂等，同一用户每枚只授一次；`snapshot` 记录授予时的事实，永不重算；撤销触发事件不收回徽章。
- 条件：
  - 起笔：存在至少一条 `voidedAt == null` 的提交。
  - 第一道岔：存在至少一条 `depth == 2` 且未删除的分支。
  - 立碑：存在至少一个里程碑。
  - 汇流：存在至少一条 `status == merged` 的分支。
- 快照至少包含：触发时间、触发实体 ID、分支 ID / 提交 ID / 里程碑 ID、当时的分支名或提交文案。
- 发放时机：触发写入成功后检查；失败不回滚主操作，下次启动或进入「我的」时补查；导入/恢复不触发补发。
- 撤销标注：起笔对应提交 `voidedAt != null`、或跳转目标已删除时，显示「原事件已撤销」/「来源不可用」。
- 不做四计数以外的统计，不把徽章数量计入任何额度或排序。

## 6. 验收标准

1. 空工作区完成第一条待办后，今天页底部出现「起笔」轻提示，且只出现一次。
2. 点轻提示的「看历程」，历程定位到该提交并高亮，原时间范围与分支筛选不变。
3. 新建第一条 L1 下的子分支后获得「第一道岔」；新建第二条子分支不再发放。
4. 新建第一个里程碑后获得「立碑」；快照包含里程碑标题与所属分支。
5. 第一次收尾子分支后获得「汇流」；根分支不可收尾，不产生该徽章。
6. 同一天解锁多枚时，轻提示按顺序逐条显示，不堆叠遮挡清单；关闭一条出现下一条。
7. 次日进入今天页，不补发前一天的轻提示；「我的」仍能看到已获徽章。
8. 撤销「起笔」对应的提交后，徽章仍在，列表标注「原事件已撤销」，跳转不可用。
9. 撤销后再次完成待办，不重复发放「起笔」。
10. 人为使徽章写入失败，主操作仍成功；下次进入「我的」时补发且不重复。
11. 导入包含徽章的文件后原样保留，不重算、不补发；文件缺少已满足条件的徽章时也不补发。
12. 「我的」页按获得时间倒序显示已获徽章，未获得的不显示；空态显示说明与「去今天」。
13. 390 px 下徽章卡单列，轻提示不遮挡底部导航。

## 7. 依赖与阶段、未决问题

- 阶段：MVP。
- 依赖：M03（首条提交）、M02（子分支）、M07（里程碑）、M08（收尾）、M06（直达）。
- 后续消费：V1-05 扩展至 16 枚、徽章墙、详情、树上标记；V2-03 加彩蛋。
- 冲突与处理：
  - 文档只规定「首批 4 枚」与名称，未定义失败补发与撤销标注；本 PRD 按幂等发放、快照不复算处理。
- 未决问题：
  - 轻提示在同一天多枚时的排队上限与是否可「全部关闭」未定。
  - 徽章快照的最小字段集需与技术线确认，避免与 `snapshot` 现有结构冲突。
  - 第一道岔是否只算 `depth=2`（L1 下第一条），还是任何新建子分支；当前按前者。
