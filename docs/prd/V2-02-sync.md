# V2-02 多设备同步与匿名统计（V2）

## 1. 背景与目标

V2-01 给了「我是谁」，本 PRD 给「我的数据在哪里」。同账号多设备打开后，一台设备上的写入要在 1–3 秒内出现在另一台；断网时照常写本机，联网后自动补传；两台设备改同一行时不静默丢数据，冲突要能被看到并在分支历史里留痕。匿名统计只上报计数器，不上报任何内容。

本 PRD 交付 L-03、J-08、J-07：同步开关与状态、设备列表、冲突记录、首次迁移、离线补推、匿名统计开关，以及 O08-sync-devices、O08-sync-conflict、`/settings#sync`。

目标：两台登录同账号的设备在正常网络下 3 秒内互相可见；断网编辑不丢、恢复网络后自动补传；冲突有记录、可查看、可在分支历史追溯；统计包不含任何标题、分支名、备注或业务标识。

## 2. 范围与非目标

**范围**

- L-03 多设备同步：登录同账号后自动同步；正常网络下 1–3 秒内互相可见。
- J-08 同步数据与冲突：本地先写 + outbox 补推；服务端拒绝过期写入时记入 `conflicts`，不静默丢弃；分支历史留痕。
- 首次登录的一次性迁移：本机数据归属并推送到账号，断点续传。
- 设备列表：当前设备、其他设备、最近同步时间。
- 冲突记录：两次修改对照、涉及字段、设备、时间，链接到分支历史。
- J-07 匿名统计：只上报计数器，不上报任何内容，可开关。
- O08-sync-devices、O08-sync-conflict、`/settings#sync`。

**非目标**

- 不做端到端加密；数据明文存储，安全边界由数据库安全规则与云函数承担（J-08 已定）。
- 不做手动合并、字段级选择保留哪一版、冲突编辑器。
- 不做协作、共享账号、团队空间、公开链接。
- 不做实时协同光标、在线状态、正在输入提示。
- 不同步备份包、示例树、本机 UI 状态与认证凭证。
- 不新增表；`outbox`、`conflicts`、`devices`、`migration_state`、`counters` 随本 PRD 启用，字段沿用 0.12。
- 匿名统计不上报任何内容，不接入第三方统计 SDK。

## 3. 用户故事与主流程

**故事 1｜两台设备同时用**

设备 A 与 B 登录同一账号 → A 完成一条待办 → B 在 3 秒内看到新提交与分支计数变化；B 新建一条分支 → A 同步出现，层级与颜色一致。

**故事 2｜地铁里断网**

设备 A 在离线状态完成 3 条待办、改 1 条分支名 → 界面立即生效，同步状态显示「离线，待补传 4 项」→ 恢复网络后自动补推，状态回到「已同步」，设备 B 收到全部变更。

**故事 3｜两台设备改同一行**

A、B 同时修改同一条待办标题 → A 先提交成功 → B 的写入被服务端拒绝 → B 的界面显示服务端当前版本，弹出一条不打断的提示「有 1 条同步冲突已记录」→ 在 `/settings#sync` 的冲突记录中看到 A、B 两次修改的对照；该待办所属分支的历史中出现一条「同步冲突」留痕。

**故事 4｜首次登录迁移本机数据**

本机已有 12 条分支、96 条提交 → 登录 → `/settings#sync` 显示「正在迁移 1/7 个集合」→ 中断后重新登录 → 从断点继续，不重头再来 → 完成后状态为「已同步」，其他设备看到完整数据。

**故事 5｜打开匿名统计**

`/settings#sync` 的「匿名使用统计」默认为关闭 → 用户打开 → 次日首次进入时上报前一日计数 → 设置页说明「只上报数字，不含标题、分支名、备注与任何业务内容」。

**故事 6｜关闭匿名统计**

用户关闭开关 → 停止后续上报，清空尚未发送的统计队列；不影响同步与其他功能。

**异常与边界**

- 未登录：`/settings#sync` 显示 V2-01 的 O07 行内提示与登录入口；不启动同步、不上报统计。
- 退出登录：停止同步与统计；本机已同步数据保留；outbox 中未推送项不再补推，恢复登录后继续。
- 网络不可用：所有写入仍落本机并立即可见；outbox 记录待推；界面不阻断编辑、不弹错误弹窗。
- 同步失败重试：指数退避，超过阈值后状态显示「同步失败」并提供手动重试；不丢失 outbox 记录。
- 服务端拒绝过期写入：采用服务端当前版本，本地被拒版本写入 `conflicts`，分支历史写一条留痕；不自动用本地版本覆盖服务端。
- 同一 `opId` 重试：服务端幂等，不产生重复记录。
- 迁移中断：按 `migration_state` 的集合与 `lastId` 续传；已迁移数据不重复写入。
- 迁移期间继续使用：本机写入照常，进入 outbox；迁移完成后再按顺序补推，不阻塞界面。
- 设备列表：当前设备始终可见；其他设备按 `lastSyncAt` 倒序；长时间未同步的设备标注「超过 7 天未同步」。
- 冲突记录不自动删除；本期不提供标记已读、恢复我的版本或手动合并，解决动作待后续定义。
- 匿名统计失败：静默重试，最多保留 7 天队列；不提示、不影响任何功能。
- 统计开关关闭后再打开：从打开次日起重新上报；不补报关闭期间的计数。
- 统计包字段固定白名单，任何标题、分支名、备注、实体 ID 都不得进入 payload。

## 4. 界面与交互

对应视图：**O08-sync-devices**、**O08-sync-conflict**；分区：`/settings#sync`。入口：P07 设置 → 同步分区；未登录时由 O07 引导登录。

### 4.1 同步分区（`/settings#sync`）

| 区块 | 内容 | 操作 |
| --- | --- | --- |
| 同步状态 | 已同步 / 同步中 / 离线待补传 N 项 / 同步失败；最近同步时间 | 立即同步、重试 |
| 设备列表 | 当前设备、其他设备的名称、平台、最近同步时间 | 查看设备明细（O08-sync-devices） |
| 冲突记录 | 最近冲突数量、时间、涉及对象 | 查看对照（O08-sync-conflict） |
| 匿名统计 | 开关、说明、上次上报日期 | 打开 / 关闭 |

- 未登录时整区显示 O07 行内提示，不显示上述区块的空壳与假数字。
- 同步状态由本机记录，不依赖轮询刷新页面；状态变化就地更新。
- 「立即同步」只在已登录且非同步中可用；离线时置灰并说明。

### 4.2 设备列表（O08-sync-devices）

- 列表项：设备名称、平台、最近同步时间、是否为当前设备。
- 当前设备固定第一行并标注「本机」；其他设备按最近同步时间倒序。
- 超过 7 天未同步的设备显示提示文字，不自动移除。
- 本期不提供移除设备、重命名设备、强制下线；字段 `removedAt` 保留但不在界面消费。

### 4.3 冲突记录（O08-sync-conflict）

- 列表项：时间、对象类型与名称、涉及字段、设备。
- 详情左右（窄屏上下）对照：
  - 本机版本：字段值、修改时间、设备。
  - 服务端版本：字段值、修改时间、设备。
  - 当前生效版本：服务端版本。
- 底部提供「在分支历史查看」，跳到对应分支 P04 并定位到留痕节点；对象不在分支下时（如设置）只显示对照，不提供跳转。
- 只读；本期不提供「改回我的版本」或手动合并。
- 无冲突时显示「没有同步冲突」，不显示空表头。

### 4.4 首次迁移

- 登录后首次进入 `/settings#sync` 显示迁移进度：已完成集合数 / 总集合数、当前集合、已推送条数。
- 迁移中允许离开页面，进度在本机继续；再次进入显示当前进度。
- 完成后显示一次性提示「本机数据已归属到账号」，并转为常态同步状态。
- 迁移失败：显示失败原因与「继续迁移」，从断点续传，不重头再来。

### 4.5 匿名统计

- 开关默认关闭；说明固定为「只上报每日提交数、活跃分支数与留存计数；不上报标题、分支名、备注与任何业务内容；可随时关闭」。
- 打开后次日首次进入工作区时上报前一日数据；当日多次进入不重复上报。
- 关闭后停止上报并清空未发送队列；设置页显示「已关闭」。
- 上报失败不显示错误，不阻塞任何操作。

### 4.6 五种状态

| 状态 | 表现 |
| --- | --- |
| 空 | 无冲突：显示「没有同步冲突」；无其他设备：只显示本机；未登录：显示 O07 登录提示 |
| 加载 | 同步中显示「同步中」与待补传条数；迁移显示集合进度；不整屏 spinner，不阻塞本机编辑 |
| 错误 | 同步失败：状态 + 重试；迁移失败：原因 + 继续；冲突读取失败：说明 + 重试；统计失败静默 |
| 只读 | 设备列表与冲突对照只读；本期不提供设备移除与冲突手动解决 |
| 无权限或未登录 | 显示 O07 行内提示与登录入口；不同步、不统计；本机功能不受影响 |

### 4.7 移动端

- 390 px：同步分区单列；设备列表与冲突记录为全屏面板，可返回。
- 冲突对照在窄屏上下排列，先本机后服务端，当前生效版本置顶标注。
- 同步状态与待补传条数在窄屏不截断；「立即同步」按钮可点区域不小于 44 px。

## 5. 数据与规则

| 表 | 字段 | 用途 |
| --- | --- | --- |
| `outbox` | `opId`、`entity`、`entityId`、`action`、`payload`、`baseRev`、`attempts`、`lastError`、`createdAt` | 本地先写后的待推队列、离线补传、幂等 |
| `conflicts` | `entity`、`entityId`、`branchId`、`field`、`localPayload`、`serverPayload`、`deviceId`、`localRev`、`serverRev`、`at`、`resolved`、`resolvedAt` | 冲突记录与对照 |
| `devices` | `_id`（设备 ID）、`ownerId`、`label`、`platform`、`lastSyncAt`、`createdAt`、`removedAt` | 设备列表与最近同步 |
| `migration_state` | `_id`（集合名）、`lastId`、`pushed`、`done`、`updatedAt` | 首次迁移断点续传 |
| `counters` | `_id`（事件名 + 日期）、`value` | 匿名统计计数器，只由云函数写 |
| `users` | `_id`（= `openid`）、`ownerId` | 同步主体，由 V2-01 提供 |
| `events` | `entityType='branch'`、`action='sync.conflict'`、`payload`、`at` | 分支历史留痕 |

规则：

- 本地先写：所有业务写入先落本机并立即对界面生效，同一事务写 `outbox`；界面不等云端返回。
- outbox 补推：按 `createdAt` 顺序推送；同一 `opId` 幂等；成功后标记已同步并从待推计数中移除。
- 同步范围：`branches`、`tasks`、`commits`、`milestones`、`badges`、`events` 参与同步；`settings`、`backups`、示例树、认证凭证、本机 UI 状态不同步。
- 冲突判定：服务端按 `baseRev` 拒绝过期写入；被拒后客户端采用服务端当前版本，把本地版本写入 `conflicts`，并在对应分支写一条 `sync.conflict` 事件。
- 冲突展示：`field` 为空表示整行冲突；对照读取 `localPayload` / `serverPayload`；`resolved` / `resolvedAt` 本期不写入，保留给后续的解决动作。
- 设备：每次成功同步更新当前设备的 `lastSyncAt`；设备名与平台只用于展示，不上报业务内容。
- 迁移：一次性、按集合分页、每批成功后写 `migration_state`；完成后云端为收敛点，但写入仍走「本地先写 + outbox」。
- 匿名统计白名单：`installId`、`localDate`、`commitCount`（当日有效提交数）、`activeBranchCount`（当日有有效提交的分支数）、`appVersion`、`platform`；不含标题、分支名、备注、实体 ID、账号 ID、邮箱。
- 留存由服务端按 `installId` 计算日留存，客户端不计算、不上报行为序列。
- 统计每天最多上报一次；失败队列最多保留 7 天；关闭开关即清空队列并停止。
- 同步与统计失败都不回滚本机写入，不影响四计数（R7）、今天分组（R8）、徽章（R18）与备份（R17）。

## 6. 验收标准

1. 两台设备登录同一账号，设备 A 完成一条待办后，设备 B 在 3 秒内看到新提交与分支计数变化；反向新建分支同样在 3 秒内可见。
2. 设备 A 断网后完成 3 条待办、修改 1 条分支名，界面立即生效且状态显示待补传 4 项；恢复网络后自动补推，状态回到已同步，设备 B 收到全部 4 项变更。
3. 同一操作因重试被推送两次，云端只保留一条记录，不产生重复提交或重复计数。
4. 两台设备同时修改同一条待办标题：后提交的一方界面显示服务端版本，`conflicts` 新增一条记录，对应分支历史新增一条 `sync.conflict` 留痕，不出现静默丢失。
5. 冲突记录详情显示本机版本与服务端版本的字段值、时间、设备，并标明当前生效版本；点「在分支历史查看」跳到对应分支并定位留痕节点。
6. 冲突记录刷新后仍存在、不自动删除；界面没有标记已读、恢复我的版本或手动合并入口，`resolved` 保持未写入状态。
7. 首次登录迁移本机 12 条分支与 96 条提交，迁移完成后另一设备看到完整数据；中途断网后重新登录从断点继续，已迁移集合不重复推送。
8. 迁移过程中继续新增待办：本机立即可见，迁移完成后该待办进入 outbox 并成功补推，不丢失、不重复。
9. 设备列表显示本机与其他设备的名称、平台、最近同步时间；超过 7 天未同步的设备有提示；本期没有移除设备入口。
10. 未登录访问 `/settings#sync` 显示 O07 登录提示，不显示同步状态、设备与冲突区块；本机功能不受影响。
11. 退出登录后停止同步与统计，本机已同步数据保留；重新登录后 outbox 继续补推。
12. 同步失败时状态显示「同步失败」并可手动重试；本机编辑始终可用，待补传条数不清零。
13. 打开匿名统计后，次日首次进入工作区上报一次；抓取上报内容只含 `installId`、`localDate`、`commitCount`、`activeBranchCount`、`appVersion`、`platform`，不含任何标题、分支名、备注、账号 ID、实体 ID。
14. 关闭匿名统计后不再上报，未发送队列被清空；重新打开后从次日起重新上报，不补报关闭期间的数据。
15. 统计上报失败不出现错误提示、不阻塞操作；队列最多保留 7 天。
16. 390 px 下同步分区单列可读，设备与冲突为可返回的全屏面板，冲突对照上下排列且当前生效版本置顶。

## 7. 依赖与阶段、未决问题

- 阶段：V2。
- 依赖：V2-01（登录、`principalId`、会话）、CloudBase 云数据库与云函数、0.12 的 `outbox` / `conflicts` / `devices` / `migration_state` / `counters` 表结构。
- 后续消费：V2-04 第二端只读同一账号数据；V2-03 帮助中的「换设备怎么办」引用本 PRD 与 V1-06。
- 冲突与处理：
  - `FRAMEWORK` J-07 的原文口径是「只上报计数器（日提交数、活跃分支数、留存），不上报任何内容（标题、分支名、备注一律不传），可开关」；用户已定阶段移入 V2。本 PRD 按该原文执行，未扩大采集范围。
  - `TECH-ARCHITECTURE` 把 `counters` 标注为「V1 用」，但 J-07 已移到 V2；本 PRD 按实际使用阶段在 V2 启用，表结构不变。
  - `FRAMEWORK` L-03 写「冲突以最后一次修改为准」；0.12 §4.6 写「服务端拒绝过期写入、客户端记入 `conflicts`、不静默丢弃」。两者合并为：服务端当前版本生效，本地被拒版本进入冲突记录，不自动覆盖。
  - 冲突的「解决动作」在索引里仍为未决；本 PRD 只做展示、已读与历史留痕，不提供手动合并。
- 未决问题：
  - 冲突记录是否需要「恢复我的版本」动作，以及恢复时如何生成新的 `baseRev`，未定。
  - `sync.conflict` 在分支历史中的具体文案与展示形态（事件行 / 标记）需与 M06 的历程样式对齐。
  - 匿名统计开关默认值：本 PRD 暂定默认关闭（隐私优先），需产品与合规确认。
  - 留存的具体口径（D1 / D7 / 活跃定义）由服务端确定；本 PRD 只要求计数，不固定算法。
  - 设备移除、重命名与强制下线未在 L-03 定义，`devices.removedAt` 暂不使用。
  - 同步范围中的 `settings` 与 `events` 是否全部跨设备一致：本 PRD 暂定 `events` 同步、`settings` 本机独立。
