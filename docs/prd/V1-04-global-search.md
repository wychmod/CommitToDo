# V1-04 全局搜索（V1）

## 1. 背景与目标

树长到几十条分支、几千条待办之后，「我记得写过这件事，但想不起挂在哪条线」会变成最常见的找回成本。全局搜索是纯本地的快速定位入口：按名称与文案前缀找分支、待办、有效提交与里程碑，结果带类型和归属，点开即到。

本 PRD 交付 O04 全局搜索：顶部入口与快捷键、四类对象的合并结果、归档历史开关、详情与历程定位。

目标：用户输入 2–4 个字，在 1 秒内看到相关对象并说清「它属于哪条线」；点一条结果能到对应详情或在历程中定位。

## 2. 范围与非目标

**范围**

- F-06 全局搜索：搜分支名、待办标题、提交文案、里程碑标题。
- 结果带类型与归属（分支路径 / 提交与里程碑的原始分支）。
- 可打开对应详情；提交与里程碑可改在历程中定位。
- 「包含归档历史」开关，默认关闭。
- O04 弹层；入口位于工作区顶栏，桌面支持 `Ctrl / ⌘ + K`。

**非目标**

- 不做全文索引、中文分词、拼音、模糊匹配、错字纠正、语义搜索。
- 不做搜索历史、热门词、联想补全。
- 不搜设置、徽章、事件、备份、示例树。
- 不做跨年批量导出搜索结果。
- 不改表结构、不新增索引；不引入搜索服务。

## 3. 用户故事与主流程

**故事 1｜按名字找回一条分支**

任意工作区页面按 `Ctrl / ⌘ + K` → 输入「跑」→ 结果分组显示分支「健康 / 跑步」→ 回车或点击 → 打开该分支详情，搜索弹层关闭。

**故事 2｜找一条待办**

输入「周报」→ 待办组出现「交周报」，右侧标注归属「工作 / 主业」与截止日期 → 点击打开待办详情。

**故事 3｜找一句提交文案**

输入「上线」→ 提交组出现「小程序 1.0 上线 —— 补一句」，标注原始分支与日期 → 点击打开提交详情；行尾「在历程查看」跳到 P04 并定位该节点。

**故事 4｜找一条旧分支的历史**

输入「考研」→ 默认结果中没有已归档的「2024 / 考研」→ 打开「包含归档历史」→ 结果出现该分支及其历史提交 → 点击进入只读详情。

**异常与边界**

- 查询为空白或只有空格：不展示结果，显示一句「搜分支、待办、提交、里程碑」。
- 无结果：显示「没有找到『xxx』」+「包含归档历史」开关，不显示空分组。
- 结果很多：按类型分组，每组最多 20 条，总计最多 50 条；超出时在该组底部显示「还有 N 条，输入更多字缩小范围」，不做无限滚动。
- 已撤销的提交：不出现；即使其文案前缀匹配。
- 已删除的分支/待办/里程碑（软删）：不出现。
- 示例树内容：不出现；搜索只覆盖真实数据。
- 已并入父分支的提交：以当前 `branchId`（父分支）作为归属显示，同时标注原始来源分支；不重复出现两次。
- 归档开关打开后，归档子树中的分支、待办、提交、里程碑都进入结果；关闭后全部排除。
- 查询包含换行或超长文本：取首行、截断到 100 字符后匹配。
- 搜索读取失败：弹层保留输入与开关，说明原因 + 重试。

## 4. 界面与交互

对应视图：**O04**（全局搜索弹层）。入口：工作区顶栏搜索按钮；桌面快捷键 `Ctrl / ⌘ + K`。

### 4.1 弹层结构

- 打开后焦点进入输入框，弹层覆盖主内容但不改变当前路由；`Esc` 关闭并把焦点还给触发控件。
- 输入框下方为结果区，按「分支 / 待办 / 提交 / 里程碑」顺序分组；空组不显示。
- 结果行固定四段：类型标记、标题、归属路径、日期或状态；提交与里程碑行尾提供「在历程查看」。
- 右上角或输入框下方放「包含归档历史」开关，默认关闭；开关状态在本次会话内保留，关闭弹层不清空。

### 4.2 匹配规则

| 对象 | 匹配字段 | 结果标题 | 归属 | 右侧信息 |
| --- | --- | --- | --- | --- |
| 分支 | `branches.title` | 分支名 | 父路径 | 状态（进行中 / 已合并 / 已放下 / 已归档） |
| 待办 | `tasks.title` | 待办标题 | 所属分支路径 | 截止日期或「无截止」 |
| 提交 | `commits.summary` | 提交文案 | 当前分支路径，标注原始来源 | 业务日期 |
| 里程碑 | `milestones.title` | 里程碑标题 | 所属分支路径 | 日期（按 `datePrecision` 展示） |

- 只做前缀匹配：查询去掉首尾空格后，从标题或文案开头匹配；不做包含匹配、不做模糊匹配。
- 拉丁字母不区分大小写；中文按字面匹配。
- 提交只取 `voidedAt == null`；分支、待办、里程碑排除 `deletedAt != null`。
- 默认排除祖先已归档的对象；开关打开后纳入。
- 结果排序：同组内按匹配字段长度升序（短标题优先），长度相同按时间倒序（分支按 `createdAt`，其余按日期或 `at`）。

### 4.3 打开与定位

| 对象 | 主操作 | 次操作 |
| --- | --- | --- |
| 分支 | 打开 P03 分支详情 | — |
| 待办 | 打开 O02 待办详情 | — |
| 提交 | 打开 O03 提交详情 | 在历程查看（P04，带入该分支与该日期） |
| 里程碑 | 打开 S04 里程碑详情 | 在历程查看（P04，带入该分支与该日期） |

- 主操作后关闭搜索弹层；返回时恢复原页面滚动与筛选。
- 「在历程查看」按 M06 的直达规则临时带入目标泳道与日期，并保留用户原筛选设置。

### 4.4 键盘

- `↑ / ↓` 在结果间移动，`Enter` 打开当前结果，`Esc` 关闭。
- `Tab` 在输入框与「包含归档历史」开关之间移动，不困在结果列表。
- 结果获得焦点时可见焦点环；屏幕阅读器可读出类型、标题与归属。

### 4.5 五种状态

| 状态 | 表现 |
| --- | --- |
| 空 | 输入为空：一句说明 + 四类对象示例；无结果：说明 + 归档开关 |
| 加载 | 输入后保留上一批结果并显示轻量加载态，不整屏 spinner；首字符输入不阻塞输入框 |
| 错误 | 读取失败：保留输入与开关，说明原因 + 重试；重试不清空查询 |
| 只读 | 搜索结果本身只读；打开已合并、已归档分支的详情时为只读态，按 M04 / V1-01 处理 |
| 无权限或未登录 | 不适用；V1 无账号，搜索不要求登录 |

### 4.6 移动端

- 390 px：搜索为全屏页，顶部输入框与关闭按钮，结果单列；不依赖快捷键。
- 「包含归档历史」放在结果区顶部一行，可点击切换。
- 行尾「在历程查看」收进行内「更多」，不依赖悬停。

## 5. 数据与规则

| 表 | 字段 | 用途 |
| --- | --- | --- |
| `branches` | `_id`、`parentId`、`path`、`title`、`status`、`archivedAt`、`createdAt`、`deletedAt` | 分支结果与归属 |
| `tasks` | `_id`、`branchId`、`title`、`dueDate`、`status`、`deletedAt` | 待办结果与归属 |
| `commits` | `_id`、`branchId`、`sourceBranchId`、`summary`、`date`、`at`、`voidedAt`、`deletedAt` | 提交结果与来源 |
| `milestones` | `_id`、`branchId`、`title`、`achievedAt`、`datePrecision`、`deletedAt` | 里程碑结果与日期 |

规则：

- 前缀匹配：`title.startsWith(query)` 或 `summary.startsWith(query)`；不做全文索引，依赖本地数据规模（分支 ≤200、待办数千）。
- 归档过滤：默认排除自身或祖先 `archivedAt != null` 的对象；开关打开后不过滤。归档不是状态，不能通过 `status` 判断。
- 有效提交：`voidedAt == null`；撤销的提交不进入结果，也不影响已撤销提交的文案检索。
- 归属路径：分支用 `path` 还原「工作 / 主业」；提交与里程碑用当前 `branchId` 的分支路径，并在提交行标注 `sourceBranchId` 对应的原始分支名（两者不同时）。
- 示例树使用独立命名空间，搜索的查询范围不包含它。
- 搜索不写 `events`、不落搜索历史、不产生计数。

## 6. 验收标准

1. 在任意工作区页面按 `Ctrl / ⌘ + K` 打开搜索，焦点在输入框；`Esc` 关闭后焦点回到触发控件。
2. 输入「跑」能搜到标题以「跑」开头的分支与待办；标题中间包含「跑」但开头不是的对象不出现。
3. 拉丁字母查询不区分大小写：输入「run」能匹配「Run 5K」。
4. 结果按分支、待办、提交、里程碑分组；每条显示类型、标题、归属路径与日期或状态。
5. 点击分支结果打开 P03，点击待办结果打开 O02，点击提交结果打开 O03，点击里程碑结果打开 S04；返回后原页面筛选与滚动位置保留。
6. 提交结果的「在历程查看」打开 P04 并定位该提交节点，且不覆盖用户原有筛选。
7. 撤销一条提交后，其文案不再出现在结果中；刷新前已打开的结果列表在下一次输入时同步消失。
8. 默认不出现已归档分支及其待办、提交、里程碑；打开「包含归档历史」后出现，关闭后再次消失。
9. 已并入父分支的提交只出现一次，归属显示父分支并标注原始来源分支。
10. 示例树中的分支与待办不出现在任何查询结果中。
11. 查询无结果时显示说明与归档开关，不显示空分组；输入为空时显示四类对象说明。
12. 结果超过上限时每组最多 20 条、总计最多 50 条，并提示输入更多字缩小范围。
13. 人为使读取失败：弹层保留查询与开关，显示重试；重试成功后结果恢复。
14. 390 px 下搜索为全屏页，输入框、归档开关与结果均可操作，无横向滚动。

## 7. 依赖与阶段、未决问题

- 阶段：V1。
- 依赖：M02（分支与路径）、M03（待办）、M05（提交文案与撤销）、M07（里程碑与日期精度）、V1-01（归档可见性）；M06 提供历程直达。
- 后续消费：无；搜索结果不进入任何统计与徽章。
- 冲突与处理：
  - `TECH-ARCHITECTURE` 明确搜索不做全文索引、不做模糊匹配：本 PRD 按前缀匹配写，验收也按前缀行为检查。
  - `FRAMEWORK` F-06 未写归档开关的默认值：本 PRD 定为默认关闭，遵循「归档退出默认视野」的既有口径。
  - `FRAMEWORK` F-06 写「可定位到对应详情或历程节点」：分支与待办只有详情，无独立历程节点；本 PRD 只对提交与里程碑提供历程定位。
- 未决问题：
  - 结果上限 20 / 50 为暂定值，需按真实数据量与弹层高度复核。
  - 是否需要在搜索中显示待办的完成状态（当前只显示截止日期），取决于行内空间。
  - 快捷键在 Windows 与 macOS 的提示文案是否需要分别展示，当前统一写 `Ctrl / ⌘ + K`。
