# V2-04 第二端只读（V2）

## 1. 背景与目标

V2 的第二端先不追求「随手记一笔」，只跑通一条可信的只读链路：用户在另一台设备或另一个端上，能看到今天要做什么、树长什么样、这条线发生过什么、这一年走了多远。写入、编辑、完成仍回到 Web 主端。

本 PRD 交付 L-04 的第二端只读范围、信息架构、状态与验收。端形态（小程序 / 桌面）与视觉稿尚未定案，本文只固定产品行为，不选技术栈、不新增页面编号。

目标：登录同一账号后，第二端能在正常网络下看到与主端一致的今天、分支树、分支详情、历程、年轮与徽章；任何写操作都不出现，也不出现「看起来能点但失败」的假入口。

## 2. 范围与非目标

**范围**

- 只读信息架构：今天、分支树、分支详情、历程、年轮、徽章墙、账号信息。
- 与 V2-01 / V2-02 共用登录与同步；数据来自同一账号。
- 只读状态、加载、错误、空数据、未登录拦截与返回路径。
- 窄屏优先的阅读布局。

**非目标**

- 不做任何写入：不新建分支、不添加 / 完成 / 编辑待办、不收尾、不放下、不归档、不改设置。
- 不做快速添加、语音输入、通知、提醒、分享、导出、备份、示例树。
- 不做离线写入与本地优先；第二端没有本机工作区，断网只读缓存由端能力决定。
- 不做独立视觉设计与新的页面编号；沿用现有信息架构与内容层级。
- 不做端形态选型、技术选型与发布渠道。
- 不新增表与字段。

## 3. 用户故事与主流程

**故事 1｜在手机上看看今天**

打开第二端 → 未登录，显示登录入口与一句「登录后查看你的树」→ 登录同账号 → 进入「今天」→ 看到逾期 / 今天 / 无截止三组与条数，与主端一致 → 点一条待办，打开只读详情。

**故事 2｜看一条线走到哪了**

「分支树」→ 三层树可展开 / 收起 → 点「工作 / 主业」→ 只读详情显示进度、待办、最近提交、子分支与里程碑 → 点一条提交，打开只读提交详情。

**故事 3｜翻一翻历程**

「历程」→ 默认最近 90 天 → 泳道、汇合点、停滞虚线按主端口径显示 → 切换分支筛选 → 筛选结果与主端一致。

**故事 4｜看今年的年轮**

「年轮」→ 默认当前年 → 四项指标、12 个月分布、一级分支占比与年度总结只读展示 → 年度总结不可编辑。

**故事 5｜主端刚改完，第二端刷新**

主端完成一条待办 → 第二端下拉刷新或重新进入 → 新提交与计数出现；页面显示「更新于 HH:mm」，不出现半新半旧的状态。

**异常与边界**

- 未登录：只显示登录入口、说明与返回；不显示任何业务数据，不提供「本机工作区」。
- 登录失败或会话失效：回到未登录态，保留当前意图路径，登录后回到原页面。
- 没有账号数据：今天显示空态「今天还没有要做的」；分支树只显示根分支或完全为空；历程与年轮显示空态；不显示示例树。
- 网络失败：已加载内容保留，页面顶部提示「网络不可用，显示上次内容」，提供重试；首屏无缓存时显示错误态。
- 数据延迟：主端写入后，第二端在同步延迟内可能仍是旧值；刷新后更新，不显示「保存成功」类回执。
- 只读内容被点击：所有条目可进入详情，但不出现编辑、完成、删除、收尾、放下、归档、置顶等入口。
- 已归档、已合并、已放下的分支按主端可见性呈现；归档内容不进入默认树，按 V1-01 的归档区口径只读浏览。
- 提交已撤销：文案保留并标注「已撤销」，不计入统计与计数。
- 统计口径与主端不一致时，以主端为准；第二端不自行计算另一套数字。
- 端能力不同导致布局差异时，内容与层级不得删减；仅允许折叠、分页与滚动。

## 4. 界面与交互

端形态与视觉稿未定，以下只固定信息架构与交互约束，页面名称沿用主端：今天（P01）、分支树（P02）、分支详情（P03）、历程（P04）、年轮（P05）、我的 / 徽章（P06）。

### 4.1 底部或主导航

- 固定四项：今天、分支树、历程、我的；年轮从历程进入，徽章墙从「我的」进入。
- 当前项高亮；不出现「记一笔」、搜索、设置等主端专属入口。
- 未登录时只显示「登录」与说明，不显示四项导航。

### 4.2 今天

- 三组顺序与主端一致：逾期 / 今天 / 无截止；组内顺序按主端 `order` 与默认规则。
- 页头显示「N 条有截止日期 · 另有 M 条无截止日期」。
- 每条显示标题、所属分支、截止日期；点击进入只读待办详情。
- 不显示勾选完成、行尾更多、安排到今天、取消等待写操作。
- 最近提交区只读，点击进入只读提交详情。

### 4.3 分支树与分支详情

- 三层树，可展开 / 收起；行内显示分支名、颜色、进度与状态；不显示拖拽、置顶、更多菜单。
- 分支详情只读展示：目标、进度、待办列表、最近提交、子分支、里程碑、已合并 / 已放下 / 已归档状态与原因。
- 待办行不显示完成按钮；提交行可进入提交详情；里程碑行可进入里程碑详情。
- 已归档子树从默认树隐藏，按归档区只读浏览。

### 4.4 历程与年轮

- 历程默认最近 90 天，泳道、分支筛选、停滞虚线与主端一致；窄屏改纵向时间线。
- 年轮默认当前年，可切换有数据的年份；四项指标、月度分布、分支占比与年度总结只读。
- 年度总结展示为文本，不提供编辑；空总结显示「这一年还没有写下总结」。

### 4.5 我的与徽章

- 显示账号邮箱、当前设备、最近同步时间；不显示退出登录以外的账号操作。
- 徽章墙按 V1-05 / V2-03 的分类与顺序只读展示；已获得与未获得状态一致；不显示「去今天」等写操作引导。
- 帮助入口可进入，内容与主端一致。

### 4.6 五种状态

| 状态 | 表现 |
| --- | --- |
| 空 | 今天无待办、树只有根、历程无节点、年轮无提交：各自空态与一句说明，不显示示例数据 |
| 加载 | 首屏保留导航与区块骨架；分页与刷新显示轻量加载，不整屏 spinner |
| 错误 | 首屏失败：说明 + 重试；已加载后失败：保留内容 + 顶部离线提示 + 重试 |
| 只读 | 全端只读是设计状态，不是降级；所有写入口不出现，不显示置灰的假按钮 |
| 无权限或未登录 | 只显示登录入口与说明；不展示任何业务数据；登录后回到原意图页面 |

### 4.7 窄屏与宽屏

- 以窄屏为主：导航固定在底部或顶部，内容单列；树用缩进 + 展开表达层级。
- 宽屏时内容区最大宽度受限，不把窄屏布局拉伸成整屏宽表。
- 触控目标不小于 44 px；不依赖悬停展示信息。

## 5. 数据与规则

| 数据 | 来源 | 用途 |
| --- | --- | --- |
| 账号与会话 | V2-01 的 `users` 与登录态 | 未登录拦截、账号信息 |
| 同步数据 | V2-02 的 `branches`、`tasks`、`commits`、`milestones`、`badges`、`events` | 今天、树、详情、历程、年轮、徽章 |
| 年度总结 | `year_reviews` | 年轮只读展示 |
| 设备与同步时间 | `devices` | 「我的」中的当前设备与最近同步 |

规则：

- 第二端只读：不写任何业务表、不写 `outbox`、不写 `events`、不上传统计以外的数据。
- 数据一致性：全部口径与主端相同——今天三组（R8）、有效提交（R3）、停滞（R4）、四计数（R7）、周月年（R9–R11）、徽章（R18）；第二端不另算。
- 归档可见性：默认树排除归档子树（R14），归档区只读；已合并与已放下按主端状态展示。
- 未登录：不读取业务数据；登录成功后按原意图页面进入，缺省到「今天」。
- 刷新：进入页面、下拉刷新与切换页签时拉取最新数据；不提供实时推送承诺。
- 缓存：允许端侧缓存上一次成功结果用于断网展示，必须标注「上次更新」时间；缓存不写入业务表。
- 只读详情与主端共用内容结构，不新增字段、不隐藏关键信息（如撤销标注、归档原因、放下原因）。
- 第二端不使用示例命名空间，不显示示例树与引导。

## 6. 验收标准

1. 未登录打开第二端，只看到登录入口与说明，看不到今天、分支树、历程、年轮或任何业务数据；登录后进入「今天」。
2. 登录后「今天」显示逾期 / 今天 / 无截止三组与页头两组计数，条数与主端一致；组内顺序与主端一致。
3. 今天页不出现勾选完成、行尾更多、快速添加、安排到今天等写操作；点击待办只能进入只读详情。
4. 「分支树」显示三层结构，可展开 / 收起；不出现拖拽、置顶、更多菜单与新建入口。
5. 分支详情显示目标、进度、待办、提交、子分支与里程碑；提交可进入只读详情；里程碑可进入只读详情。
6. 「历程」默认最近 90 天，泳道、分支筛选与停滞虚线与主端一致；窄屏为纵向时间线。
7. 「年轮」显示四项指标、12 个月分布、一级分支占比与年度总结；年度总结不可编辑。
8. 「我的」显示账号邮箱、当前设备与最近同步时间；徽章墙按已获得 / 未获得状态只读展示。
9. 主端完成一条待办后，第二端刷新能看到新提交与计数变化；页面显示「更新于 HH:mm」，不出现半新半旧。
10. 主端撤销一条提交后，第二端刷新显示「已撤销」，该提交不计入计数与统计。
11. 已归档分支不出现在默认树；归档区只读可浏览；已合并与已放下分支的状态、原因可查看。
12. 无账号数据时，各页显示空态与说明，不显示示例树、引导或模板。
13. 首屏网络失败显示错误与重试；已加载后断网保留内容并显示「网络不可用，显示上次内容」与更新时间。
14. 会话失效时回到未登录态；重新登录后回到失效前的页面，而不是固定回「今天」。
15. 全端不出现任何写入口，也不出现置灰的「完成」「编辑」「收尾」假按钮。
16. 窄屏下导航、树层级与触控目标可正常使用；宽屏内容区不被拉伸成整屏宽表。

## 7. 依赖与阶段、未决问题

- 阶段：V2。
- 依赖：V2-01（登录）、V2-02（同步数据与设备）、V1-05 / V2-03（徽章展示）、V1-01（归档可见性）。
- 后续消费：若第二端后续开放写入，需要单独 PRD，不在本文扩展。
- 冲突与处理：
  - `FRAMEWORK` L-04 写「小程序或桌面端，先跑通只读链路；端未定，V2 前定案」；本 PRD 不选端、不选技术栈、不新增页面编号，只固定只读范围与验收行为。
  - `UI-PAGES` 的 V2 登录原则是「本机入口始终可用」；第二端没有本机数据，因此本 PRD 定为「未登录只显示登录入口」，不提供本机工作区。这是端能力差异，不改变 Web 主端的本机优先原则。
  - `FRAMEWORK` L-04 的选择标准是「用户在哪里最容易随手记一笔」，但本期只读；该标准用于端选型，不作为本期验收条件。
- 未决问题：
  - 端形态（小程序 / 桌面）与视觉稿未定，页面布局与导航位置需端定案后补齐。
  - 第二端是否需要独立的「今天」缓存与离线阅读范围，取决于端能力。
  - 只读范围是否包含设置中的主题与密度（当前不包含，固定使用端默认）。
  - 后续是否开放「记一笔」写入，需单独立项并复用 V2-02 的 outbox 与冲突规则。

### 8.2 必须自动化的用例

本 PRD 无新增单测。

理由：第二端只读，不新增任何计算规则。今天三组（R8）、有效提交（R3）、停滞（R4）、四计数（R7）、周月年（R9–R11）与徽章（R18）全部由 `web/src/core` 的既有纯函数产出，V2-04 只消费同一结果，不复制也不另算。若为第二端新建同名单测，只是重复 M03、M06、V1-02、V1-05 已覆盖的规则，且无法证明「不出现写入口」这一只读约束；后者只能靠人工逐页核对，见 8.3 第 1 条。

### 8.3 只能人工验收

1. **只读约束逐页确认**：前置为登录有数据的账号；按「今天 / 分支树 / 分支详情 / 历程 / 年轮 / 我的 / 徽章 / 帮助」逐页检查；判定为任何页面都没有勾选、编辑、删除、收尾、放下、归档、置顶入口，也没有置灰假按钮，长按与下拉不出现写菜单；1440 与 390。为什么不能进单测：这是「不存在」的断言，单测只能覆盖已声明组件，漏掉整类入口无法自动发现。
2. **真实双端数据一致性**：前置为主端与第二端登录同账号；主端完成待办、撤销提交、新建分支后，第二端刷新；判定为新提交与计数出现、撤销项标注「已撤销」且不计入、树层级与主端一致，显示「更新于 HH:mm」且无半新半旧；1440。为什么不能进单测：需要两个真实端与云端同步时延。
3. **断网缓存与重试**：前置为成功加载一次；断网后刷新；判定为保留上次内容、顶部显示「网络不可用，显示上次内容」与更新时间、重试可用；冷启动断网显示错误态；1440 与 390。为什么不能进单测：依赖真实端侧缓存与网络状态切换。
4. **会话失效回跳**：前置为第二端已登录；使会话过期后点击深层页面；判定为回到未登录态并保留原路径，重新登录后回到失效前页面而不是「今天」；1440。为什么不能进单测：需要真实凭证过期与路由恢复。
