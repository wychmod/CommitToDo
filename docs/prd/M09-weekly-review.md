# M09 周回顾（MVP）

## 1. 背景与目标

周回顾不是让用户写总结，而是在周末把这一周的事实摆出来，并用一个问题让人停一下。它只读、只提问、不给建议、不接受输入，避免变成又一项待办。

目标：周六、周日打开今天页，能看到本周提交数、活跃分支数与连续提交周数，并读到一条由本周数据生成的提问；周一零点后自动消失。

## 2. 范围与非目标

**范围**

- G-01 周回顾：今天页卡片 + 展开面板；只在周六、周日出现；展示本周事实与一条提问。
- S01-week-review 视图。
- 统计口径：有效提交、活跃分支、连续提交周数。
- 提问由本周数据生成，只提问，不给建议，不可输入。

**非目标**

- 不做月回顾（V1-03）、年轮（V1-02）、分享图（V1-03）。
- 不做总结输入、心情记录、目标设定、提醒推送。
- 不做补看往周；错过周末不补。
- 不新增表或字段；统计现算。

## 3. 用户故事与主流程

**故事 1｜周六看到这周的事实**

周六打开 `/today` → 页面出现周回顾卡片，折叠态一行：「本周 9 次提交 · 3 条分支有进展」→ 点开 → 面板显示提交数、活跃分支数、连续提交周数，以及一句提问「这周大多给了『工作』，是你想投入的地方吗？」→ 读完关闭，不写任何内容。

**故事 2｜周一它自己消失**

周一 00:00 后打开今天页 → 卡片不存在，也不提示「上周回顾未读」→ 不提供补看入口。

**故事 3｜本周没有提交**

周六打开今天页 → 本周无有效提交，卡片不出现；不显示 0 次提交的空回顾。

**异常与边界**

- 周六日跨时区：按本机当前时区的自然日判断是否为周六/周日；周一 00:00 起不再出现。
- 提交在周末被撤销：统计随之减少；若撤销后本周为 0，卡片不再出现。
- 本周有提交但都在已归档分支：仍计入活跃分支与提交数，历史事实不因归档消失。
- 一条分支本周多次提交：活跃分支只计 1 次。
- 提问所需的分支数据缺失（分支已删除）：改用次高分支或退化为通用提问，不报错。
- 统计读取失败：卡片保留标题，面板内说明 + 重试；不显示 0。
- 用户在周六 23:59 打开、周一 00:01 仍停留：下次进入今天页时卡片消失，不做强制刷新打断。

## 4. 界面与交互

对应视图：**S01-week-review**，挂在 P01 今天页底部（桌面侧栏或主列底部，窄屏主列底部）。

### 4.1 卡片

- 折叠态一行：本周提交数 + 活跃分支数。
- 展开后显示三项事实：

| 指标 | 口径 |
| --- | --- |
| 本周提交 | 本周一 00:00 至当前时刻的有效提交数（R3） |
| 活跃分支 | 本周有至少 1 条有效提交的分支数，按分支去重；已放下分支不计入，已归档分支照常计入 |
| 连续提交周数 | 截至本周，连续有至少 1 条有效提交的周数；按周一至周日为一周 |

- 提问：只显示一句，由本周数据生成；不提供输入框、按钮选项、建议或评价。
- 提问选择：优先取本周提交最多的分支；并列时取最近一条提交所在的分支；仍并列按分支 `order`。
- 卡片可折叠，展开状态不持久化；关闭后本次会话不再自动展开。

### 4.2 出现规则

- 仅在本机时区周六、周日出现。
- 周一 00:00 起不再出现；不补看、不提醒。
- 本周无有效提交时不出现。
- 今天页其他区块（清单、最近提交、停滞提醒）顺序不变，周回顾固定在其后。

### 4.3 五种状态

| 状态 | 表现 |
| --- | --- |
| 空 | 非周末或本周无提交：整个卡片不渲染，不留空位 |
| 加载 | 周末首次进入显示卡片骨架；不阻塞今天清单 |
| 错误 | 卡片保留标题，展开面板说明读取失败 + 重试；不显示 0 |
| 只读 | 周回顾本身只读，不提供任何写入 |
| 无权限或未登录 | 不适用；MVP 无账号 |

### 4.4 移动端

- 390 px 下卡片位于今天清单之后、最近提交之前或之后按 M03 的侧栏合并顺序；不悬浮遮挡底部导航。
- 展开后面板高度自适应，不横向滚动；提问文本完整可读。

## 5. 数据与规则

| 表 | 字段 | 用途 |
| --- | --- | --- |
| `commits` | `date`、`at`、`branchId`、`voidedAt` | 本周提交数、活跃分支、连续周数 |
| `branches` | `order`、`status`、`archivedAt` | 提问选择、归档分支仍计入 |
| 页面上下文 | 本机当前时区与日期 | 判断周六/周日、周边界 |

规则：

- R3 有效提交：只统计 `voidedAt == null`。
- R9 周回顾：仅周六、周日出现；本周为周一 00:00 至周日 23:59（本地时区）；统计提交数、活跃分支数、连续提交周数；活跃分支不计已放下、已归档照常计入；只生成一个问题；不提供建议、不可输入；周一 00:00 后不再出现，跨周不补。
- 活跃分支按 `branchId` 去重；合并后的提交按当前 `branchId` 归属，不重复计父与子。
- 连续周数：从本周往前逐周检查是否有有效提交，遇到第一个空周停止；本周无提交时卡片不出现，不展示断掉的连续数。
- 所有统计现算，不落库、不写 `counters`。
- 提问文案只引用事实（分支名、次数、周数），不做评价、不使用「应该」「建议」。

## 6. 验收标准

1. 周六或周日打开 `/today`，今天页出现周回顾卡片；折叠态显示本周提交数与活跃分支数。
2. 周一 00:00 后打开今天页，卡片不出现，也没有「上周未读」或补看入口。
3. 本周提交 3 次，全部属于同一条分支，面板显示提交 3、活跃分支 1、连续周数按实际计算。
4. 本周提交分布在 2 条分支，活跃分支显示 2；同一分支多次提交不重复计数。
5. 撤销本周一条提交后，提交数与活跃分支数同步减少；若本周变为 0，卡片不再出现。
6. 已归档分支上的本周提交仍计入提交数与活跃分支数；已放下分支的提交仍计入提交数，但不计入活跃分支数。
7. 面板只出现一个问题，没有输入框、选项、建议或评价文案。
8. 提问指向本周提交最多的分支；并列时取最近提交所在分支。
9. 连续提交周数按周一到周日计算，遇到空周即停止。
10. 统计读取失败时卡片保留标题，面板给出重试，不显示 0。
11. 390 px 下卡片不遮挡底部导航，提问完整可读。

**最值钱的回归用例**：`week-review.test.ts` 里的「周一 00:00 起不出现、连续周数遇空周即停」守的是两周口径混用这一类 bug——把周一当周首、周日 23:59 的提交算进下一周，或把历史上所有有提交的周都算成连续，结果周回顾在周一仍出现、连续周数永远偏大。手工点页面时几乎发现不了：卡片只在周末出现一次，跨周要等到下周一，且「连续 7 周」与「连续 9 周」在界面上都只是一个数字，没有对照物。

说明：周回顾全部统计现算、不落库，Dexie 读取与 `useLiveQuery` 刷新按 AGENTS.md 口径不进单测，由 8.3 覆盖；本 PRD 不写 `counters`，`counters.test.ts` 无需扩展。

### 8.3 只能人工验收

1. **周末出现与周一消失**：前置 本周有 2 条有效提交；操作 周六、周日各打开一次 `/today`，周一 00:00 后再打开；判定 周六日出现卡片、周一不出现且无「上周未读」或补看入口；1440 与 390 各一次。为什么不能进单测：判定依赖本机真实日期与自然日翻转，单测只能注入固定日期。
2. **骨架不阻塞清单**：前置 工作区有今天待办；操作 节流网络后进入 P01；判定 卡片骨架出现时清单可操作、加载完成后卡片与清单行高不跳动。为什么不能进单测：加载态与布局跳动只能在真实渲染下观察。
3. **展开面板与窄屏**：前置 卡片已出现；操作 390 px 展开再关闭；判定 提问完整可读、不横向滚动、不遮挡底部导航，关闭后回到折叠行。为什么不能进单测：遮挡与滚动是视觉结果。
4. **提问文案审读**：前置 某一级分支本周 6 条提交、其余分支各 1 条；判定 提问指向该分支，只引用事实，不出现「应该」「建议」与评价句，面板无输入框与按钮选项。为什么不能进单测：文案语气的审读无法由断言表达。
5. **读取失败与重试**：前置 本周有提交；操作 在 DevTools 中使 IndexedDB 读取失败；判定 卡片保留标题、面板说明 + 重试、不显示 0；恢复后重试显示真实数字。为什么不能进单测：需在浏览器内制造 Dexie 读取失败。
