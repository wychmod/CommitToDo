# M04 分支详情（MVP）

## 1. 背景与目标

分支详情是一条线的档案页：它回答「这条线要做什么、做到哪了、发生过什么」。用户从这里判断是否继续、是否收尾，因此本页必须同时给出目标、自己的待办进度、待办、提交、子分支和里程碑，而不是把信息打散到多个页面。

目标：从分支树点进任意分支，能在同一页读完这条线的现状与历史，并能就地编辑目标、添加待办、打开提交与子分支。

## 2. 范围与非目标

**范围**

- D-02 分支详情五项：一句目标（可直接编辑）、待办、提交、子分支、进度（仅本分支自己的待办完成比例，不含子分支）。
- P03 分支详情 `/branches/:id`，含里程碑行。
- 从详情进入子分支详情、打开待办详情（O02）、打开提交详情（O03）、添加待办（复用 O01/O02）、新建子分支（复用 B03）、进入收尾（M08）。
- 已合并、已放下、已归档分支的只读呈现。

**非目标**

- 不做提交文字纠错与撤销（M05）；不做里程碑新建与详情（M07）；不做收尾确认（M08）；不做放下 / 归档 / 重新开始（V1-01）。
- 不做子分支提交的汇总进度：进度只算本分支自己的待办。
- 不新增页面、不改表结构。

## 3. 用户故事与主流程

**故事 1｜看一条线现在怎么样**

`/branches` 点「工作 / 主业」→ 详情页显示路径与状态、目标「把主业做稳」、进度 4/9、9 条待办、最近提交、3 条子分支、最近里程碑 → 用户判断这条线还需不需要继续。

**故事 2｜写一句目标**

详情页目标为空，显示「写一句这条线的目标」→ 点击就地编辑 → 输入并保存 → 页头立即显示新目标，刷新后保留。

**故事 3｜在分支里加一条待办**

详情页待办区点「添加待办」→ 复用快速添加面板，父分支预填当前分支 → 保存后待办出现在本分支待办区，进度分母 +1。

**故事 4｜看一条子分支**

子分支区点「小程序 1.0」→ 进入它的详情；面包屑与返回落到父分支详情。

**故事 5｜看这条线已经合并**

打开一条 `status=merged` 的分支 → 页头显示「已合并到『工作』· 11 月 13 日」→ 待办、提交、子分支只读，目标不可编辑，不显示收尾入口。

**异常与边界**

- 分支不存在或已物理删除（空分支删除）：显示应用内 404，提供「回分支树」，不白屏。
- 分支属于已归档子树：页面可打开但整体只读，顶部说明「已归档，只读」。
- 进度分母为 0：显示「还没有待办」，不显示 0% 或空进度条。
- 提交分页加载失败：保留已加载部分，底部提供重试；不清空列表。
- 目标保存失败：保留输入并就地提示，不关闭编辑态。
- 从详情新建子分支失败：保留表单，见 M02 的校验与反馈。
- 父分支收尾后子分支被并入：详情中的状态与提交来源标注随数据更新，不缓存旧状态。

## 4. 界面与交互

对应页面：**P03**（`/branches/:id`）。

### 4.1 页头

| 元素 | 内容 |
| --- | --- |
| 路径 | `工作 / 主业`，可点上级返回 |
| 名称与色相 | 分支名 + 所属色相标记；与树、历程一致（K-03） |
| 状态 | 进行中 / 已合并到「父分支」· 日期 / 已放下 · 原因（V1） / 已归档（附加标记） |
| 目标 | 一句话；空时显示占位文案；点击就地编辑，保存/取消 |
| 进度 | 本分支自己的 `taskDone / taskTotal`，如 4/9；不含子分支 |
| 操作 | 「更多」菜单：新建子分支、重命名、移动、收尾（M08）；V1 追加放下、归档 |

### 4.2 待办区

- 只列 `branchId` 等于本分支的待办，按状态与截止日期排序；已完成与已取消默认不混在未完成列表中。
- 每行可打开 O02 详情；行尾菜单提供「安排到今天 / 移出今天 / 取消」。
- 顶部「添加待办」打开快速添加（O01），父分支预填。
- 已合并、已放下、已归档分支：列表只读，完成与编辑不可用，写明原因。

### 4.3 提交流

- 按 `branchId` 查询，按 `date` 倒序分页，每页 20 条；只显示 `voidedAt == null` 的有效提交（R3）。
- 合并后，子分支提交的 `branchId` 已改为父分支，因此出现在父分支提交流；当 `sourceBranchId != branchId` 时标注原始来源（如「来自 主业」）。
- 每条显示日期与时刻（如「2026 年 11 月 20 日 16:42」），不显示短 hash 或内部 ID（R5）。
- 点击进入提交详情（M05）；已归档分支的提交仍可查看，纠错按 M05 的当天规则处理。

### 4.4 子分支区

- 列出直接子分支：名称、状态、自己的进度；点击进入对应详情。
- 顶部「新建子分支」，复用 B03，父分支预填。
- 已合并但仍留在默认树的子分支照常显示；已归档子树不在默认树中，从归档视图或历程进入。
- 无子分支时给一句说明 + 「新建子分支」。

### 4.5 里程碑行

- 显示本分支最近若干个里程碑，格式只含日期与标题；`datePrecision=day` 显示「11 月 16 日」，`month` 显示「2026 年 11 月」（R6）。
- 点击打开 S04 里程碑详情（M07）；新建入口在 M07，本页只提供入口按钮。
- 里程碑不计入 `ownLastCommitAt`，不影响停滞判定。

### 4.6 五种状态

| 状态 | 表现 |
| --- | --- |
| 空 | 各区块独立空态：无待办 →「添加待办」；无提交 →「完成一条待办后会出现在这里」；无子分支 →「新建子分支」；无里程碑 →「新建里程碑」；目标为空 → 占位文案 |
| 加载 | 保留页头与区块骨架；提交分页加载不遮挡页头 |
| 错误 | 页头读取失败 → 应用内 404；提交分页失败 → 保留已加载并重试；写入失败 → 保留输入 |
| 只读 | 已合并 / 已放下 / 已归档 / 所属祖先已归档：所有写操作不可用并写明原因；提交仍可查看 |
| 无权限或未登录 | 不适用；MVP 无账号 |

### 4.7 移动端

- 390 px：单列顺序为页头 → 进度 → 待办 → 提交 → 子分支 → 里程碑。
- 目标编辑、待办详情、提交详情、子分支新建均使用全屏面板，保留关闭入口。
- 提交分页使用「加载更多」，不横向滚动。

## 5. 数据与规则

| 表 | 字段 | 用途 |
| --- | --- | --- |
| `branches` | `_id`、`parentId`、`path`、`depth`、`title`、`goal`、`color`、`status`、`archivedAt`、`finishedAt`、`finishedIntoId`、`droppedAt`、`dropReason`、`taskTotal`、`taskDone`、`commitCount`、`ownLastCommitAt` | 页头、进度、状态、只读判断 |
| `tasks` | `branchId`、`title`、`status`、`dueDate`、`plannedDate`、`completedAt`、`cancelledAt` | 待办区、进度分子分母 |
| `commits` | `branchId`、`sourceBranchId`、`date`、`at`、`summary`、`voidedAt` | 提交流、来源标注 |
| `milestones` | `branchId`、`title`、`achievedAt`、`datePrecision` | 里程碑行 |
| `events` | `entityType='branch'`、`action`、`payload`、`at` | 分支历史与目标修改留痕 |

规则：

- R7：进度只算本分支、不含后代；`taskTotal` 不含 `cancelled` 与已删除；`taskDone` 只算 `done`；提交数只算有效提交。
- R3：提交流与计数只用 `voidedAt == null` 的提交。
- R5：提交只显示日期与时刻，不显示短 hash 或 `_id`。
- R6：里程碑按 `datePrecision` 渲染，不补虚构的日。
- 合并口径：提交并入父分支后 `branchId` 改父、`sourceBranchId` 保留原分支；因此「合并前父分支只显示自己的提交，合并后才出现子分支提交」由数据本身表达，不在查询里加时间条件。
- 目标：`goal` 为空字符串或 `null` 时显示占位；保存写 `goal` 与 `updatedAt`，并写一条 `events`。
- 只读判定：`status != active` 或 `archivedAt != null`，或任一祖先已归档。

## 6. 验收标准

1. 从 `/branches` 点分支名称进入 `/branches/:id`，页头显示路径、名称、状态、目标与进度。
2. 目标为空时显示占位文案；输入一句并保存后页头立即更新，刷新后仍在；保存失败时输入保留。
3. 进度显示本分支自己的 `taskDone / taskTotal`，不含子分支待办；在子分支完成一条待办，父分支进度不变。
4. 待办区只出现本分支待办；点击打开 O02；「添加待办」保存后出现在本分支，进度分母 +1。
5. 提交流只显示有效提交，按日期倒序，每页 20 条；点击进入 O03；合并后父分支提交流出现子分支提交并标注「来自 X」。
6. 提交行显示「2026 年 11 月 20 日 16:42」形式，不出现短 hash 或内部 ID。
7. 子分支区点击进入对应详情；返回落到父分支详情；新建子分支成功后即时出现。
8. 里程碑行只显示日期与标题；`month` 精度的里程碑显示「2026 年 11 月」，不显示具体日；点击打开 S04。
9. 打开 `status=merged` 的分支：页头显示合并去向与日期，目标、待办、子分支不可编辑，收尾入口不出现。
10. 打开已归档分支：顶部显示「已归档，只读」，所有写操作不可用，提交仍可查看。
11. 打开不存在或已删除的分支：显示应用内 404 与「回分支树」，不白屏。
12. 无待办、无提交、无子分支、无里程碑时，各区块分别出现对应空态与动作，不合并成一条大空态。
13. 390 px 下按页头 → 进度 → 待办 → 提交 → 子分支 → 里程碑单列显示，编辑面板可关闭。

  - 已放下分支的待办在详情中如何排序（按原截止日期还是原顺序）未定义，V1-01 前需确认。
