# V1-06 备份、快照与异地恢复（V1）

## 1. 背景与目标

MVP 的数据安全依赖用户自己记得导出。V1 要把「记得」变成默认动作：每天第一次打开自动留一份本机快照，保留最近 7 份；随时可以立即备份；恢复某个时间点时，先把当前状态也备份一份，避免「恢复错了就回不去」；换设备时可以上传 / 下载一个明文备份包。

本 PRD 交付 J-02 每日快照与备份库、J-05 快照恢复、J-06 异地备份，以及 P08 的 V1 分区、S08-data-v1、S08-snapshot-restore。

目标：用户不需要理解备份机制，也能在误删、误导入或换设备后回到某个可用时间点；任何备份或恢复失败都不破坏现有数据。

## 2. 范围与非目标

**范围**

- 每日首次进入工作区自动写一条本机快照，保留最近 7 条自动快照。
- 「立即备份」手动写一条快照。
- 快照列表：自动 7 条、手动 7 条、恢复前 1 条、异地 1 条，按时间倒序单列表展示，自动行浅色区分；每行显示时间、类型、分支数、待办数、提交数、`schemaVersion`。
- 按快照恢复：恢复前自动写一条恢复前副本；整体替换；重算四计数。
- 异地备份：按匿名设备归档的上传 / 下载，明文 JSON，含 `schemaVersion`。
- P08 V1 分区、S08-data-v1、S08-snapshot-restore；M10 的导出 / 导入 / 清空不变。

**非目标**

- 不做云端账号、设备登录、双向同步、增量备份、端到端加密（V2）。
- 不做自动清理策略的可配置项；不做备份加密与密码保护。
- 不做快照内容的逐条浏览或选择性恢复；快照恢复是整体替换。
- 不做跨用户共享、公开链接、团队备份。
- 不新增表；`backups` 表随本 PRD 启用，字段沿用 0.12。
- 不改 M10 的从文件恢复硬门槛与 `schemaVersion` 规则。

## 3. 用户故事与主流程

**故事 1｜今天第一次打开，自动留了一份**

上午打开工作区 → 后台写一条 `auto` 快照 → `/data` 列表顶部出现「今天 09:12 · 自动 · 12 条分支 / 8 条待办 / 96 条提交」→ 用户无需操作。

**故事 2｜恢复两小时前的状态**

`/data` → 选择「今天 09:12 自动」→ 面板显示日期、类型、各实体数量、`schemaVersion` → 确认框写明「当前数据会先自动备份为恢复前副本」→ 确认 → 系统先写 `pre-restore` 快照，再整体替换 → 页面重载，数据回到 09:12 的状态。

**故事 3｜恢复失败，现有数据还在**

恢复写入中途失败 → 页面提示失败原因，当前数据保持恢复前的状态；`pre-restore` 快照仍可在列表中找到。

**故事 4｜手动留一份再做大改**

在导入或整理分支前点「立即备份」→ 列表新增一条手动快照，显示「刚刚 · 手动」→ 之后可以从这条恢复。

**故事 5｜换一台电脑**

`/data` →「异地备份」→「上传当前备份」→ 提示「文件为明文 JSON，包含全部分支、待办、提交、里程碑、徽章与设置」→ 确认上传 → 得到一份按匿名设备标识的备份 → 在新设备打开同一页 → 下载该备份包 → 走 M10 的从文件恢复流程。

**异常与边界**

- 当日已写过自动快照：再次打开不重复写；跨自然日后第一次打开再写一条。
- 自动快照写入失败：不阻断进入工作区，不弹错误；`/data` 显示「今天还没有自动备份」与「立即备份」。
- 快照数量超过 7 条：删除最旧的一条自动快照；手动、恢复前与异地备份不参与自动淘汰。
- 快照中的 `schemaVersion` 与应用当前版本不一致：不可恢复，行内说明「版本不一致，无法恢复」，不提供确认按钮。
- 恢复前写 `pre-restore` 快照失败：中止恢复，现有数据不变，提示可重试。
- 恢复后：分支、待办、提交、里程碑、徽章、设置、事件全部以快照为准；四计数按 R7 全量重算；页面重载到 `/today`。
- 恢复后当前会话的筛选、滚动、展开状态清除；主题以快照中的设置为准。
- 上传时断网或失败：保留本地数据与快照，提示可重试；不产生半份远端文件。
- 下载失败或文件不完整：不进入恢复流程，提示重试；现有数据不变。
- 异地备份只存文件，不解析、不合并、不推送回本机；下载后仍走「从文件恢复」。
- 未登录、无账号：全部备份与恢复都不要求登录；异地备份用匿名设备标识，不采集邮箱或身份。
- 上传前必须显示明文提示；用户确认后才上传。

## 4. 界面与交互

对应页面：**P08**（`/data`，V1 分区）。视图：**S08-data-v1**、**S08-snapshot-restore**。

### 4.1 P08 V1 分区

| 区块 | 内容 | 操作 |
| --- | --- | --- |
| 数据概览 | 分支 / 待办 / 提交 / 里程碑 / 徽章数量；最近一次备份时间与类型 | 刷新 |
| 备份列表 | 自动 7 条 + 手动 7 条 + 恢复前 1 条 + 异地 1 条，单列表按时间倒序，不分组、不合并；自动行浅色区分；每行显示时间、类型、分支数、待办数、提交数 | 立即备份、从快照恢复、下载异地包、删除远端包 |
| 异地备份 | 上传当前备份的入口与明文说明；上传成功后以「异地」行进入备份列表，不再单列第二份列表 | 上传当前备份 |
| 文件 | M10 的导出、从文件恢复、清空本机数据 | 保持不变 |

- 快照行不显示内部 ID、文件路径或技术字段。
- 列表不设 10 行上限；四类同时存在时最多 16 行，滚动查看。
- 自动行使用浅色样式区分，手动、恢复前、异地行使用常规样式；类型以文字标注，不只靠颜色。
- 备份新鲜度：最近一次备份超过 7 天时，在页头显示一行提示「已经 7 天没有备份」，不阻断任何操作。
- 「立即备份」成功后列表即时新增一行，并给一次轻提示。

### 4.2 从快照恢复（S08-snapshot-restore）

- 选择快照后，面板显示：快照时间、类型、`schemaVersion`、分支数、待办数、提交数、里程碑数、徽章数。
- 确认文案必须写明三件事：将整体替换当前全部数据、不合并；当前数据会先自动备份为「恢复前副本」；恢复后页面会重新加载。
- 版本不一致时只显示摘要与原因，不显示确认按钮。
- 执行顺序：写 `pre-restore` 快照 → 校验快照完整性 → 整体替换 → 重算四计数 → 重载。
- 任一步失败：中止后续步骤，现有数据不变，说明失败发生在哪一步并可重试。
- 成功后不保留「最近导出时间」等旧会话状态。

### 4.3 异地备份

- 首次使用显示说明：明文 JSON、含全部数据、服务端只存文件、不做加密、不要求账号；上传按匿名设备标识归档。
- 「上传当前备份」：生成与导出同结构的明文 JSON，显示实体数量，确认后上传；上传中显示进度，可取消。
- 上传成功后，异地记录以「异地」行进入统一备份列表，显示匿名设备标签（如「本机 · Chrome」）、上传时间、分支数、提交数、`schemaVersion`；行内提供下载与删除。
- 列表只保留最近 1 条异地记录；新的上传成功后替换该行，不做多设备并列。
- 下载得到与导出格式一致的 JSON 文件；提示「下载后请按从文件恢复导入」。
- 离线或上传失败：不改变本机数据，不生成空记录。

### 4.4 五种状态

| 状态 | 表现 |
| --- | --- |
| 空 | 尚无快照：显示「今天还没有自动备份」+「立即备份」；无异地备份：一句说明 + 上传入口 |
| 加载 | 概览与快照列表保留行高骨架；上传 / 恢复显示进度，不整屏 spinner |
| 错误 | 自动备份失败：不阻断工作区，`/data` 说明；快照读取失败：说明 + 重试；恢复或上传失败：保留现有数据并说明 |
| 只读 | 快照与异地备份列表本身只读；只有恢复、下载、删除远端包等显式动作 |
| 无权限或未登录 | 不适用；V1 无账号，备份与恢复不要求登录，异地备份不采集身份信息 |

### 4.5 移动端

- 390 px：快照列表单列，时间与三项数量分两行显示；恢复确认与上传确认为全屏步骤页，可返回。
- 下载按钮与删除远端包保持间距，删除需二次确认。
- 文件选择与下载调用系统能力，不依赖悬停。

## 5. 数据与规则

| 表 | 字段 | 用途 |
| --- | --- | --- |
| `backups` | `_id`、`kind`、`createdAt`、`branchCount`、`taskCount`、`commitCount`、`schemaVersion`、`bytes`、`restoredAt`、`remoteKey`、`payload` | 快照元数据、列表、恢复、异地备份 |
| `branches` / `tasks` / `commits` / `milestones` / `badges` / `settings` / `events` | 全量 | 快照正文与恢复目标 |

规则：

- R17 备份：每日首次打开写一条 `kind=auto`；只保留最近 7 条 `auto`；恢复前先写 `kind=pre-restore`；快照记录分支数、待办数、提交数与 `schemaVersion`；`payload` 为明文 JSON；异地备份在对象存储留一份，元数据进 `kind=remote`。
- 快照正文：与 M10 的导出文件同结构，包含全部分支、待办、提交、里程碑、徽章、设置、事件；不含示例树与设备凭证。
- 保留策略：`auto` 最近 7 条；`manual` 最近 7 条；`pre-restore` 与 `remote` 各保留最近 1 条，四类合计最多 16 条。`auto` 超限时只淘汰最旧的 `auto`，不淘汰手动、恢复前与异地记录。
- 备份列表：四类合并在一个列表，按 `createdAt` 倒序展示，不分组、不合并、不截断；自动行使用浅色样式，类型以文字标注。
- 「距上次备份超过 7 天时补一份」：首次进入工作区时若最近一条任意类型备份早于 7 天前，除当日 `auto` 外再写一条 `auto`，仍受 7 条上限约束。
- R7 四计数：恢复完成后按快照中的数据全量重算 `branches` 的四个计数，不信任快照中的旧计数。
- R3 有效提交：恢复保留 `voidedAt`；已撤销提交仍不计入统计、历程与徽章条件。
- `schemaVersion`：快照与异地备份必须记录；恢复前比对，不一致则拒绝，不做迁移、不猜测缺失字段。
- 恢复为整体替换：单事务或可回滚；任一步失败保持现有数据；成功后写入当前快照的 `restoredAt`。
- 异地备份：只做整包上传 / 下载，不解析远端内容、不回写本机、不参与 `syncState` 与 outbox；不要求账号，按匿名设备标识归档；明文存储，无客户端加密。
- 备份与恢复不写徽章、不触发任何奖励判定；不进入四计数与统计。
- 导出、导入、清空（M10）与快照互不影响；清空本机数据时一并清除本机快照与异地备份的本机元数据，远端文件是否删除由用户单独操作。

## 6. 验收标准

1. 当日第一次进入工作区后，`backups` 新增恰好 1 条 `kind=auto`，记录分支数、待办数、提交数与 `schemaVersion`；同日再次进入不新增。
2. 连续 8 天每天首次进入，`auto` 快照始终为 7 条，最旧的一条被淘汰；手动与恢复前快照不被淘汰。
3. 「立即备份」新增一条 `kind=manual`，列表显示时间、类型、分支数、待办数与提交数。
4. 当自动 7 条、手动 7 条、恢复前 1 条、异地 1 条同时存在时，备份列表共 16 行，按时间倒序单列展示，自动行浅色区分，无分组、无合并、无截断。
5. 点某条快照恢复，确认面板显示时间、类型、`schemaVersion` 与各实体数量；确认后先新增一条 `kind=pre-restore`，再完成替换并重载。
6. 恢复后分支、待办、提交、里程碑、徽章与设置与快照一致；四计数按 R7 重算，与直接统计结果一致。
7. 恢复后已撤销提交仍为已撤销，不进入统计；徽章不因恢复重新发放。
8. 模拟恢复写入中途失败：现有数据完整保留，`pre-restore` 快照存在，页面提示失败并可重试。
9. 模拟写 `pre-restore` 快照失败：恢复不执行，现有数据不变，提示可重试。
10. 选择 `schemaVersion` 不一致的快照：不可恢复，行内与面板均说明版本不一致，无确认按钮。
11. 最近一次备份早于 7 天时，P08 页头显示备份新鲜度提示，且不阻断导出、恢复与其他操作。
12. 异地备份上传成功：统一备份列表新增一条「异地」行，显示匿名设备标签、上传时间、分支数、提交数；本机数据与快照不变；再次上传成功后该行替换为最新一条。
13. 在另一干净浏览器下载该备份包并走从文件恢复，数据完整恢复；远端备份不直接写本机、不产生 outbox 记录；列表行内可下载与删除远端包。
14. 上传或下载断网失败：本机数据不变，无半份记录，提示可重试。
15. 未登录状态下可完成快照、恢复、上传与下载；界面不出现登录要求，不采集邮箱或身份字段。
16. 上传前出现明文提示；未确认时不上传。
17. 390 px 下备份列表单列可读，最多 16 行可滚动；恢复与上传确认为可返回的全屏步骤页。

## 7. 依赖与阶段、未决问题

- 阶段：V1。
- 依赖：M10（导出结构、`schemaVersion`、从文件恢复）、M01（设置与本机状态）；`backups` 表随本 PRD 启用；异地备份依赖 V1 已定的云函数与对象存储能力。
- 后续消费：V2-02 的同步与迁移不读取 `backups`；快照与异地备份在 V2 仍保留为独立兜底。
- 冲突与处理：
  - `TECH-ARCHITECTURE` Q8 写「只取最近 7 条 auto 与最近一条 pre-restore / remote」，未提 `manual`，并把列表压在 10 行以内。**已定：不截断、不合并。** 保留自动 7 条 + 手动 7 条 + 恢复前 1 条 + 异地 1 条，四类按时间倒序单列表展示，自动行浅色区分；Q8 的 ≤10 行不再作为约束。
  - `FRAMEWORK` J-02 写「距上次备份超过 7 天时补一份」；在每日自动快照已存在的前提下，本 PRD 解释为「长时间未打开后首次进入时补一条」，仍受 7 条上限约束。
  - `FRAMEWORK` J-06 写「服务端只存文件」；本 PRD 不设计账号、权限与分享链接，匿名设备标识仅用于列表区分。
- 未决问题：
  - 异地备份的对象存储容量、单文件大小上限、保留时长与删除策略未定，需随 V1 后端能力确认。
  - 匿名设备标识的生成与重置方式未定；当前只要求可区分设备、不含个人信息。
  - 清空本机数据时是否同时删除远端备份包：当前只清本机元数据，远端需用户单独删除。
