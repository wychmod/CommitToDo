# V1-07 批量导入与回填过去（V1）

## 1. 背景与目标

两类「一次录入很多」的场景在 MVP 里都得逐条来：一是把手头的一份清单搬进来；二是让刚上手的人补几件过去发生的事，否则历程是空的，产品最有价值的部分（回看）无从发生。

本 PRD 交付 B-02 批量导入待办与 A-04 回填过去，不新增页面：批量导入复用 O01 快速添加，回填复用 S04 新建里程碑与月份精度。

目标：用户能把一段多行文本一次变成多条待办，并逐条删掉不要的；能在引导里补 3–5 个过去节点，补完后历程立即有内容，且不伪造提交与统计。

## 2. 范围与非目标

**范围**

- B-02 批量导入：粘贴多行文本，每行一条待办；必选目标分支（含根分支）；预览可逐条删除；一次写入。
- A-04 回填过去：引导填写 3–5 个过去节点，只创建里程碑，日期只填年月；可跳过；不生成提交。
- O01 的批量模式、S04 新建的月份精度、P04 历程空态入口。
- 补白徽章（V1-05）由回填的第一个过去里程碑触发。

**非目标**

- 不做 CSV / Excel 列映射，不做文件上传，不做从其他待办应用迁移。
- 不做日期、分支的自动识别；批量导入只生成标题。
- 不做批量编辑、批量完成、批量删除已导入的待办。
- 不做「补记提交」：E-04 已按 0.12 不实现，回填只写里程碑。
- 不改表结构；不新增页面。

## 3. 用户故事与主流程

**故事 1｜把一份清单一次搬进来**

今天页「记一笔」→ 切到「批量」→ 粘贴 12 行文本 → 选择目标分支「工作 / 主业」→ 预览出现 12 条，逐条删掉 2 条 → 点「导入 10 条」→ 面板关闭，全部待办出现在「无截止日期」组，分支进度与额度同步更新。

**故事 2｜只导入到根分支**

批量面板不选分支时默认根分支「我」；预览顶部写明「将导入到：我」；导入后待办在根分支下可查。

**故事 3｜补几件过去的事**

完成首次引导后，历程空态出现「补几件过去的事」→ 面板给出示例「毕业 / 入职 / 搬家 / 开始健身」→ 用户填写「入职 · 2023 年 6 月 · 工作」等 3 条 → 保存 → 历程中这三条以里程碑出现在对应年月；第一枚「补白」徽章发放。

**故事 4｜跳过回填**

在回填面板点「以后再说」→ 不创建任何里程碑、不发放徽章；面板不再自动出现，但历程空态仍保留入口。

**异常与边界**

- 粘贴内容只有空行或空白字符：导入按钮不可用，不创建任何待办。
- 单行超过 200 字符：按原样保留标题，列表预览省略显示，保存后详情可看全。
- 总行数超过 200：拒绝导入并提示分批，不截断、不静默丢弃。
- 目标分支已合并、已归档或已放下：不可选；根分支与默认树中进行中分支可选。
- 预览中删掉全部条目：导入按钮不可用。
- 导入写入失败：不创建任何一条，面板保留文本、目标分支与预览，提示可重试；不出现「导入了一半」。
- 导入成功后重复点击：按钮立即禁用，不产生第二批。
- 回填面板只填 0 条就保存：保存不可用；至少 1 条才能保存。
- 回填超过 5 条：第 6 条不可添加，提示「最多 5 条」。
- 回填选择的月份晚于当前月：不可选；允许选择任意过去年月。
- 回填所属分支已合并、已归档或已放下：不可选，与 S04 新建里程碑的接收规则一致。
- 回填保存失败：不创建任何里程碑，保留已填内容并提示重试。
- 回填与里程碑新建重复：不做合并或覆盖；用户手动新建的里程碑正常保存。

## 4. 界面与交互

对应视图：**O01 快速添加**（批量模式）、**S04 新建里程碑**（回填引导）；入口在 P01 今天页与 P04 历程空态。

### 4.1 批量导入（O01 批量模式）

- O01 顶部提供「单条 / 批量」切换；切到批量时，单行输入替换为多行文本域。
- 文本域下方固定一行：目标分支选择器，默认根分支「我」；选择器只列可接收待办的分支，并显示路径。
- 粘贴后即时按行拆分：去首尾空白，跳过空行；预览列表逐行显示，行尾提供删除。
- 预览顶部显示「将导入 N 条到『路径』」；N 随删除实时变化。
- 主按钮文案为「导入 N 条」；导入中按钮禁用并显示进度；成功后关闭面板并回到今天页，「无截止日期」组数量更新。
- 不解析行内日期与分支；每行原文即标题。
- 面板不提供「清空全部」以外的批量操作；关闭未导入的面板不保存草稿（与 M03 的单条输入一致）。

### 4.2 回填过去（S04 回填引导）

- 入口：
  - 真实数据中没有任何里程碑且没有任何提交时，P04 历程空态显示「补几件过去的事」。
  - M12 首次引导完成第一条待办后，在当天今天页底部出现一次可关闭的引导卡；关闭或完成后不再自动出现。
- 面板结构：
  - 开头一句「补几件已经发生的事，历程会从那时开始」。
  - 示例 chips：毕业 / 入职 / 搬家 / 开始健身；点击填入下一条的标题。
  - 最多 5 行；每行三个字段：标题（必填）、年月（必填，只到月）、所属分支（默认根分支）。
  - 「再加一条」在不足 5 条时可用；每行可删除。
- 主按钮「保存 N 条」；次按钮「以后再说」。
- 保存后：每条创建为一个 `datePrecision=month` 的里程碑，`achievedAt` 归一化到该月由技术线按 0.12 的未决口径处理；不生成提交、不写待办。
- 保存成功回到历程并定位到最早的一条；不自动切换时间范围。

### 4.3 五种状态

| 状态 | 表现 |
| --- | --- |
| 空 | 批量：文本为空，预览为空，导入按钮不可用；回填：没有可填行时给示例与「再加一条」 |
| 加载 | 批量拆分与预览即时完成，不显示整屏 spinner；导入写入显示进度；回填保存显示进度 |
| 错误 | 目标分支不可接收：选择器内说明原因；写入失败：保留文本、预览与已填内容并提示重试 |
| 只读 | 目标分支或回填所属分支为已合并、已归档、已放下时不可选；不提供只读模式下的导入 |
| 无权限或未登录 | 不适用；V1 无账号，批量导入与回填不要求登录 |

### 4.4 移动端

- 390 px：批量面板为全屏，文本域占主要高度，目标分支与导入按钮固定底部；键盘弹起时按钮可见。
- 预览逐条单行，删除按钮不小于 44 px；超过 10 条时列表内部滚动。
- 回填面板为全屏步骤页，字段纵向排列；年月使用系统月份选择器，分支选择为可搜索列表。

## 5. 数据与规则

| 表 | 字段 | 用途 |
| --- | --- | --- |
| `tasks` | `_id`、`branchId`、`title`、`status`、`dueDate`、`plannedDate`、`order`、`createdAt` | 批量导入生成待办 |
| `branches` | `_id`、`path`、`status`、`archivedAt`、`taskTotal`、`taskDone` | 目标分支校验与四计数 |
| `milestones` | `_id`、`branchId`、`title`、`note`、`achievedAt`、`datePrecision` | 回填生成里程碑 |
| `events` | `entityType='task'` / `'milestone'`、`action='create'`、`payload`、`at` | 导入与回填留痕 |

规则：

- 批量导入：每行生成一条 `status=open` 的待办，`dueDate=null`、`plannedDate=null`；`branchId` 为目标分支；标题为行原文去首尾空白。
- 目标分支：根分支或 `status=active` 且未归档的分支；批量导入不校验层级额度（待办不受分支额度限制）。
- 四计数：导入成功后按 R7 更新目标分支的 `taskTotal`；`taskDone` 不变。
- 事务：一次导入的所有待办在同一事务内创建，任一条失败全部回滚。
- 行数上限暂定 200；超限拒绝，不做部分导入。
- 回填：每条生成一条里程碑，`datePrecision=month`，`achievedAt` 落在所选年月；`note` 为空；`branchId` 为所选分支，默认根分支。
- 回填不生成提交、不改变 `taskTotal` / `taskDone` / `commitCount` / `ownLastCommitAt`；不计入周、月、年回顾的提交数。
- 回填的第一个「过去里程碑」满足 V1-05 的「补白」条件；徽章按 R18 幂等发放。
- 回填与批量导入都不进入示例命名空间，不影响示例树。
- 导入与回填都写 `events`，`payload` 记录来源（批量 / 回填）与目标分支，便于历史追溯。

## 6. 验收标准

1. 在 O01 切到批量，粘贴 5 行文本并选择「工作 / 主业」，预览显示 5 条；点「导入 5 条」后今天页「无截止日期」组新增 5 条，归属为目标分支。
2. 删除预览中的 2 条后，按钮文案变为「导入 3 条」；导入结果恰好 3 条。
3. 粘贴内容只含空行时导入按钮不可用；混合空行时只导入非空行。
4. 超过 200 行时拒绝导入并提示分批，现有待办不变。
5. 目标分支为已合并、已归档或已放下时不可选并写明原因；不选时默认根分支「我」。
6. 模拟导入写入失败：不创建任何待办，面板保留文本、目标分支与预览，可重试。
7. 导入成功后连续点击按钮不会产生第二批待办。
8. 导入的待办 `dueDate` 为空，出现在「无截止日期」组；分支 `taskTotal` 增加对应条数，`taskDone` 不变。
9. 真实数据为空时，P04 历程空态出现「补几件过去的事」；M12 引导完成后今天页出现一次回填引导卡，关闭后不再自动出现。
10. 填写 3 条过去节点并保存后，历程出现 3 条月份精度的里程碑，日期与所选年月一致；没有新增提交与待办。
11. 回填第一条过去里程碑后获得「补白」徽章，重复回填不再发放。
12. 回填超过 5 条时第 6 条不可添加；0 条时保存按钮不可用；选择未来月份不可用。
13. 回填所属分支为已合并、已归档或已放下时不可选。
14. 模拟回填保存失败：不创建任何里程碑，已填内容保留，可重试。
15. 390 px 下批量面板为全屏，文本域、目标分支与导入按钮可用；回填面板字段可完整填写与删除。

## 7. 依赖与阶段、未决问题

- 阶段：V1。
- 依赖：M03（O01 与待办写入）、M07（里程碑与月份精度）、M12（首次引导）、V1-05（补白徽章）。
- 后续消费：V1-05 徽章判定；V1-03 月回顾与 V1-02 年轮不统计回填里程碑为提交。
- 冲突与处理：
  - `FRAMEWORK` B-02 写「预览可逐条删除」，未写标题可编辑：本 PRD 只提供删除，标题需回到原文本修改后重新拆分。
  - `FRAMEWORK` A-04 写「填 3–5 个过去节点」，未写节点落在哪张表；0.12 无补记字段，本 PRD 按里程碑承接，不生成提交，也不写「补记」标记。
  - `E-04` 补记已按 0.12 不实现；本 PRD 不提供补记入口，回填不标「补记」。
- 未决问题：
  - 批量导入的行数上限 200 为暂定值，需按目标分支与设备性能复核。
  - 回填节点是否必须挂在具体分支（当前默认根分支、允许改选），以及是否需要在里程碑标题上统一加「过去」标记，尚未定。
  - 月份精度里程碑的 `achievedAt` 归一化（当月 1 日或月首本地零点）仍按 0.12 的未决口径，由技术线定。
