# CommitToDo 首页终选评审

> **历史评审 · 29 个方向的当轮推荐**。以下保留评审结论与旧原型复测。当前首页与分组树采用后续确认的画稿，见[设计交接入口](../../../../../docs/DESIGN.md)。

**首选 01 Codex · 蓝紫光场。** 用一条可以亲手完成的待办介绍产品，让官网和工作台共享同一套待办、分支与提交节点。**21 Framer · 画布折面**是更强调时间树的品牌方向。**14 Microsoft · 分层功能展位**是更强调工作台清晰度的方向。

## 评审依据

本轮逐套查看最新动效版的 29 套首页、58 张明暗长图和对应的 58 个 HTML 演示。看完整首页如何从第一屏引导到产品镜头和末尾行动，再检查各套的重要控件、滚动变化、自动播放和视觉节奏。在 Chromium 中重点复测入围稿的桌面实际操作和 390px 窄屏表现。以下结论来自本地设计与原型，尚未做真实用户测试或商业转化测试。

优先看访客能否理解「做完一件待办，会在所属分支留下一条提交，之后能在历程找到」。然后看同一套设计能否连续用于「今天、分支、历程、我的」，包括空白分支、新增待办、同日纠错、长期多分支回看和数据恢复。视觉冲击取决于它是否让这条链路更醒目。官网可以有大面积光场和有层次的产品镜头，工作台需要把位置、颜色和操作反馈稳定下来。

以现行框架和产品定位确定功能及用词，以页面架构稿参考路由及编排。正式稿用人能认出的任务名、分支名和日期表达提交。文件导出和从文件恢复在首发范围内，「我的」应提供可达入口。无需账号即可开始，连续多设备同步属于 V2。[功能框架](../../../../../docs/FRAMEWORK.md) · [产品定位](../../../../../docs/PRODUCT-STRATEGY.md) · [页面架构稿](../../page-architecture-plan.md)

## 01 Codex · 蓝紫光场

[浅色长图](01-codex-light.png) · [深色长图](01-codex-dark.png) · [浅色动效](preview/01-codex-light.html) · [深色动效](preview/01-codex-dark.html)

**为什么首选。** 浅色的蓝紫雾面和深色的靛蓝底都把视线落到工作台。完成动作、带分支名的回执和随后出现的历程节点有连贯的视觉语言。演示区的待办可实际勾选和取消，回执随之出现和隐藏。它是原型中的演示状态。访客从官网到工作台，仍能凭同一个勾选框、分支标记和提交节点理解下一步。

**落地要改什么。** 首屏产品名下直接说明「做完一件待办，留下一条提交」。把可操作演示提前，示例初始为未完成，勾选后给出带原任务名的回执，点「在历程查看」定位同一个节点。主按钮「开始使用」进入今天页，首个真实任务进入用户自己的根分支。示例区和真实历程各自独立。原型的演示待办默认已勾选，两段滚动时间线在复测中停住。390px 下品牌标题被切、顶栏标签纵向换行、工作台只露出部分内容。窄屏应改为短导航、可换行标题和单列的「待办 → 回执 → 历程节点」。

**产品内部怎么延续。** 今天页用高对比中性色和紧凑待办行。分支页、历程页和提交回执共享分支颜色、状态文字及节点造型。蓝紫作为品牌与主操作强调色，分支身份由独立且跨页一致的颜色表达。光场服务首页的首屏与章节过渡。应用内采用短反馈，确保每天连续勾选时，内容和按钮保持在预期位置。

## 21 Framer · 画布折面

[浅色长图](21-framer-light.png) · [深色长图](21-framer-dark.png) · [浅色动效](preview/21-framer-light.html) · [深色动效](preview/21-framer-dark.html)

**为什么入围。** 首屏透视画布上有实际日期、分支行和节点。其他方向大量展示能完成的待办，它第一屏就能给访客看到多年累积之后的产品价值。「按分支／按日期」在原型里可以操作，切到按日期后，页面确实换成带具体日期的视图。适合让时间树成为最容易记住的产品画面。

**为什么排第二。** 首屏重心在回看，首次使用需要更早交代节点怎么产生。两套主题首屏都偏暗，透视和光效在窄屏下吃掉有效区域，390px 的「打开工作台」有裁切。官网可以保留折面作为开场画面，紧接一条「勾选 → 时间树新增节点」的具体示例。浅色首屏需要明确的浅色表现和可读的分支线。

**产品内部怎么延续。** 历程页用正视时间轴、固定日期刻度、按一级分支分泳道，子分支显式分出及合并。在移动端保留日期与分支归属。工作台采用平面的导航和卡片，实现扫读、筛选、选节点、定位及键盘操作。

## 14 Microsoft · 分层功能展位

[浅色长图](14-microsoft-light.png) · [深色长图](14-microsoft-dark.png) · [浅色动效](preview/14-microsoft-light.html) · [深色动效](preview/14-microsoft-dark.html)

**为什么入围。** 「今天／分支／历程」有真实的标签切换，点击后展示不同产品画面。「我的」在后续展位承接个人空间和本机数据。明暗两版都有清晰的文本、容器和操作层级，好迁移到工作台、设置和备份流程。适合优先追求正式软件的清楚和可信。

**为什么排第三。** 首屏的设备模型和大字比时间树抢眼，「完成即提交」主要作为展示卡片，难以建立独有印象。演示可围绕同一条任务跨标签联动，让用户在历程里看到这条任务刚生成的节点。390px 下标题被拆成许多短行，标签与产品区域拥挤，调成宽度可容纳的标签和竖排产品画面。现有滚动时间线在复测中停住，手动标签仍然能切换。

**产品内部怎么延续。** 用稳定的四入口导航和一致的资料容器，使待办详情、分支属性、提交回执和恢复确认容易辨认。把时间树作为品牌特征，让官网第一屏就展示看得见的分支和时间刻度。

## 首选进入正式设计的验收点

- **第一次操作。** 官网演示有待办完成前后和同名历程节点。真实工作台从空状态开始，首次添加、完成及定位历程连贯。当天撤销应同时反映在待办和历程。
- **用一年后的样子。** 今天能快速扫任务，分支页知道父子关系和状态，历程能跨日期定位节点，「我的」能找到文件导出和恢复。确认同一分支在四页颜色与文字标识一致，浅色和深色都看得清。
- **动效。** 首屏主信息可立即读。光场和章节动效做成一次短过渡。应用内以约 120–320ms 的即时反馈为起点，完成和切换在关闭动效时仍有明确状态。自动长动效若与其他内容并行，超过五秒应依据 WCAG 2.2.2 提供暂停、停止或隐藏机制。对减少动效偏好提供等价静态呈现，键盘可以触发演示、看到焦点并读取反馈。[W3C 暂停、停止、隐藏](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html) · [W3C 交互动效](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)
- **不同尺寸。** 先验证 390px 的完整首屏、主要入口和演示，再回测桌面。逐段核对滚动状态、减少动效和手动切换，避免把长图中的最终帧当成原型已可触发的效果。

## 29 套逐页记录

下表记录每套影响取舍的主要效果。部分 CSS 滚动时间线在这次 Chromium 测试中停在固定进度。表中明确区分了实际可操作的演示和自动播放的示意。

| 方向 | 动效观察与取舍 |
| --- | --- |
| **01 Codex · 蓝紫光场** | 光场衬托产品窗口，勾选会显隐回执。分支动画的滚动触发停住。**首选**，操作、品牌和工作台衔接最自然。 |
| 02 Linear · 活动轨道 | 活动卡自动推进，滚动段停住。活动流很适合历程局部，整页的密集卡板容易让人联想到团队看板。 |
| 03 Vercel · 分光棱镜 | 棱镜折射和分层界面入场有视觉力，首屏要读到下一段才能理解待办如何生成提交。 |
| 04 Cursor · 桌面接力 | 桌面、终端、提交回执自动接力，动作清楚。终端占核心位置，容易让访客预期一个代码工具。 |
| 05 Resend · 提交铸件 | 扫光勾勒立体铸件，造型容易记住，真实待办和分支出现偏晚。 |
| 06 Stripe Press · 可翻阅的私人编年 | 封面漂浮、书页展开，分支标签能点。漂浮区域的点击位置随画面变动，书籍语义也会把使用预期引向阅读。 |
| 07 TRAE · 绿色信号 | 绿色脉冲沿分支传递。单色冲击有技术感，多分支的区分和日常工作台的明暗层级需要重做。 |
| 08 语雀 · 会长成分支的手账 | 纸层缓慢错动，观看柔和。首屏像写手账，分支与提交的反馈层级弱。 |
| 09 少数派 · 流动的每日进度报 | 报刊卡片换位，主题可点选。像进度专栏，持续操作工作台时的信息密度和定位成本偏高。 |
| 10 Manus · 一句话到一条记录 | 可输入文字或选择示例，页面随之更新预览。首屏像 AI 指令框，提交如何进入分支仍需要看后续。 |
| 11 Apple · 双面玻璃展台 | 玻璃翻面、光照变化和时间线脉冲很醒目。镜头主要在展示设备，窄屏的体验损失大。 |
| 12 Stripe · 流动色带 | 色带持续流动，数据卡浮在前景。像数据平台，任务与所属分支缺乏清楚的因果。 |
| 13 Figma · 分支画布的选区 | 光标沿画布巡游并依次选区。多色和工具栏强化编辑器印象，现有画面里的选区主要是播放示意。 |
| **14 Microsoft · 分层功能展位** | 标签可实际切换，滚动段停住。**第三**，产品导航与可信的数据操作最容易延续。 |
| 15 Xiaomi · 跑道摄影长镜头 | 跑道全景横移，分区标签可切换。作为健康分支案例成立，作为品牌会让人首先联想到运动。 |
| 16 Huawei · 钛面反射展场 | 钛面扫光强调分叉符号，塑形强。符号和材质先于用户能完成的事，产品出现晚。 |
| 17 阿里云 · 玻璃数据场 | 玻璃层组装后浮动，配合展开面板。容易让访客预期云平台或托管服务，与本地优先定位相距较远。 |
| 18 飞书 · 可切换发布台 | 四个视图真能切换，有键盘焦点。历程以列表为主，企业协作画面的比重也偏大。 |
| 19 Claude · 温纸与微光 | 手写内容和翻页用暖纸材质串起来。亲切耐看，首页首先传递的是书写和整理感。 |
| 20 Notion · 贴纸工作间 | 卡片和情景标题轮换，实际可暂停。标题推进时产品窗口仍停在今天，广义工作空间的印象压过时间树。 |
| **21 Framer · 画布折面** | 透视画布先展示具体分支和日期，视图可切。**第二**，时间树在首屏有最高的辨识度。 |
| 22 Runway · 两段路的慢切 | 水面与山景慢切，画面叙事完整。大片占据首屏时，很难快速辨认任务和分支操作。 |
| 23 Pentagram · 一个不断展开的个人档案 | 作品索引和形状逐段出现，适合作为年度回顾的编辑方向。持续操作的工作台需要重建主要布局。 |
| 24 Teenage Engineering · 桌上任务仪 | 橙色实体感按钮可点，LCD 会更新提交反馈。操作即时，但首页更像发布任务硬件。 |
| 25 Aesop · 暖光手稿 | 暖光与纸面缓慢变动，有材质辨识度。长期使用更容易被理解为日记或书写。 |
| 26 Porsche · 远路慢推 | 镜头缓推，暂停控件可用。适合单次发布叙事，日常待办和提交的层级偏低。 |
| 27 Studio Dumbar · 一次完成的动谱 | 大字依序打出今天、完成、历程，发布时非常醒目。持续使用会与任务名、日期、输入框争夺视线。 |
| 28 IKEA · 两束光，一张桌 | 明暗场景可手动切换。空间和生活方式先被记住，产品操作出现过晚。 |
| 29 LEGO · 分支装配间 | 工作、健康、生活切换会更新例子，便于理解分支概念。玩具式视觉容易让访客预期游戏化玩法。 |
