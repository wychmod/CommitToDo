# 首页长度决策：长页，但首屏自足

> **历史草案 · 首页长度试验**。4200 px 的长页和分屏方案属于本轮探索。当前首页章序与实际画稿见[设计交接入口](../../../docs/DESIGN.md)，播放、滚动和窄屏规格见[首页动效定稿](../../../docs/HOMEPAGE-MOTION.md)。

## 一、结论

**做长页，共 4 屏，总高 4200px（1512 宽下约 4.4 个视口）。但第一屏必须能独立成立——不滚动也读得懂、也好看。**

现状 1607px 是"两头不靠"：它把首屏、484px 高的五栏工作台、四宫格卖点、CTA 条、页脚压进了 1.7 屏，于是每一段都被压扁——首屏没呼吸，工作台没可读性，卖点区没存在感。这不是长度问题，是**每段都没被允许成为一个完整的想法**。

### 依据

1. **首页要交付的三件事，只有第一件能靠一屏完成。** 两秒内看懂"分支—提交"、相信它真实存在、然后点进去。"看懂"可以一屏，"相信"需要展示机制，"点进去"需要一次安静的收束。把后两件塞进首屏，只能靠缩小产品界面——正是现在失败的地方。
2. **这个产品的心智模型不常见。** 主流 AI 编码工具（Trae / Cursor / Qoder / Codex / WorkBuddy）的产品名本身就说明了用途；CommitToDo 需要解释"分支"和"提交"是从 git 借来的隐喻，一屏讲不完，硬讲就变成四宫格卖点（已证明难看）。
3. **当前 AI 工具官网的通行做法是有节奏的长页**，但共同点是：**首屏永远自足**，向下是"证明"而不是"补充说明"。长页不等于无限长——4 屏是这类产品的合理上限，超过就开始靠卡片堆叠续命。
4. **1607px 必须被淘汰**：它既没有一屏的干净，也没有长页的节奏，正好落在最差的位置。

## 二、页面骨架（1512 宽）

| # | 区间 | 高度 | 唯一信息点 | 内容 |
| --- | --- | --- | --- | --- |
| 1 | 0–950 | 100vh | **目标会分叉，进展会提交** | 148px 标题 / 一条发丝分支雕塑 / 产品窗从右下入画并被裁切 / 一个文字链 CTA |
| 2 | 950–2050 | 1100 | **分叉是结构，不是标签** | 线从左侧入画、90° 下折成一条脊线，三个 40px 行（根 / 子 / 已合并）挂在脊线上，编号 01/02/03 |
| 3 | 2050–3150 | 1100 | **每次完成都留下不可变的一条** | 线右移后下折成时间线脊线，四个 7px 方节点，右侧 11px 等宽 hash + 12px 时间 |
| 4 | 3150–4200 | 1050 | **数据在你手里** | 大号收束句 + 唯一实心 CTA + 页脚（1px 横线） |

每屏只有一个信息点，其余全部是该信息点的证据。**段落之间不加卡片、不加分割块**，只用三种手段分节：96px 空白、10px 等宽编号、以及那根线本身的转向。

### 那根 1px 线如何跨屏

坐标以 1512×4200 画布为准（x, y）：

1. **屏 1**：`(0, 818)` 入画 → 主干到 `(498, 703)` → 在此劈成上下两弧，最大间距 26% 画高 → 收束于 `(1074, 361)` 的节点。
2. **出屏**：节点继续向右，`(1074, 361) → (1512, 361)`，从右边缘离开。**不是垂直往下穿过画面**——那会把产品窗切坏。
3. **屏 2**：从**左边缘** `(0, 1080)` 重新入画 → 水平到 `(498, 1080)` → **90° 下折**成脊线 → `(498, 1780)`。三个分叉点 `y = 1180 / 1380 / 1580`，每点向右伸 160px 的 1px 短枝，枝端是 15px 标签。**最后一次转向向右出画**：`(498, 1780) → (1512, 1780)`。
4. **屏 3**：左边缘 `(0, 2160)` 入画 → 到 `(726, 2160)` → 下折成时间线脊线 → 四个节点 `y = 2260 / 2420 / 2580 / 2740` → 继续到 `(726, 3000)` → 向右出画。
5. **屏 4**：左边缘 `(0, 3400)` 入画 → 水平到 `(756, 3400)` → **终止于主 CTA 的左边缘**，线头是一个 20px 实心节点。线到此为止，不再出画。

这套路径读起来是一条电路：**右出左进、三处 90° 转向、一次分叉、一次收束、一次终止于动作**。它替代了所有 section 分割线和卡片。

## 三、滚动与动效

线不是淡入，是**被画出来的**。

- 整条路径是一条 SVG path（跨 4200px，分 5 段），`stroke-dashoffset` 与滚动进度绑定，只画到"视口下沿往上 120px"的位置——线永远追在手后面一点，像钢笔在纸上走。
- **三个关键节点**：① 首屏节点（进度 0.12）点亮；② 屏 2 的第二条分叉（0.38）出现 160px 短枝；③ 屏 4 的终止节点（0.92）由描边变成实心。其余位置不动。
- 编号 01/02/03 不是上移淡入，而是**被线"印"出来**：一条 1px 下划线从左向右展开 240ms，文字在最后 120ms 才到 1 透明度。
- 线经过产品窗时**不做视差**，窗是固定面板，只有线在动——避免整页漂移的廉价感。
- 顶栏在首屏内透明，滚过 950px 后变实底 + 出现 1px 底边（无毛玻璃、无高度变化）。
- `prefers-reduced-motion` 下：**首帧即完整路径**（无 dash 动画），三个节点静态点亮，编号与下划线直接可见，顶栏直接为实底；页面结构与信息完全一致，只是没有"画"的过程。

## 四、出图策略

- **保留**现有的 16:10 首屏稿（`prompt-dark-v3-system.txt`）——它负责首屏细节与产品窗可读性。
- **新增**一张 1512×4200 竖长稿，只负责四屏的节奏、留白与那根线的旅程。文件名：`prompt-dark-longpage-v1.txt`。
- 长图稿的取舍（已写进提示词）：
  1. **文字只允许 6 处营销文案**（eyebrow、两行标题、副文案、01/02/03 三个标题、CTA）。产品窗内只放 10–12 个短标签，禁止长句、禁止段落。
  2. **字号不随画布放大**：标题保持 148px，不要因为画布变高而拉到 300px。
  3. **每屏的 y 区间写死在提示词里**，并要求四段之间没有可见分割线——分节只靠 96px 空白与编号。
  4. 若工具把竖长稿压扁或糊字：改用 **三段 16:10 分段稿**（屏 2、屏 3、屏 4 各一张），长图只作为节奏参考。两者不冲突。
- 白底版的长图不需要重写，只需替换提示词末尾的 PALETTE / SURFACE 两段（`prompt-light-longpage-swap.txt`）。
